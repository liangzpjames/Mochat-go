# SaaS 总后台 MVP 上线范围

## 产品阶段

当前处于未获得正式客户的获客前阶段。总后台的目标不是覆盖成熟 SaaS 公司的全部运营流程，而是让创始团队能够完成首个客户从开户、分配套餐、启用服务到运行检查的完整闭环。

## 首版必须进入总后台

| 工作区 | 必须能力 | 上线理由 |
| --- | --- | --- |
| 概览 | 业务租户数、有效套餐数、平台账号数、系统健康、最近操作、上线证据进度 | 判断平台当前是否可服务客户 |
| 客户租户 | 创建租户、查看详情、分配套餐、启用/停用、查看用量 | 完成首个客户交付的核心闭环 |
| 套餐 | 创建和编辑套餐、启停套餐、查看额度 | 定义客户可购买和可使用的能力边界 |
| 平台账号 | 查看平台成员、角色和权限；团队模式下处理待审批事项 | 控制谁可以操作总后台 |
| 系统运维 | 系统健康检查、备份状态、最近平台操作 | 上线前发现故障并保留审计证据 |
| 上线检查 | 六类生产证据、负责人、截止时间、发布候选门禁 | 明确“本地可运行”和“可生产发布”的差异 |

首版界面只调用现有 Go API，不使用模拟业务数据。没有客户时显示真实空状态。

## 暂不进入主导航

以下能力后端继续保留，不删除数据表或 API，但在获得客户和形成真实需求前不占用总后台主导航：

- 在线支付、退款、发票、结算、催缴和复杂对账。
- 客户成功队列、续费预测、运营任务中心和复杂通知 SLO。
- 白标品牌、自定义域名和自动 TLS 交付。
- 服务账号、API Key、开放平台调用量趋势和限流策略。
- 合规导出、数据擦除、法律保留、审计锚点和对象锁治理。
- 套餐批量同步、批量开户、批量续费和大规模任务编排。
- 多级审批委托、审批策略治理和复杂组织权限模型。

## 触发后再开发

| 触发条件 | 下一阶段能力 |
| --- | --- |
| 出现首个付费客户且需要线上收款 | 支付、退款、发票和订阅对账 |
| 业务租户达到 5 个以上 | 客户成功、续费提醒、批量运营和通知策略 |
| 出现渠道商或品牌定制订单 | 白标品牌、自定义域名和域名交付 |
| 出现客户系统集成需求 | 服务账号、API Key、调用量和限流 |
| 出现明确合规合同或监管要求 | 数据导出/擦除、法律保留和不可变审计 |
| 平台管理员达到 2 人以上 | 开启双人审批和审批 SLA 提醒 |

## 单人运营与团队模式

- 独立部署样例默认 `MOCHAT_GO_SAAS_ADMIN_APPROVAL_REQUIRED=0`，适合只有一名平台管理员的获客前阶段。
- 添加第二名平台管理员并完成权限分工后，将该值改为 `1`，高风险动作重新进入双人审批。
- Go 应用自身的配置默认仍保持审批开启；只有独立部署样例明确选择单人运营模式，避免把获客前便利误当成通用安全默认值。

## 生产发布边界

本地构建、单元测试和浏览器验收通过不等于生产就绪。正式发布仍必须在“上线检查”补齐 MySQL 5.7 amd64、真实企业微信、真实微信开放平台、至少两个真实业务租户、生产域名前端浏览器和目标环境短周期健康/外部监控六类证据。按当前要求不执行 24 小时本地运行。
