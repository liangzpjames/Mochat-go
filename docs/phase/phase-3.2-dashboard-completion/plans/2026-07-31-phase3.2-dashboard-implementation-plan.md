# Phase 3.2 Dashboard Implementation Plan

> 本计划已由 `2026-08-01-phase3.2-eight-page-parity-plan.md` 取代，仅保留为历史实施记录。后续工作与验收以新计划为准。

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver eight real Dashboard pages—overview, global conversations, sensitive words, leads, contacts, opportunities, public pool, and tags—with real persistence, tenant/corp/data-scope enforcement, and repeatable browser acceptance.

**Architecture:** Keep the Phase 3.1 shell, manifest, session isolation, and page registry. Reuse existing Dashboard handlers behind typed frontend adapters where their contracts are sufficient; extend the modular SCRM domain for customer lifecycle APIs under `/dashboard/scrm`, using MySQL migration `0100` and domain/application/ports/adapters/transport boundaries.

**Tech Stack:** Go 1.26, MySQL/MariaDB, React 19, TypeScript, Ant Design, TanStack Query, Vitest, Playwright, pnpm, Docker Compose.

## Global Constraints

- Follow `docs/phase/phase-3-dashboard/PHASE3_CONSTRAINTS.zh-CN.md`.
- Follow `docs/phase/phase-3.2-dashboard-completion/design/2026-07-31-phase3-dashboard-completion-design.md`.
- The runtime manifest contains exactly 53 pages; Phase 3.2 completes exactly the eight routes listed in this plan.
- Completed routes must not render `DemoPage`, `PlaceholderPage`, or production fixtures.
- Every business record is tenant-scoped; corp-owned records are also corp-scoped.
- The server derives tenant, corp, and data scope from authentication; client-supplied scope is never trusted.
- Mutable resources use optimistic versions; retryable writes use stable idempotency keys.
- `403` means forbidden, `404` means absent or hidden, `409` means version conflict, and `422` means invalid state transition.
- Migration `0099` is already occupied; this plan uses `0100_scrm_customer_lifecycle`.
- Automated tests must not send real customer messages or invoke destructive third-party operations.
- Each task ends with an independently testable commit.
