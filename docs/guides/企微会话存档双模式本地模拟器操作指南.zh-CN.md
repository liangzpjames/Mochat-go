# 企微会话存档双模式本地模拟器操作指南

## 适用边界

本工具只用于本地开发。自建应用模式会执行 RSA 解包、逐消息 AES-256-GCM 解密和媒体分片；第三方代开发模式会执行授权夹具、逐消息密钥解包和展示组件回读。它证明本地协议合同与 MoChat 生产代码路径可用，不代表真实企业微信线上环境已经通过。

模拟器只向 bridge 的上游夹具写入数据，不直接写最终消息表或媒体表。最终业务数据由 app 内的 durable worker 拉取、解析并提交。

## 启动

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/deploy_docker_desktop.ps1 -EnableArchiveFixture
```

部署脚本会在仓库外的本地受保护目录幂等生成 bridge、模拟管理接口、企微凭据和登录所需密钥，不会在命令、日志或仓库文件中打印这些值。Compose 文件本身默认关闭 durable worker 和模拟器；只有该显式部署入口会开启，避免误把开发夹具带入普通环境。

应用入口为 `http://127.0.0.1:18080`。bridge 是同一 Compose 项目中的独立容器，不暴露宿主机端口。

## 初始化一个租户的模拟上游

租户必须已经存在唯一企业绑定，命令中的模式必须和租户开户时选择的权威模式一致。`seed` 会为该数据集幂等创建名称含“本地验收”的员工和客户，并把当前 integration 标记为 `local_contract`；它不会调用真实企微，也不会把本地结果标记成线上验证通过。

自建应用租户不要求先填写 CorpID、AgentID 或 Secret；模拟器只接受空值或 `wwSIM` / `wwMOCHATLOCALSIM` 开头的显式本地 CorpID，遇到生产形态的 CorpID 会失败关闭。第三方代开发租户也不需要预填永久授权码：`seed` 会真实构造 `suite_ticket` 与 `create_auth` 加密回调，经过 app 的签名校验、AES 解密、防重放账本和 bridge 换码边界后，把永久授权凭据加密保存。敏感值不会在命令输出中回显。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 seed --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo
```

第三方代开发租户将 `--mode` 改为 `third_party_delegated`。重复执行相同命令是幂等的，不会重复升级 integration 版本或追加激活审计。

## 发送文本消息

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 send --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo --type text --text "本地模拟消息"
```

## 发送图片、录音、视频或文件

先把去敏文件放到 `deploy/standalone/fixtures`，然后执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 send --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo --type image --file /fixtures/input/sample.png
```

`--type` 可选 `image`、`voice`、`video`、`file`。第三方代开发模式下，媒体正文只进入本地展示组件，不会落到普通媒体对象存储。

## 触发同步与查看

发送后可等待后台周期任务，也可在 Dashboard 的“唯一企业资料 → 数据同步”点击“立即同步会话”。同步成功后，在会话页面查看文本或鉴权媒体；第三方代开发消息使用“安全查看会话内容”打开 60 秒一次性展示会话。

查看模拟器上游状态：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 status --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo
```

## 清理

先执行只读预览：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 cleanup --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo --dry-run
```

确认租户、模式、数据集和数量无误后，再传精确确认值执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_archive_simulator.ps1 cleanup --enable-simulation --tenant-id 2 --mode self_built --dataset MOCHAT-LOCAL-SIM-demo --confirm-dataset MOCHAT-LOCAL-SIM-demo
```

清理范围同时受数据库数据集所有权账本、租户、企业、模式和数据集约束；不会删除其他租户或没有 `MOCHAT-LOCAL-SIM-` 标记的数据。如果同一 source 中混入任何不属于该数据集的消息，清理会失败关闭。

清理会删除正式 worker 生成的消息、媒体账本、展示组件定位器、同步 run/source、对象文件和该数据集的本地验收员工/客户，并清除 bridge 上游夹具；不会删除租户、企业或两种企微对接模式配置。下游清理先于 bridge 清理执行，因此 bridge 请求失败时仍可重放或再次清理。

## 开发与生产的区别

- Compose 安全默认值关闭两套会话同步任务；本地部署脚本显式只启用 durable worker，旧 archive cron 保持关闭，避免同一消息被两套任务并行消费。
- `run_archive_simulator.ps1` 会从部署脚本创建的仓库外密钥目录安全加载 Compose 所需值，命令行无需复制或显示任何密钥。
- bridge 与 app 位于同一个 `mochat-go-desktop` Compose 项目和网络，但保持独立容器，便于后续替换真实 Finance SDK 动态库、单独限流和故障隔离。
- 上线时不更换消息解析、媒体对象、游标或 Dashboard 回读链路；需要将 bridge 的本地夹具上游替换为真实企微自建应用/第三方代开发凭据解析与请求实现，并完成真实企微环境联调。
