# Dashboard 空数据页面展示优化设计

## 背景与问题

文件录音、好友、客户群和客户分析的客户明细在没有业务数据时，空态内容直接从卡片左侧开始，标题、说明和操作入口缺少视觉重心。客户群以及部分报表页面还会把 `Provider`、接口限制等实现概念展示给普通用户，既不能帮助用户完成下一步，也容易被误解为系统故障。

## 目标

1. 普通用户看到的空态只回答三个问题：当前是什么状态、数据如何产生、可以执行什么操作。
2. 不在空态或普通报表提示中展示 `Provider`、接口、数据表等开发术语，也不直接透传后端限制消息。
3. 文件录音、好友、客户群、客户分析客户明细采用一致的居中空态，桌面宽屏不贴左，窄屏仍可读。
4. 不改变数据查询、鉴权、租户隔离和同步逻辑；没有配置或没有数据时继续正常显示空数据。

## 方案选择

### 方案 A：逐页写独立样式

每个页面新增自己的空态类。改动直观，但四份样式容易逐渐不一致，后续页面还会重复出现同类问题。

### 方案 B：复用统一空态类（采用）

在四个页面的自定义空态区域使用 `phase35-empty-state`，统一设置居中布局、合理的最大文本宽度、上下留白和可访问的链接焦点。报表限制统一折叠为业务提示，不展示服务实现名或后端原始消息。

### 方案 C：重构所有页面到新的空态组件

长期一致性最好，但本次范围内会带来不必要的全站迁移与回归风险，不符合最小改动原则。

## 详细设计

### 空态文案

- 文件录音：说明当前没有录音；完成企业微信会话同步后自动展示。
- 好友：说明当前没有好友；完成企业微信联系人同步后展示负责人、标签与来源。
- 客户群：说明当前没有客户群；完成企业授权并同步客户群后展示群主和成员。
- 客户分析客户明细：说明当前筛选范围没有客户；可创建联系人或调整日期范围。
- 报表限制：只显示“部分数据暂未同步完整，当前仅展示已获取的数据”，不展示后端返回的技术细节。
- 概览、AI 洞察和营销工具：状态、限制与失败提示统一使用业务语言；包含开发术语的外部错误改为可操作的安全提示。

### 布局

`phase35-empty-state` 使用网格纵向排列，内容水平居中，最小高度保证空卡片有稳定视觉重心；说明文本限制行宽以提高可读性。小屏保持左右安全边距，不引入固定像素宽度。

正文颜色需在白色背景上达到 WCAG AA 4.5:1；当前共享空态正文对比度约为 5.6:1。

### 安全与边界

- 后端限制字段仍保留在 API 数据中，供日志和受控诊断使用；普通页面不直接渲染。
- 不新增虚假数据、不改变空态判断条件。
- 错误态仍显示“数据加载失败”并提供重试，不将真实错误伪装为空数据。

## 验收标准

1. 四个目标页面无数据时，空态标题、说明和入口在卡片内水平居中。
2. 四页及相关普通用户概览、报表、AI 和营销页面不出现 `Provider`、接口、数据表等开发术语。
3. 客户分析、概览或 AI 页面即使收到包含技术细节的限制消息，也只展示业务化概括。
4. 有数据、加载、失败、筛选和分页行为不回归。
5. Dashboard lint、typecheck、测试、构建通过；Docker 19080 实例重建后逐页点击、刷新和 390×844 响应式验收通过。
