# Phase 3.4 第一批渠道获客页面实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将渠道活码、群活码和活码短链从 demo/placeholder 升级为覆盖圆弧主要功能结构、使用真实后端能力并具备完整页面状态的 React 页面。

**Architecture:** 在 `features/phase34` 内建立独立 API 合同、三个聚焦页面和共享的渠道获客页面组件。渠道活码直接复用 `/dashboard/channelCode/*`；群活码先通过已存在的自动拉群能力形成真实查询与详情闭环；活码短链使用明确 Provider 状态，在正式短链写合同完成前不伪造创建结果。

**Tech Stack:** React 19、TypeScript、TanStack Query、现有 `BusinessWorkbenchApi`、Vitest、Testing Library、Go Dashboard API。

## Global Constraints

- 页面参考圆弧的筛选栏、表格、主操作、详情和统计结构，不要求像素完全一致。
- 生产页面不得引用 `demo-fixtures`，不得使用静态业务数据冒充接口结果。
- 所有查询使用当前 Dashboard 企业与权限上下文，写操作继续由服务端校验权限。
- 覆盖加载、空数据、筛选无结果、无权限、Provider 缺失、服务异常和刷新状态。
- 自动化环境不得触发真实企微写入或不可逆外部操作。
