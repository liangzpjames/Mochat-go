# Phase 3.4 第二批接待转化页面实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将获客链接、微信客服和一键加群三个路由升级为覆盖圆弧主要信息结构、真实能力边界和完整页面状态的 Phase 3.4 React 页面。

**Architecture:** 在 `features/phase34/conversion-pages.tsx` 中建立第二批独立页面模块。获客链接与微信客服采用显式 Provider 阻断模型，不调用虚构接口；一键加群通过 `BusinessWorkbenchApi.read('/workRoomAutoPull/index')` 复用真实自动拉群查询能力，并在页面内完成响应标准化。

**Tech Stack:** React 19、TypeScript、TanStack Query、Vitest、Testing Library、现有 Dashboard Access Context 与 BusinessWorkbenchApi。

## Global Constraints

- 页面覆盖圆弧的授权状态、筛选项、主操作、表格字段和详情层级，不要求像素完全一致。
- 生产页面不得引入 demo fixture，也不得生成虚假授权、客服账号、链接、群聊或统计数据。
- 自动化环境不得触发真实企业微信授权、账号同步或外部写入。
- Provider 缺失必须可见并禁用相关写操作；真实查询必须覆盖加载、空数据、错误重试和详情。
