# Phase 3.3 风险行为 Provider 实施计划

> **For agentic workers:** 按任务逐项执行，每个任务完成后运行对应测试并提交。

**目标：** 基于现有会话存档消息实现风险行为规则配置、风险记录查询和审计闭环，并接入风险行为页面。

**架构：** 新增独立的风险域模型和 MySQL Store。规则由企业隔离，评估器读取已归档消息，按规则生成风险记录；HTTP handler 只负责权限、参数和响应映射。首期不依赖音频和外部 AI，AI 摘要允许为空。

**技术栈：** Go、MySQL migration、现有 dashboard handler/server option、React、TanStack Query、Vitest。

## 全局约束

- 所有风险数据必须绑定 `tenantID` 与 `corpID`。
- 只评估已授权的会话存档消息。
- 不在前端生成风险记录，不伪造 AI 摘要。
- 规则同一行为只能存在一条有效策略。
- 所有写操作保留现有企业权限和审计模式。
