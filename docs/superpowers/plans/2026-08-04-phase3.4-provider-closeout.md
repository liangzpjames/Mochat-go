# Phase 3.4 Provider 全线收口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 marketing-tools 九页具备可审计的真实 Provider、持久化、权限/租户隔离、错误状态和浏览器验收证据，并精确保留外部凭据阻塞。

**Architecture:** 新增 Phase 3.4 获客/转换 Provider 表与 handler，复用已有自动拉群、群发、素材和朋友圈本地 Provider；所有 HTTP handler 从登录上下文解析企业，外部能力通过 fail-closed adapter。React 通过统一 adapter 和 MaterialSelector 读取真实数据，最终以 Go/前端/Docker/浏览器证据更新 Manifest。

**Tech Stack:** Go、MariaDB、React 19、TanStack Query、Vitest、Testing Library、Docker Compose、Playwright/in-app Browser。

- 工作目录必须是 `D:\workspace\mochat-go\mochat-go`；保留并禁止修改 `.workbuddy/`、`docs/superpowers/plans/2026-07-29-phase3-frontend-acceptance.md`、`web/saas-admin/`。

- 客户端不能覆盖 `tenant_id`、`corp_id`、操作者或权限范围；跨企业资源隐藏为 `404`，无权限为 `403`。
- 未配置企业微信外部凭据时只能返回 `503` 或持久化明确失败/等待状态，禁止 fixture、假链接、假成功和自动化真实外发。
