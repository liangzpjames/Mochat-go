# 员工会话圆弧式工作台改造设计方案

## 1. 范围与目标

本轮只改造菜单“会话 → 员工会话”，目标路由为 `/chat/v2-staff`。菜单导航、应用顶部 banner、企业切换和全局搜索保持不变；客户会话、群聊会话、会话轨迹和会话导出不在本轮联动改造。

目标不是给现有三张卡片换皮，而是参照圆弧 AI 员工会话的连续工作台结构，重组为“员工目录 → 会话轨迹 → 消息阅读”三栏，同时保证所有员工、会话、统计、状态和能力提示来自 MoChat 的真实数据。

本轮文档完成后暂停，不实施代码。

## 2. 当前基线与问题

### 2.1 本地页面

当前 `EmployeeConversationPage` 已具备员工搜索、员工选择、会话类型、会话列表、详情和固定每页 20 条会话，但存在以下问题：

1. 页面仍是三张彼此分离的卡片，不是连续会话工作台。
2. 三栏固定为 `250px + 390px + 1fr`，第三栏允许缩到 0。实测在 1066×1272 视口中，内容区宽 818px、工作区宽 747px，详情栏仅 83px，文字被挤成竖排。
3. 工作区只有 `min-height`，没有视口高度约束。选择长会话后工作区高达 3128px，三个面板不能独立滚动。
4. 员工接口固定读取前 100 人且只返回数组，没有总数、分页、部门、状态和重点关注口径。
5. “企业架构”“存档成员”只是文案，实际接口没有组织树和存档成员统计，语义不准确。
6. 详情只返回最近 200 条消息，不能按内容、消息类型或日期检索，也没有完整会话统计。
7. 详情仅把内容转成文字；图片、文件、链接等归档内容缺少类型化展示。

### 2.2 圆弧 AI 参考页

参考页 `/chat/v2-staff` 的有效结构为：

- 左栏：企业架构/重点关注切换、员工搜索、组织与成员、存档成员/离职人员状态。
- 中栏：会话轨迹，按客户、客户群、同事、内部群切换，列表独立分页。
- 右栏：选中会话标题、刷新/关注等动作、消息类型、内容搜索、日期检索、四项会话统计和完整消息流。
- 三栏使用边框连续分隔；右栏随宽屏扩展，消息区内部滚动。

只借鉴信息架构、栅格、密度和交互。圆弧的业务数字、成员、聊天内容、升级服务入口和未被 MoChat 支持的能力不复制。

## 3. 方案比较与决策

### 方案 A：仅调整 CSS

保留现有组件和接口，只修改三栏宽度、颜色和间距。优点是变更小；缺点是员工 100 人截断、假“企业架构”、重点关注、详情筛选和完整统计均无法解决。拒绝。

### 方案 B：前端拼装现有员工/部门管理接口

前端同时调用 `/workEmployee/index`、`/workDepartment/pageIndex`、`/workDepartment/showEmployee` 和会话接口。能快速拼出组织树，但聊天页用户可能没有员工管理菜单权限；多个接口的数据权限、分页和归档口径也难以保持一致。拒绝。

### 方案 C：员工会话专用工作台契约（采用）

在现有会话权限域内增加员工目录聚合和员工详情查询契约。后端复用组织、员工、部门、归档消息、关注记录和访问范围；前端只负责展示与 URL 状态。该方案工作量高于纯前端，但能保证真实数据、统一权限和稳定分页。

## 4. 页面结构

```text
┌──────────────────────────────── 员工会话工作台 ────────────────────────────────┐
│ 员工目录 272px        │ 会话轨迹 380px           │ 消息阅读 minmax(0, 1fr)      │
│ 企业架构 | 重点关注   │ 客户 客户群 同事 内部群  │ 对象 + 员工 + 刷新 + 关注    │
│ [员工搜索] [刷新]     │ 会话卡片                  │ 全部 [消息类型] [内容] [日期] │
│ 部门树                │ 头像/对象/时间             │ 沟通天数 消息数 对方发 员工发 │
│ 员工列表              │ 摘要/风险或超时标识        │ 消息时间轴                    │
│ 存档成员 | 离职人员   │ 固定 20 条分页             │ 加载更早消息                  │
└───────────────────────────────────────────────────────────────────────────────┘
```

整个工作台使用一个外框，三栏之间只保留 1px 分隔线，不再给每栏独立阴影和外间距。页面不增加顶部介绍框。

### 4.1 左栏：员工目录

- 顶部页签为“企业架构”和“重点关注”，数字分别为当前权限范围内员工总数、存在已关注会话的员工数。
- 搜索输入提交后写入 `employeeKeyword`；刷新只重取目录数据，不改变 URL。
- 企业架构模式展示真实部门树和员工列表。点击部门后只展示该部门及其下级部门成员。
- 重点关注模式展示至少有一条当前用户关注会话的员工，并显示关注会话数量。
- 底部“存档成员”表示在有效归档来源中至少出现过一条消息的员工；“离职人员”以 `mc_work_employee.status = 5` 为准。两者是可点击筛选，不再只是说明文字。
- 员工列表每批固定 50 人，使用“加载更多”，总数来自后端，不能静默截断在 100 人。
- 部门未同步但员工存在时，显示紧凑告警“组织架构未同步，仅展示可访问员工”，仍允许继续查看会话。

### 4.2 中栏：会话轨迹

- 选中员工后读取该员工的真实会话列表；每页固定 20 条。
- 类型为“客户、客户群、同事”。“内部群”保持可见但禁用，并以警示点/提示说明“当前归档数据未提供内部群能力”。
- 每张会话卡显示真实对象头像或文字头像、对象名称、最后消息时间、最后消息摘要；只有后端返回时才显示风险、超时、关注标识。
- 整张卡片可点击。切换员工、部门、目录模式或会话类型时清空已选会话并回到第 1 页。
- 当前列表继续复用 `/workMessage/toUsers?view=global`，因为该契约已经提供稳定 `conversationId`、固定分页、消息总数、风险数、超时数和关注状态。

### 4.3 右栏：消息阅读

- 标题显示对象名称、对象类型和当前员工；动作仅保留“刷新”和“关注/取消关注”。刷新只刷新当前详情。
- 不在本页新增“会话下载”。当前导出菜单只导出会话摘要，不能保证下载完整选中会话；伪装成参考页能力会误导用户。
- 筛选区包含“全部”、消息类型多选、内容关键词和单日日期。筛选只影响消息时间轴，不改变中栏会话列表。
- 统计条固定展示“累计沟通天数、累计消息、对方发送、员工发送”。统计来自全量会话聚合，不用当前已加载的 50 条消息在前端推算。
- 消息按时间正序展示，每次固定加载 50 条；初次读取最新 50 条，点击“加载更早消息”使用游标向前读取，避免大偏移分页。
- 图片、链接、文件、视频和语音仅在归档内容真实包含可用字段时展示对应卡片；字段不足时显示“该类型内容暂不支持预览”，不构造地址或文件名。

## 5. 响应式与尺寸

- 视口宽度 ≥ 1600px：工作台宽度占满内容区，列宽 `272px 380px minmax(0, 1fr)`。
- 视口宽度 1200–1599px：左栏改为可开合目录抽屉，中栏固定 360px，右栏至少 520px；不能把右栏压成窄条。
- 视口宽度 769–1199px：默认显示中栏与右栏，员工目录从左侧抽屉打开。
- 视口宽度 ≤ 768px：员工、会话、详情采用分步单栏，返回操作恢复上一级。
- 桌面工作台高度使用 `calc(100dvh - 72px - 56px)`，三栏各自滚动；页面本身不因长消息无限增高。
- 2560×1440 是主验收尺寸，同时回归 1440×900、1066×1272 和 390×844。

## 6. URL 与状态规则

Canonical URL 参数：

```text
/chat/v2-staff?
directoryMode=all&employeeKeyword=&departmentId=&employeePage=1&
employeeId=9&conversationType=customer&page=1&pageSize=20&
conversationId=9:1:31&messageKeyword=&messageTypes=image,file&messageDate=2026-08-16
```

- `directoryMode`：`all | focused | archived | departed`，默认 `all`。
- `employeePage` 只用于“加载更多”的恢复；员工页大小固定 50。
- `conversationType`：空、`customer | room | employee`；内部群不产生查询值。
- `pageSize` 只接受 20，非法值重置为 20。
- `conversationId` 使用稳定的 `employeeId:toUserType:toUserId`，不再用最后一条消息 ID 作为详情主标识。
- 消息游标不写入 URL；刷新页面从最新 50 条重新加载。

## 7. 后端契约

### 7.1 员工目录

新增：

```http
GET /dashboard/workMessage/staffDirectory
  ?mode=all&keyword=&departmentId=&page=1&pageSize=50
```

响应：

```json
{
  "departments": [{ "id": 10, "parentId": 1, "name": "销售部", "employeeCount": 8, "children": [] }],
  "employees": [{
    "id": 9,
    "name": "张伟",
    "avatar": "",
    "status": 1,
    "departmentIds": [10],
    "archived": true,
    "conversationCount": 3,
    "focusedConversationCount": 1,
    "lastConversationAt": "2026-08-16 13:50:08"
  }],
  "counts": { "all": 10, "focused": 1, "archived": 4, "departed": 0 },
  "page": 1,
  "pageSize": 50,
  "total": 10,
  "limitations": [],
  "capabilities": [{ "key": "internalGroup", "available": false, "reason": "当前归档数据未提供内部群能力" }]
}
```

处理器沿用 `/dashboard/workMessage/toUsers#get` 权限键，并同时限制 principal tenant、corp 和允许员工集合。组织树只包含当前访问范围内仍有可见员工的节点。中栏在尚未选择会话时也必须从该响应读取 capability，不能在前端硬编码内部群状态。

### 7.2 员工会话详情

新增：

```http
GET /dashboard/workMessage/staffDetail
  ?conversationId=9:1:31&keyword=&messageTypes=image&date=2026-08-16&pageSize=50&before=
```

响应：

```json
{
  "conversationId": "9:1:31",
  "employeeId": 9,
  "employeeName": "张伟",
  "targetType": "customer",
  "targetId": 31,
  "targetName": "陈晓明",
  "focused": true,
  "stats": { "communicationDays": 2, "messageTotal": 15, "inboundTotal": 5, "outboundTotal": 10 },
  "messages": [],
  "nextBefore": "opaque-cursor",
  "hasMore": true,
  "capabilities": [{ "key": "internalGroup", "available": false, "reason": "当前归档数据未提供内部群能力" }]
}
```

`stats` 始终按完整会话计算；`messages` 应用关键词、类型和日期筛选。游标由后端生成，前端不得解析。会话不存在或不在访问范围时统一返回 404，归档未开通时返回现有 40301。

### 7.3 关注

继续使用：

```http
PUT    /dashboard/workMessage/focus
DELETE /dashboard/workMessage/focus
```

请求体仍为 `{ "conversationId": "9:1:31" }`。成功后同时刷新详情、当前会话卡和员工目录重点关注计数。

## 8. 数据来源矩阵

| 控件/数据 | 系统来源 | 当前状态 | 设计处理 |
|---|---|---|---|
| 部门树 | `mc_work_department`、`mc_work_employee_department` | 数据与查询能力已有，员工会话未接入 | 目录接口聚合并按权限裁剪 |
| 员工及离职状态 | `mc_work_employee`，`status=5` 为退出企业 | 已有 | 目录接口返回分页、状态与计数 |
| 存档成员 | 当前有效归档来源中的 `work_employee_id` | 可推导，暂无接口 | 后端真实聚合，不用企业员工数代替 |
| 员工会话列表 | 归档分表/来源注册表，经 `WorkMessageGlobalPage` | 已有 | 继续复用，固定 20 条 |
| 会话详情 | 归档消息，经 `/workMessage/detail` | 已有但只取最近 200 条 | 新增 staffDetail 筛选、统计与游标 |
| 重点关注 | `mochat_go_work_message_focus` | 已有会话级读写 | 聚合到员工目录并复用写接口 |
| 风险/超时标识 | `mochat_go_risk_records`、`mochat_go_timeout_records` | 表存在时可用 | 只有 capability 可用时展示 |
| 消息类型/日期/关键词 | 归档消息 `type/content/msg_data_time` | 存储层部分支持，详情接口未暴露 | staffDetail 补齐 |
| 内部群 | 无对应 `to_user_type` | 功能与数据均未接入 | 禁用态告警，不返回 0 |
| 完整单会话下载 | 当前导出页只导出最多 100 条会话摘要 | 功能不完整 | 本页不展示下载动作，另立后续任务 |

## 9. 组件边界

- `EmployeeConversationPage`：URL 状态、查询编排和跨栏联动。
- `EmployeeDirectoryPane`：目录模式、部门、员工搜索与加载更多。
- `EmployeeConversationListPane`：会话类型、卡片和固定分页。
- `EmployeeConversationDetailPane`：动作、筛选、统计、消息游标。
- `ConversationMessageContent`：按真实归档类型渲染内容，可供其他会话页复用。
- `conversation-global-api.ts`：强校验目录与详情契约，不接受缺字段的“半成功”数据。

组件不直接调用数据库口径，也不自行推算全量统计。

## 10. 错误与缺口状态

- 归档未开通：整页显示共享的“会话归档未开通”状态和配置入口。
- 组织未同步：左栏紧凑告警，允许使用归档中可识别的员工继续查询。
- 员工无会话：中栏显示“该员工当前没有归档会话”，不是加载失败。
- 详情筛选无结果：保留标题和完整统计，仅消息区显示空态。
- 风险/超时表缺失：不显示对应数量徽标，并通过 capability 提示不可用原因。
- 内部群：固定禁用并提供原因。
- 单个统计聚合失败：统计项显示 `--` 和原因，消息详情仍可使用；接口整体失败时才显示重试状态。

## 11. 测试与验收

### 自动化

- 前端：URL 联动、目录分页、重点关注、类型切换、固定 20 条、详情筛选、游标、内容渲染、能力缺口和四种页面状态。
- 样式：宽屏列定义、工作台视口高度、面板独立滚动、1200px 以下抽屉规则、分页 hover 清晰度。
- 后端处理器：principal tenant/corp、员工权限交集、参数校验、40301、404 和 capability。
- 存储：目录聚合、部门裁剪、存档成员、离职人员、重点关注、详情统计、类型/关键词/日期、游标顺序和 MariaDB 语法。

### 浏览器

1. 2560×1440 下三栏填满内容区，右栏获得主要剩余宽度。
2. 1440×900 下右栏不少于 520px；1066×1272 下目录变抽屉，不出现 83px 详情栏。
3. 长会话只滚动消息区，页面和其他两栏高度不被撑开。
4. 员工搜索、部门、重点关注、会话类型、分页、详情筛选、刷新、关注和加载更早消息均真实生效。
5. URL 刷新后恢复员工、会话和筛选；非法页码与页大小被纠正。
6. MySQL、Redis 和现有数据卷保持不变。

## 12. 明确不做

- 不修改菜单导航和顶部 banner。
- 不复制圆弧 AI 的升级服务、成员、聊天内容或统计数字。
- 不在本页实现完整会话下载、AI 摘要、情绪识别或内部群归档。
- 不联动重构客户会话、群聊会话、会话轨迹和会话导出。
- 不为视觉完整而加入静态业务数据。
