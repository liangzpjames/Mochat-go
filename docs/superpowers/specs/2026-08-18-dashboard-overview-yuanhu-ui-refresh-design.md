# Dashboard 数据概览圆弧风格优化设计

## 背景与目标

总进度台账已把 2026-08-18 的主攻方向切换为 Dashboard 与 Sidebar/Operation 的逐页功能、交互和布局优化。数据概览 `/index` 已完成统一 reporting 口径、企业时区、AI 洞察、会话统计、趋势范围、分页和 CSV 导出，但当前页面仍以纵向模块堆叠为主，首屏主线、信息密度和行动入口没有达到可售卖产品应有的完成度。

本轮只优化数据概览，完成后暂停供用户检查。目标是吸收圆弧 AI 会话概览页清晰的业务分区、首屏信号密度和“指标 + 趋势”组合方式，同时保留 MoChat 已有的真实数据口径、权限边界和受限态表达，不复制圆弧品牌素材，不伪造当前没有来源的质检、排行或轨迹数据。

## 现状基线

### MoChat 当前能力

- 页面入口：`/#/index`，React 路由为 `/index`。
- 数据接口：`GET /dashboard/reports/overview`，权限键复用 `/dashboard/corpData/index#get`。
- 主筛选：企业、开始日期、结束日期；URL 保留日期与分页状态。
- 真实模块：经营指标、AI 洞察、客户增长趋势、客户/客户群会话统计与近七日趋势、经营趋势明细。
- 受限态：AI 或会话归档未接入时显示明确说明和配置入口，不显示伪造的零值业务结论。
- 已有门禁：加载、403、普通错误、旧接口错误、日期范围、分页、导出、AI 文本结构和会话切换均有组件测试。

### 圆弧参考页观察

2026-08-18 对圆弧 AI 会话 `/#/index` 实页进行只读检查，提炼出以下可借鉴模式：

- 数据概览首屏直接展示五个业务信号，图标、主数值、今日变化和累计值形成稳定阅读节奏。
- AI 洞察紧随经营概览，独立成区且指标密集，强化产品的 AI 定位。
- 会话与质检采用“左侧指标选择、右侧趋势图”的工作台结构，而不是将图表和数字拆成多个孤立卡片。
- 每个模块都就近展示团队或时间范围，用户能快速理解统计上下文。
- 白色大卡、浅灰蓝页面底色、较轻分隔线和少量高饱和强调色构成清晰层级。

圆弧参考页也存在大量零值指标和依赖其自有后端的质检、排行、轨迹模块。本轮不照搬这些数据模块，只借鉴信息组织方式。

## 方案选择

采用“驾驶舱重排”方案：保留 API、查询、权限和数据语义，重新组织页面首屏和模块关系，并在现有视觉体系内引入圆弧式的轻量卡片、上下文标签和左右工作台。

未选择仅调色和间距的轻量润色，因为它无法解决首屏主线弱和模块纵向堆叠的问题；未选择新增质检、排行、轨迹与 AI 任务流的深度产品化，因为缺少本轮可用的真实数据合同，会扩大后端、权限和验收范围。

## 范围与非目标

### 本轮范围

- 重排数据概览页面的信息架构和响应式布局。
- 优化筛选区、刷新状态、更新时间、数据来源和导出入口的表达。
- 重新设计经营指标卡、AI 洞察、客户增长、会话工作台和明细区。
- 复用现有 `DashboardOverview` 数据合同，不新增接口字段。
- 保留并强化加载、无权限、错误、空数据、AI 未接入和会话归档未接入状态。
- 补充组件结构、交互、样式合同和移动端布局测试。
- 在本地 Docker Desktop 中只重建 `app` 服务进行最终验收，保留现有数据卷。

### 非目标

- 不修改 reporting 后端、数据库迁移或权限资源。
- 不新增质检数据、员工排行、会话轨迹或同比/环比字段。
- 不恢复员工/部门 ID 高级筛选，不改变 principal 数据范围。
- 不引入新的图表或图标依赖，不复制圆弧 logo、插画或专有资源。
- 不改动其他 52 个 Dashboard 页面。

## 信息架构

页面从上到下分为五层。

### 1. 页首控制台

标题区保持“数据中心 / 数据概览”，增加当前企业和“统一报表口径”状态标签。日期筛选、查询、刷新和导出收敛为右侧操作组；刷新时按钮展示忙碌状态但保留当前数据，只有权限或请求错误时移除旧数据并进入专用状态。

桌面端标题与操作同排，窄屏改为上下布局。筛选错误和导出错误显示在控制台下方，并通过 `role="alert"` 对辅助技术可见。

### 2. 经营快照

四张 KPI 卡保持客户总数、线索总数、订单总数和行为事件四个真实口径。每张卡由小型色块图标、标签、主数值和口径说明组成，使用蓝、青、紫、橙四种克制强调色。卡片上方统一展示数据更新时间，避免每张卡重复状态。

卡片只表达当前筛选区间结果，不推导缺少基准数据的升降趋势。桌面端四列，中等宽度两列，移动端单列。

### 3. 智能经营区

桌面端使用 5:7 双栏：左侧 AI 洞察，右侧客户增长趋势。

- AI 已就绪：显示生成时间、结构化摘要和“查看 AI 洞察”入口；长摘要限制首屏高度并允许区块内部滚动，避免挤压趋势区。
- AI 未就绪：显示能力状态、简洁说明和“前往 AI 设置”行动按钮，不渲染零值假结论。
- 客户增长：模块标题、SCRM 来源标签、趋势日期选择和柱状趋势置于同一视觉卡片；空数据保留坐标区占位与明确文案。

### 4. 会话工作台

采用圆弧参考页的“左指标、右趋势”结构，但使用 MoChat 的真实会话合同。

- 左侧为客户会话/客户群分段选择，当前项突出显示；每项展示会话数、员工消息数和客户消息数。
- 右侧显示当前选择对应的近七日趋势，并保留来源、周期和图例。
- 会话归档不可用时，整块切换为受限态说明和配置指引，不显示三项零值。
- 近七日明细表放在工作台下方的次级区域，视觉权重低于趋势图，但仍保持可访问表格与分页合同。

### 5. 明细与页尾

经营趋势明细保留日期和新增客户列，作为导出范围的可读校验。它与会话趋势明细采用统一表头、行高、空态和分页样式。桌面端允许紧凑表格，移动端使用横向滚动容器，不压缩列内容。

## 组件边界

为避免当前页面文件继续膨胀，拆分为以下单元：

- `dashboard-overview-page.tsx`：查询状态、URL 状态、日期校验、导出、副作用和顶层编排。
- `dashboard-overview-widgets.tsx`：纯展示组件，包括指标卡、模块标题、AI 洞察、趋势图、会话工作台和空态。
- `dashboard-overview-api.ts`：保持现有数据解析和序列化职责，不改响应合同。
- `index.css`：只新增以 `.dashboard-overview-page` 或 `.overview-` 为前缀的页面样式，避免影响其他页面。

纯展示组件只通过 props 消费数据，不自行请求接口或读取路由。页面组件是唯一持有 TanStack Query、搜索参数和导出副作用的单元。

## 数据流与交互

1. 页面从 URL 读取 `startDate`、`endDate`、`page` 和 `pageSize`，无值时使用企业时区下的本月范围。
2. 页面将企业 ID、主日期范围、近七日趋势范围和分页传给 `DashboardOverviewApi.load`。
3. API 继续把 overview 响应解析成 `cards`、`summary`、`trend`、`aiInsight`、`conversation`、`limitations` 和分页信息。
4. 顶层页面根据 query 状态选择加载、403、错误或驾驶舱内容。
5. 修改主日期只更新 draft；点击查询后写回 URL 并重置到第 1 页。
6. 修改趋势日期只影响趋势请求范围，不污染主日期和导出范围。
7. 切换客户会话/客户群只改变本地展示状态，不重新请求接口。
8. 导出继续使用当前有效查询参数；失败只显示导出错误，不清空页面数据。

## 状态与错误处理

- 首次加载：展示与目标布局相符的骨架/状态卡，不闪现零值指标。
- 后台刷新：保留已有内容，刷新按钮进入忙碌状态，避免页面跳空。
- 403：立即移除旧企业数据，显示“无权访问当前企业数据”。
- 普通错误：移除旧数据，显示错误摘要和重试按钮。
- 旧接口或不兼容响应：沿用受控错误，不尝试用 legacy 字段拼接页面。
- 空数据：经营 KPI 可显示真实 0；趋势和明细显示“当前区间暂无数据”。
- AI 未接入：显示能力配置空态，不显示分析次数等伪指标。
- 会话归档未接入：显示 Provider 受限态，不显示会话零值。
- 日期无效或超过 31 天：保持现有查询不变，就地显示中文错误。

## 视觉规范

- 页面底色沿用 Dashboard 浅灰蓝环境，主卡使用白色，不增加大面积渐变背景。
- 大卡圆角 14px，小卡圆角 12px；边框使用低对比灰蓝色，阴影只用于悬浮和主层级。
- 主文字使用深蓝灰，次级文字使用中性灰；蓝紫色只用于主操作、选中态和关键数据。
- 标题层级固定为页面 `h1`、模块 `h2`、子区 `h3`，不以字号模拟标题。
- 卡片之间主要依赖 16–20px 留白区分，不使用密集实线分割。
- 动效限制为 120–180ms 的颜色、边框和轻微位移过渡；遵循 `prefers-reduced-motion`。
- 所有图标为装饰时使用 `aria-hidden="true"`；数值、来源、周期和状态必须保留文字。

## 响应式与可访问性

- `> 1180px`：经营快照四列；智能经营区 5:7；会话工作台 4:8。
- `721–1180px`：经营快照两列；智能经营区和会话工作台改为单列。
- `<= 720px`：操作区、KPI、会话选择均单列；表格横向滚动；按钮保持至少 40px 可点击高度。
- 键盘可依次访问日期、查询、刷新、导出、AI 入口、会话切换和分页。
- 会话切换按钮保留 `aria-pressed`；趋势图保留可读 `aria-label`；分页继续使用共享的 `navigation` 合同。
- 颜色不是唯一状态线索，选中态同时使用文字、边框和 `aria-pressed`。

清理后再次记录 `docker system df -v` 和四个卷，确认卷仍存在。若 Docker 已释放内部块但 VHDX 文件未缩小，只记录逻辑释放量；本轮不直接操作 VHDX，不手工压缩或迁移 WSL 数据盘。

## 完成标准

- 数据概览形成“页首控制台 → 经营快照 → AI/增长 → 会话工作台 → 明细”的稳定信息主线。
- 视觉层级明显接近圆弧 AI 会话参考页的产品化密度，但所有指标和状态仍来自 MoChat 真实合同。
- 现有 API、权限、URL、日期、导出和分页合同不回退。
- 桌面和 390px 移动端均可用，无页面级横向溢出。
- Docker 清理不删除任何数据卷，后续构建和 Docker Desktop 数据继续位于 D 盘。
- 完成自动化与本地 Docker 浏览器验收后暂停，由用户检查数据概览页面，再决定下一个页面。
