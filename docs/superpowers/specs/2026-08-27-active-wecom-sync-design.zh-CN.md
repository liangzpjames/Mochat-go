# 企业微信主动同步设计

## 1. 背景与结论

当前人员同步入口分散在员工、部门和唯一企业资料页面，其中唯一企业资料的同步区域随第三方代开发配置区一起被隐藏；会话存档只有周期任务，没有操作员可用的手动触发合同。结果是操作员无法在一个明确位置判断“能否同步、是否正在同步、最近一次结果”，第三方模式尤其没有入口。

本次采用“统一入口 + 业务页快捷入口”：在唯一企业资料页增加与配置模式解耦的“数据同步”区域；员工列表和全局会话页保留同一正式合同的快捷入口。同步按钮只发起服务端任务，不把前端刷新伪装成同步。

## 2. 备选方案

1. **统一入口 + 业务页快捷入口（采用）**：发现成本最低，既方便日常操作，也方便集中排障；需要抽取可复用的前端同步组件。
2. 只在唯一企业资料页集中展示：实现较少，但员工和会话操作员必须离开工作页面。
3. 只在各业务页放按钮：入口直观但状态和前置条件继续分散，难以审计。

## 3. 产品行为

### 3.1 统一同步区域

唯一企业资料页始终展示“数据同步”，不归属于自建应用配置区，因此自建应用和第三方代开发应用都能看到。区域包含两张紧凑卡：

- 人员信息：状态、最近完成时间、部门数、员工数、“立即同步人员”“刷新状态”。
- 会话存档：状态、最近完成时间、已处理消息数、失败数、“立即同步会话”“刷新状态”。

状态文案只使用“尚未同步、等待处理、同步中、已完成、同步失败、暂不可用”。不展示内部错误码、source、cursor、lease 或 Provider 名称。

### 3.2 快捷入口

- 员工列表的原按钮改为“立即同步人员”，先弹出确认框，随后调用唯一企业人员同步正式 API；任务进入队列后刷新列表和同步状态。
- 全局会话页在筛选操作区提供“立即同步会话”，同样先确认，再调用正式会话存档任务 API；成功后刷新会话列表、概览和同步状态。
- 快捷入口与统一同步区域共享 API、状态映射和 Query key，不产生两套同步语义。

### 3.3 配置不足与权限

- 未配置企微或未开通对应能力时，Dashboard 仍正常展示空数据；同步按钮禁用，并显示“需要管理员先完成对应授权”之类的业务说明，不把缺少配置当页面加载错误。
- 第三方代开发模式不显示企微配置表单，但只要 SaaS 当前授权包含对应能力且凭据可用，就可以同步。
- 发起同步必须使用服务端认证得到的 tenant/corp，不接受请求体传入 tenantId、corpId 或 actorId。
- 人员同步沿用现有写权限；会话同步新增明确的 Dashboard 写权限合同，默认仅唯一企业资料写权限或超级管理员可执行。只读用户可以看状态，不能发起任务。

## 4. 后端架构与数据流

### 4.1 人员同步

复用现有 `POST /dashboard/company/employee-sync`、Redis 可靠队列、绑定版本围栏和 `GET /dashboard/company/sync-status`。前端不再依赖第三方模式判断来隐藏同步入口。重复点击由按钮 pending 状态和队列幂等共同抑制。

### 4.2 会话存档同步

新增：

- `POST /dashboard/company/archive-sync`：请求只携带一次性 `requestId`；服务端解析当前 principal、检查当前集成模式、`archive.read` 能力、验证状态和 bridge 可用性，然后在 0138 durable run ledger 创建 `queued` 任务并返回任务摘要。
- `GET /dashboard/company/archive-sync-status`：按当前 tenant/corp 返回最近任务的业务状态、计数和时间；无记录返回 `idle`，不报错。

手动任务使用 `archive:manual:<requestId>` 幂等键。durable worker 优先领取已有 queued run，再执行常规定时拉取；重启后 queued/running 的 lease 接管规则继续有效。定时轮询键加入服务端时间窗口，避免“某次空拉取成功后同一 cursor 永久不再检查”的问题，同时保持同一窗口的多实例幂等。

媒体仍由现有 durable media worker 分片下载；手动消息同步成功只代表消息页已处理，媒体状态继续按现有 worker 独立推进。

### 4.3 审计与安全

- 0138 run/audit ledger 记录 enqueue、start、complete、fail、retry/stale takeover。
- Dashboard 企业审计追加不含 Secret 的 `company.archive_sync.requested` 操作事实，或在现有 run audit 已足够时以 run audit 作为权威证据；前端不展示技术详情。
- 请求、响应、日志和前端缓存均不得包含企微 Secret、永久授权码、RSA 私钥、bridge token 或 SDK file id。

## 5. 错误与并发

- 同一租户已有 queued/running 任务时返回已有任务摘要，前端显示“正在处理中”，不重复创建。
- 配置不足返回稳定机器码供前端映射，但页面只显示中文原因。
- bridge/存储失败进入 durable failed 状态；游标只在成功保存页后推进，沿用现有失败不推进合同。
- HTTP 请求只负责入队，不等待完整企微拉取；进程重启后 worker 从账本继续。

## 6. 测试与验收

- Go：服务授权、租户隔离、能力门槛、幂等、queued 领取、重启/lease、状态投影、路由和审计。
- 前端：两种模式均显示同步区域；配置不足为空数据而非页面错误；确认前不发请求；pending 防重复；成功/失败状态；业务页快捷入口；无内部错误码。
- Docker：只重建 app，保留 MariaDB、Redis、媒体卷和 bridge；验证主动同步写入正式 run/queue、状态刷新、重启恢复。
- 浏览器：唯一企业资料、员工列表、全局会话页分别实际点击；检查网络、控制台、刷新恢复、桌面和 390×844。

## 7. 边界

本地验收只使用去敏 bridge/SDK 夹具，不调用真实企业微信。按钮可证明正式本地任务合同、持久化和回读有效，不能宣称真实企微线上同步已经通过。
