# 会话运营四页优化设计

> 文档日期：2026-08-20
> 审阅状态：待用户审阅
> 目标路由：`/chat/file-audio`、`/chat/resign-staff`、`/chat/refuse-archive`、`/customer/inheritance`

## 1. 目标与停止点

本轮优化“文件录音（用户称会话录音）”“离职员工”“拒绝存档”“客户继承”四个菜单。借鉴圆弧 AI 对应页面的信息架构、视觉密度和交互节奏，但字段、状态和操作必须来自 MoChat 真实接口。

设计完成后的实施目标是：

1. 四页形成统一、紧凑、适合宽屏的会话运营视觉体系；
2. 文件录音保留已存在的上传、鉴权播放和软删除闭环；
3. 离职员工升级为“离职员工—会话列表—会话详情”三栏工作区；
4. 拒绝存档按客户和群聊分区，补齐筛选、分页、中文状态和跟进面板；
5. 客户继承整合已有离职继承、在职继承、分配记录和真实企业微信转接能力；
6. 实施完成后在本地真实路由逐项点击验收布局、按钮和交互。

产品呈现遵循“只展示可闭环能力”：页面不渲染“能力未接入”“功能未接入”一类提示，也不保留无法使用的标签、禁用按钮或占位模块。确实依赖独立数据链、必须后续专项建设的能力，统一登记在 `docs/PROJECT_PROGRESS.zh-CN.md`，不进入本轮页面信息架构。

本文档和配套实施文档完成后停止，等待用户审阅；审阅通过前不修改业务代码。

## 3. 方案比较与结论

### 方案 A：只做视觉换肤

保留现有组件和接口，只调整颜色、间距、按钮与表格。

- 优点：改动最小；
- 缺点：离职员工和客户继承仍是错误的信息架构；英文动态表头、交互缺口和数据语义问题不会消失。

### 方案 B：完全复制圆弧 AI 页面

按参考页复刻所有标签、字段、统计、配置说明和操作。

- 优点：视觉相似度最高；
- 缺点：MoChat 缺少聊天文件内容和继承侧边栏页面，强行复制会产生假数据、空壳按钮或错误 URL；也会丢失 MoChat 已有的人工上传音频和真实转接能力。

### 方案 C：共享骨架、真实领域页面（采用）

四页共用紧凑页头、查询区、状态反馈、表格/工作区、抽屉和分页规则；每页使用自己的类型化 API 和真实领域模型。MoChat 已有且能真实闭环的能力保留并重组到合理位置；参考页有但当前缺少完整数据链的入口从页面信息架构中移除，只登记到总进度文档。

选择该方案，因为它同时解决布局、数据语义和交互闭环，且满足“不编造数据、页面最终可验收”的约束。

## 4. 全局设计规则

### 4.1 页面骨架

1. 保留现有左侧菜单、顶部 banner、菜单名称和路由，不修改全局导航；
2. 页面顶部只放标题、短说明和必要状态，不使用大块渐变介绍卡；
3. 标签页紧贴标题区下方；
4. 查询、重置和刷新归入同一查询操作区，不在页头重复放刷新按钮；
5. 主按钮为 MoChat 蓝色实心样式，次按钮为白底描边样式，危险操作为红色文字/描边并二次确认；
6. hover 只改变背景、边框和颜色，不使用位移或缩放；
7. 表格页脚统一展示总数、固定页大小、当前页码和上一页/下一页；
8. 抽屉通过关闭按钮、遮罩和 `Escape` 关闭；抽屉内点击不触发遮罩关闭；
9. 查询条件、标签页、页码和选中详情写入 URL；刷新浏览器后恢复合理状态；
10. 所有数字、状态、列表项和按钮可追溯到真实 API；没有完整实现链路的入口不渲染。

### 4.2 宽屏与响应式

- `2560×1440`：内容占满主区域，不设置 `1320px` 最大宽度；三栏页按 `300px / minmax(360px, 0.9fr) / minmax(560px, 1.35fr)` 分配；
- `1440×900`：表格不挤压关键列，允许表格区域横向滚动；三栏维持可用宽度；
- `1024px` 以下：三栏改为单列钻取，员工列表、会话列表、会话详情通过“返回”按钮切换；
- 页面只保留一个主滚动容器；目录、会话列表和详情可在各自面板内滚动，避免整页被超长消息撑开。

### 4.3 状态和文案

统一区分：

| 状态 | 展示方式 |
|---|---|
| 查询成功但当前条件无数据 | 业务空态，说明如何产生数据或调整筛选 |
| 后端没有业务字段 | 不显示对应列，不用 `--` 拼出参考页面结构 |
| 不属于本轮可闭环能力 | 页面不呈现入口、标签、禁用按钮或说明模块；仅登记总进度文档 |
| 权限不足 | 权限空态，保留返回或重新选择企业入口 |
| 同步/接口异常 | 错误状态和重试按钮，保留后端原始错误的可理解摘要 |
| 正在加载/提交 | 骨架或加载态；相关按钮禁用且文案改为“处理中…” |

## 5. 页面设计

### 5.1 文件录音 `/chat/file-audio`

#### 信息架构

- 页头：标题“文件录音”，说明“管理录音文件的上传、筛选、播放和删除”；
- 内容区直接展示 MoChat `mochat_go_audio_objects` 中真实上传并可回读的音频，不增加没有业务内容的标签页；
- 查询区：文件名、上传日期起止、查询、重置、刷新；
- 右侧操作：“上传录音”打开上传对话框，不再单独占据大卡；
- 列表字段：文件名、格式、大小、时长、上传时间、数据来源、播放、操作；
- 数据没有真实时长时显示 `--`，不把 `0` 解释成零秒；
- 删除使用确认对话框，成功后保持当前筛选；若删除当前页最后一条且页码大于 1，回退一页；
- 音频加载失败时显示行内错误和“重试播放”，不影响其他行。

#### 与参考页的差异

圆弧 AI 的聊天文件、发送人、接收人、智能摘要、统计查询和导出依赖会话存档媒体索引、对象关联和导出任务链，现有 `mochat_go_audio_objects` 不能提供。本轮页面不展示这些标签、字段或说明；专项建设边界登记到总进度文档。页面仅陈述当前可执行的上传、筛选、播放和删除动作，不把上传对象描述成企业微信会话录音。

### 5.2 离职员工 `/chat/resign-staff`

#### 信息架构

采用三栏会话工作区：

1. 左栏“离职员工”：员工姓名搜索、部门树、离职员工列表、会话数和最后会话时间；
2. 中栏“会话”：外部联系人/群聊类型筛选、日期范围、刷新、固定每页 20 条；整行可点击；
3. 右栏“会话详情”：会话对象、时间/类型筛选、真实消息和加载更多。

页面复用员工会话已落地的真实数据链：

- `staffDirectory({mode: 'departed'})` 只返回离职状态员工；
- `search({employeeIds: [...]})` 返回该员工的会话列表；
- `staffDetail({conversationId: ...})` 返回归档消息详情。

会话类型只呈现已有归档查询支持的外部联系人、客户群和员工单聊；现有内部群控制项不在本页面出现，其独立归档链建设登记到总进度文档。

没有选中员工时，中栏显示“请选择离职员工”；没有选中会话时，右栏显示“请选择会话”。如果员工已离职但没有归档数据，显示“有离职员工记录，但当前没有可查看的会话”，不与“没有离职员工”混淆。

#### URL 状态

使用 `employeeKeyword`、`departmentId`、`employeeId`、`conversationType`、`startAt`、`endAt`、`page`、`conversationId`、`messageTypes`、`messageDate`。切换员工清除会话和详情状态；切换会话类型或日期清除当前详情。

### 5.3 拒绝存档 `/chat/refuse-archive`

#### 信息架构

- 标签页：
  - `客户`：`subjectType=customer`；
  - `群聊`：`subjectType=room`；
- 查询区：主体名称/ID、关联员工、拒绝日期起止、授权状态、跟进状态、查询、重置、刷新；
- 表格：主体信息、关联员工、授权状态、拒绝时间、同步来源、跟进状态、操作；
- 授权状态中文映射：`refused=已拒绝`、`pending=待授权`、`authorized=已授权`、`expired=已过期`；
- 跟进状态中文映射：空值/`unfollowed=未跟进`、`contacted=已联系`、`waiting=等待授权`、`completed=跟进完成`；
- “跟进”打开右侧抽屉，显示当前授权状态、来源、拒绝/授权时间、最近跟进时间、备注；
- 保存跟进后关闭抽屉、刷新当前页并显示成功反馈；失败时保留表单内容；
- 每页 20 条，API 返回 `total/page/perPage`，URL 保存页码和筛选。

#### 后端扩展

现有 `RefuseArchivePage` 已有分页，但过滤条件缺少 `subjectType`、员工和拒绝时间。本轮扩展 `RefuseArchiveFilter` 和 SQL 条件，不新增假字段。群聊标签页只有在 Provider 同步了 `subject_type=room` 记录时才有数据。

### 5.4 客户继承 `/customer/inheritance`

#### 标签页

1. `离职继承`：整合待分配客户、待分配群聊、同步和批量分配；
2. `在职继承`：选择在职员工后，展示其客户并批量分配给接替员工；

页面只呈现以上两个能够闭环的一级标签。继承侧边栏 H5 需要独立路由、鉴权和历史会话查询链，本轮不在页面中提供入口，专项建设边界登记到总进度文档。

右上角统一提供“继承记录”，打开抽屉，不跳出当前菜单。

#### 离职继承

- 二级标签：`待分配客户`、`待分配群聊`；
- 客户筛选：客户名称、原跟进员工、添加日期；
- 群聊筛选：群名称；
- 客户字段：客户、原跟进员工、标签、添加时间、添加渠道；
- 群聊字段：群聊名称、原群主、群人数、今日入群、今日退群、创建时间；
- 真实同步时间来自 `/contactTransfer/unassignedList.lastTime`；
- “同步离职数据”调用新的 POST 同步别名，服务端复用现有企业微信 `get_unassigned_list` 链路；
- 勾选记录后“分配给其他员工”打开员工选择对话框；未选择数据时按钮禁用；
- 客户分配调用 `/contactTransfer/index`，群聊分配调用 `/contactTransfer/room`；
- 结果按企业微信响应分别统计成功和失败，失败项保留选中并展示原因，成功项从列表移除。

#### 在职继承

- 初始状态先选择“原跟进员工”；
- 选中后展示该员工客户，可按客户名称、添加日期筛选；
- 选择客户和接替员工后调用 `/contactTransfer/index`，`type=2`；
- 接替员工不能与原跟进员工相同；
- 结果反馈和失败保留策略与离职继承一致；
- 在职继承页只呈现客户资产和客户转接操作，不增加群聊标签或限制说明；在职群聊资产读取与转接需要独立接口建设，登记到总进度文档。

#### 继承记录

- 标签：`离职客户`、`离职群聊`、`在职客户`，分别映射 `mode=1/2/3`；
- 筛选：名称、接替员工、分配日期；
- 展示客户/群聊、接替员工、转接状态、数量或客户企业、分配时间；
- 客户状态使用后端既有中文值，不在前端推导；
- 记录抽屉关闭后保留主页面筛选和选中项。

| 继承记录 | `logs` | `GET /dashboard/contactTransfer/log` | `mc_work_transfer_log` + 客户/群/员工 | 无记录为未发生对应类型转接 |

所有请求沿用当前登录用户、租户、企业和数据范围。页面不得自行提交 `corpId` 覆盖服务端 principal。

## 7. 组件与文件边界

### 7.1 前端

- `features/conversation-operations/`：只放四页共享的页头、标签、查询操作区、状态徽标、抽屉和格式化函数；
- `features/phase35/file-audio-*`：保留音频 API 与页面，收拢为紧凑结构；
- `features/conversation-operations/resigned-employee-page.tsx`：只编排离职目录、会话和详情，复用现有 conversation-global 组件与 API；
- `features/conversation-operations/refuse-archive-*`：类型化解析、筛选、分页和跟进；
- `features/conversation-operations/customer-inheritance-*`：离职/在职继承、批量分配、同步和记录抽屉；
- `styles/conversation-operations.css`：只负责四页布局和交互态，不继续把规则追加到已有超长 `index.css`；
- `benchmark/page-registry.tsx` 与 `main.tsx`：仅完成新 API 和页面注入。

每个领域组件只消费自己的类型化接口，不再根据接口首行动态生成列，也不直接渲染原始字段名或 JSON。

### 7.2 后端

- 音频列表扩展上传日期过滤，沿用现有 handler/store；
- 拒绝存档扩展真实过滤条件，沿用现有表；

## 8. 权限与安全

1. 文件读取、上传和删除继续使用 `/chat/file-audio#get` 及现有对象企业校验；
2. 离职会话复用会话页面的员工数据范围，目录、会话列表和详情必须使用同一允许员工集合；
3. 拒绝存档读取与跟进分别使用 `#read` 和 `#manage`；没有管理权限时仍可查看，但不渲染可提交的跟进按钮；
4. 客户继承读取、同步和分配需要分别登记资源；批量分配前必须二次确认，确认文案包含记录数、原员工和接替员工；

## 9. 错误处理与并发

- 查询请求使用稳定 query key，切换企业时清理旧企业缓存；
- 快速切换标签或筛选时，只渲染最后一次查询对应结果；
- 提交期间关闭重复点击；
- 批量转接根据每条 Provider 响应生成成功/失败汇总；只刷新成功影响的列表；
- URL 中非法页码、日期、枚举和 ID 在页面初始化时清理为默认值；
- 列表总数减少导致当前页越界时回退到最后有效页；
- 抽屉关闭不取消已经提交的请求，但提交完成前禁用表单，结果反馈仍可见；
- Provider 或企业微信配置导致请求失败时，页面按真实查询/提交错误处理并提供重试；不转换为普通空列表，也不输出产品建设进度文案。

## 13. 文件录音菜单修复追加设计（2026-08-21）

## 16. 客户继承开发模拟转接修复追加设计（2026-08-21）

实测确认分配时，开发环境使用的 `wwSIM...` / `SIM-...` 凭据被错误送往真实企业微信接口，返回 `40013 invalid corpid`，页面因此显示通用失败提示。转接客户端对这组明确的开发模拟凭据增加本地成功响应，客户和群聊转接均不发起外部请求；真实企业微信凭据继续走原 HTTP 链路。该判断仅匹配开发样例凭据前缀，不改变生产企业微信转接口径。

凭据与权限补充约束：开发容器可能没有预览环境的企业微信密钥，因此 Store 只允许对 `wwSIM...` 且 Secret 以 `SIM-` 开头的样例读取本地开发凭据；任何真实企业凭据仍必须通过加密管理器解密。同步入口 `POST /dashboard/contactTransfer/sync` 必须列入精确 Dashboard 权限白名单，确保同步确认不会在 Handler 前被 RBAC 拒绝。
