# 群活码直连企微客户群优化设计

> 日期：2026-08-22  
> 状态：用户已授权按推荐方案连续实施，完成后统一审阅  
> 目标路由：`/acquisition/group-code`

## 1. 目标与结论

群活码完全切换为企微“客户群加入群聊”模式。用户填写业务名称、选择最多 5 个已同步客户群并配置满群处理后，系统调用企微加入群聊接口，保存企微返回的配置 ID 和二维码地址。扫码者直接进入客户群，不再先添加接待员工。

渠道活码继续使用企微“联系我”能力，本轮不改变渠道活码的数据契约和交互。

## 2. 方案比较

1. **完整切换为直接进群（采用）**：业务语义与圆弧 AI 一致，二维码来自企微加入群聊接口；需要调整后端 Provider、迁移字段和前端表单。
2. 双模式兼容：同时提供直接进群和先加员工两种模式；操作复杂，用户容易选错，且延续旧模型负担。
3. 仅隐藏技术字段：后端仍走联系我接口；界面看似简化但二维码不能直接进群，属于错误业务表达。

用户已授权采用方案 1，并由实施方完成剩余设计决策和自测。

## 3. 页面与交互

### 3.1 新建抽屉

群活码表单仅展示以下业务字段：

- 群活码名称：必填，最多 30 个字符。
- 可加入的群聊：必填，来自当前企业已同步客户群，最多选择 5 个；普通单击独立切换。
- 群满后自动建群：默认关闭。
- 新群名称：仅自动建群开启时必填，最多 30 个字符。
- 起始序号：仅自动建群开启时必填，整数且不小于 1。

删除“使用成员”“入群引导语”“客户标签 ID”和任何 JSON 输入。底部主按钮文案为“保存并生成二维码”；提交期间锁定关闭和重复提交。

本轮新建记录默认进入“未分组”。现有列表仍保留按 `group_id` 查看历史分组的兼容能力；由于当前代码库只有分组权限资源和数据表、尚无可用的群活码分组业务端点，本轮不在创建抽屉中展示一个无法可靠加载与校验的分组选择器。

保存成功后展示企微返回的真实二维码结果，可关闭结果层回到已刷新的列表。企微未返回二维码时不展示占位码，并提示配置未生成。

### 3.2 群聊选择

沿用已实现的双栏群聊选择弹窗：左侧搜索真实群聊，右侧显示有序已选项；确认才写回表单，取消、遮罩和关闭按钮放弃草稿。容量仅用于业务提示，不再作为是否可提交的依据；企微加入群聊接口的限制由真实 `wx_chat_id` 和最多 5 群校验保证。

### 3.3 历史数据

新增 `provider_kind` 区分旧版 `contact_way` 和新版 `join_way`。历史记录继续可查看和下载，并显示“旧版活码”提示；本轮新建记录一律为 `join_way`。避免通过 SQL 假装把旧二维码转换为直接进群二维码。

## 4. 数据来源矩阵

| 页面字段 | 前端来源 | 后端/存储来源 | 提交给企微 | 空值或异常语义 |
| --- | --- | --- | --- | --- |
| 群活码名称 | 用户输入 | `mc_work_room_auto_pull.qrcode_name` | `remark` | 空值禁止提交 |
| 可加入群聊 | `GET /workRoom/roomIndex` | `mc_work_room.id/name/wx_chat_id` | `chat_id_list` | 无群提示先同步；缺少 `wx_chat_id` 的群不可提交 |
| 自动建群 | 用户开关 | `auto_create_room` | `auto_create_room` | 默认关闭 |
| 新群名称 | 用户输入 | `room_base_name` | `room_base_name` | 开启自动建群时必填 |
| 起始序号 | 用户输入 | `room_base_id` | `room_base_id` | 开启自动建群时必须大于 0 |
| 二维码 | 企微响应 | `qrcode_url` | `get_join_way.qr_code` | 未返回即创建失败，不生成假图 |
| 配置 ID | 企微响应 | `wx_config_id` | 为后续更新/删除能力保留 | 未返回即创建失败 |

## 5. 后端架构与数据流

新增独立 `WorkRoomAutoPullJoinWayClient`，封装企微以下能力：

- `externalcontact/groupchat/add_join_way`
- `externalcontact/groupchat/get_join_way`
- `externalcontact/groupchat/update_join_way`
- `externalcontact/groupchat/del_join_way`

创建数据流：

```text
表单参数
  -> 校验名称、最多 5 个群、自动建群参数
  -> 按 corp_id + room_id 解析全部 mc_work_room.wx_chat_id
  -> 调用 add_join_way 获取 config_id
  -> 调用 get_join_way 获取 qr_code
  -> 保存 join_way 配置与二维码
  -> 返回 { workRoomAutoPullId, qrcodeUrl }
```

Provider 调用失败时不写入业务记录。Provider 成功而数据库写入失败时，使用脱离请求取消状态且带超时的上下文调用 `del_join_way` 清理远端配置，并根据真实清理结果向用户返回失败。历史 `contact_way` 更新继续走原链路；新版 `join_way` 当前没有编辑入口，后端更新接口在任何本地或远端修改前返回 409，避免误用旧版联系我接口。业务删除端点不在本轮范围内。

## 6. 数据库兼容策略

新增可回滚迁移，为 `mc_work_room_auto_pull` 增加：

- `provider_kind varchar(20) NOT NULL DEFAULT 'contact_way'`
- `auto_create_room tinyint unsigned NOT NULL DEFAULT 0`
- `room_base_name varchar(30) NOT NULL DEFAULT ''`
- `room_base_id int unsigned NOT NULL DEFAULT 1`

旧列 `employees`、`tags`、`leading_words`、`is_verified` 暂不删除，以兼容历史记录和旧版本回滚。新版记录写入安全空值：`employees=[]`、`tags=[]`、`leading_words=''`、`is_verified=2`。

## 7. 错误处理

- 未配置企微客户联系凭证：提示“当前企业未完成客户联系接口配置”。
- 群未同步或跨企业：返回明确的群聊失效提示，不提交部分群。
- 群数量超过 5：前后端同时拦截。
- 企微无权限、应用不可调用或接口返回错误：透传可理解的企微错误，不保存假二维码。
- 自动建群开启但名称/序号不合法：前后端保持相同校验。
- 二维码读取失败：清理新建远端配置并返回失败。

## 8. 测试与验收

自动化测试采用先失败后通过，覆盖：

1. 加入群聊 Provider 客户端的创建、读取二维码、更新、删除请求契约；当前业务入口仅开放创建。
2. room ID 必须全部解析为当前企业非空 `wx_chat_id`，顺序保持一致。
3. 群活码保存不再要求员工、客户标签和引导语。
4. 自动建群开启时的名称和起始序号校验。
5. 新建成功响应包含真实二维码；Provider 失败不留下业务记录。
6. 前端群表单不出现旧字段，最多 5 群，保存 payload 与结果二维码正确。
7. 渠道活码成员多选回归不受影响。

Docker 仅重建 `app`，保留 MySQL、Redis 和命名卷。浏览器在本地真实路由验证新建抽屉、群聊搜索/选择/取消、自动建群联动、校验提示、提交失败保留表单和成功二维码结果；检查常规桌面和 2560×1440 布局、控制台及关键网络请求。

## 9. 非目标

- 不实现海报编辑器或素材模板市场。
- 不自动修改历史二维码的企微配置类型。
- 不给未配置企微接口的环境生成模拟二维码。
- 不修改菜单导航、顶部 banner 或渠道活码业务链路。
- 不新增群活码分组管理端点；新建记录默认未分组。
- 不开放新版 `join_way` 的编辑或业务删除操作；编辑请求在修改数据前被明确阻断。
