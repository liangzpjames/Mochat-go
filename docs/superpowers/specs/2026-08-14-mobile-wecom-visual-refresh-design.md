# 移动端企业微信风格视觉优化设计

## 1. 背景与目标

现有 `web/apps/sidebar` 与 `web/apps/operation` 已完成独立认证边界、显式路由和两个真实业务纵切面，但页面仍以工程基础样式为主。用户提供的四张企业微信移动端参考图体现了成熟的员工工作台视觉语言：浅蓝页面背景、白色圆角卡片、蓝色渐变重点区域、图标宫格、固定底部导航、轻量分隔和大面积留白。

本次目标是在不改变现有业务合同、认证模型和路由数量的前提下，让两个移动端具备一致、适合企业微信 WebView 的产品级视觉基础：

- Sidebar 员工端采用“客户 / 会话 / 我的”三栏底部导航和工作台式页面层级。
- Operation 外部活动端沿用同一视觉令牌、卡片与状态风格，但不显示员工导航。
- 真实页面继续使用真实 API 数据；未迁移页面仍明确显示“模块待迁移”，不生成假统计、假列表或假操作结果。
- 390×844 为主要设计视口，同时保证 320px 至桌面预览宽度无文档级横向溢出。

## 2. 参考图识别结果

四张参考图的共同规律如下：

1. 页面底色为低饱和浅蓝，内容使用纯白卡片形成层级，不依赖重边框。
2. 卡片圆角约 16–24px，组间距明显大于卡片内间距，阴影非常克制。
3. 主色为明亮蓝色，重点卡片使用蓝色渐变；绿色、橙色仅作为小面积语义色。
4. 标题使用较强字重，正文和说明使用中灰色；数值、状态和主要按钮强调明显。
5. 常用功能使用图标宫格；列表页使用搜索、分类标签、筛选和独立空状态。
6. 底部导航固定在安全区上方，图标与文字垂直排列，当前项使用蓝色强调。
7. 顶部返回、关闭、更多菜单和手机状态栏属于企业微信宿主界面，不应在 H5 内重复绘制。

本项目只复用上述布局与视觉规律，不复制参考产品名称、Logo、人物插画、机器人形象或其他品牌素材。

## 3. 方案比较与选择

### 方案 A：共享视觉系统 + 应用级组合（采用）

在 `@mochat/mobile-foundation` 中建立视觉令牌、页面壳、卡片、图标按钮、状态组件和底部导航基础；Sidebar 与 Operation 在各自应用内组合业务内容。

优点是两端一致、可测试、可持续迁移，且不会把员工导航或身份状态错误共享给 Operation。缺点是首轮需要同时修改共享层与两个应用。

### 方案 B：两个应用分别重写 CSS

短期改动较少，但会复制卡片、状态、间距和响应式规则，后续 20 个待迁移模块容易产生视觉漂移。

### 方案 C：一次性重做完整移动端信息架构

可最接近参考产品的完整工作台，但需要新增大量 Dashboard/会话/统计 API 与路由，超出本次“优化现有移动端样式”的范围，也会诱发假数据和临时接口。

因此采用方案 A。

## 4. 共享视觉系统

### 4.1 视觉令牌

在 `web/packages/mobile-foundation/src/styles/mobile.css` 中统一：

- 页面背景：`#eef6ff`，内容表面：`#ffffff`。
- 主色：`#1677ff`，强调渐变：`#5f80ff -> #1688ff`。
- 主文字：`#172033`，次文字：`#7d8799`，弱文字：`#a8b0bd`。
- 圆角：卡片 20px、控件 14px、胶囊 999px。
- 页面水平边距：16px；卡片间距：16px；触控区最小 44px。
- 底部导航高度与 `safe-area-inset-bottom` 合并计算。

### 4.2 共享组件

- `MobileShell`：负责页面背景、内容最大宽度、安全区和可选底部区域；不模拟企微宿主顶部栏。
- `MobileCard`：白色卡片，支持普通、强调、无内边距三种密度，不包含业务数据。
- `MobileIconTile`：图标、标题、可选说明/角标的可访问入口，图标使用项目内 SVG/CSS 图形。
- `MobileBottomNavigation`：可访问链接列表、当前项状态、固定底部安全区；业务路由由调用方提供。
- `MobileState`：加载、空、错误、无权、未找到统一为轻量插图式状态，不使用外部图片。

所有组件只包含展示与可访问语义，不读取 token、路由、Dashboard storage 或业务状态。

## 5. Sidebar 员工端设计

### 5.1 底部导航

认证后的业务页面显示三栏：

- 客户：映射现有 `/contact`，保留当前 query/hash，避免丢失 `wxExternalUserid`。
- 会话：映射现有 `/contactSop`，保留当前客户上下文参数。
- 我的：映射现有 `/`。

`/login`、`/auth`、`/codeAuth` 和未知路由不显示底部导航。导航只使用现有 manifest 路由，不新增第 13 个授权单元，也不伪造业务完成状态。

### 5.2 客户详情

真实 `/contact` 页面改为参考图中的资料卡形式：头像、客户名称、客户编号和企业编号分层显示；只展示 `ContactSummary` 已返回的字段，不推测手机号、标签或员工归属。无头像使用中性渐变占位图标。

页面下方提供“当前客户”信息分组和统一状态区，但不新增无后端支持的编辑、拨号或写操作。

### 5.3 待迁移页面

现有待迁移入口改成工作台卡片：显示模块图标、名称、说明和“功能建设中”状态。页面仍不提供可点击的假按钮。Sidebar 首页 `/` 可展示 12 个现有模块的只读入口宫格；只有真实注册路由可点击。

## 6. Operation 活动端设计

Operation 不显示“客户 / 会话 / 我的”导航，避免混淆外部参与者和企业员工身份。

真实 `/workFission?id=...` 页面采用活动 H5 结构：

- 顶部为 CSS 渐变活动横幅，展示“任务宝活动”和可信的静态说明，不复制参考图人物或品牌素材。
- 进度摘要使用蓝色渐变重点卡，展示真实 `inviteCount` 与 `differCount`。
- 任务列表使用白色圆角卡片，完成/未完成和奖励领取状态使用语义色与图标区分。
- OAuth、活动结束、无权限、网络失败等继续使用既有 fail-closed 行为，只优化视觉，不改变请求顺序或身份来源。

其余 9 个入口使用统一活动卡片和“模块待迁移”状态，不生成随机进度、奖品或参与人数。

## 7. 图标与素材策略

- 优先使用内联 SVG 图标组件和 CSS 渐变形状，保证清晰度、主题一致性和无外部网络依赖。
- 不引入新的大型 UI 库或图标运行时依赖。
- 不复制参考图中的品牌 Logo、人物、机器人、插画和产品名称。
- 所有纯图形图标使用 `aria-hidden`；有独立含义的按钮必须有可读名称。

## 8. 响应式与交互

- 主要视口为 390×844；320px 下卡片与宫格自动收缩，桌面预览最大宽度 480px 并居中。
- 底部导航固定时，内容区必须预留高度，不能遮挡最后一项内容。
- 所有链接和按钮最小触控尺寸为 44×44px。
- 尊重 `prefers-reduced-motion`，仅使用轻量淡入/位移效果。
- 不引入横向滚动；长名称和错误信息允许安全换行。

## 9. 测试与验收

按 TDD 实施，每个行为先写失败测试：

- 共享组件：卡片变体、状态图形、导航可访问性、当前项、44px 和安全区。
- Sidebar：认证页不显示导航；业务页显示三栏；客户上下文参数保留；真实资料字段正确；待迁移模块无假操作。
- Operation：无员工导航；真实进度数据渲染；任务卡状态；错误/OAuth 行为不回归。
- 完成门禁：12+10 路由不变、无直接 `fetch`、无 Dashboard 会话引用、无外部参考品牌素材、无假业务结果。
- Playwright：390×844 与 1280×900 打开全部 22 条路由及未知路由；检查固定导航、无内容遮挡、无横向溢出、console/pageerror/requestfailed/意外 4xx/5xx 为零。
- 视觉证据：对 Sidebar 客户页、Sidebar 首页/待迁移页、Operation 任务宝成功页及统一状态页生成截图并人工审阅层级、间距和文字可读性。

## 10. 完成边界

本次完成的是两个移动端的统一视觉基础、全部现有入口的产品化外观，以及 `/contact`、`/workFission` 两个真实纵切面的视觉升级。其余 20 个模块仍是明确待迁移状态；视觉完成不等于其业务列表、表单、回调或写操作已完成。
