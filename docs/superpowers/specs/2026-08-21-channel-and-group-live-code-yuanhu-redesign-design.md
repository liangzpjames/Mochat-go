# 渠道活码与群活码页面圆弧 AI 对齐设计

> 日期：2026-08-21
> 状态：待审阅
> 审阅范围：产品结构、交互、数据口径、技术边界与验收标准；本文件通过后再进入代码实施。

## 1. 背景与目标

MoChat 当前的“渠道活码”和“群活码”共用一个通用营销页面。页面能够请求部分现有接口，但仍存在以下关键问题：

- 页面结构与圆弧 AI 差异明显：大幅渐变头图、通用筛选器、通用详情抽屉占据了首屏空间；
- 渠道活码缺少创建人、使用员工、客户标签、有效期、好友统计等业务字段；
- 群活码没有区分“无限群活码”和“自建群活码”，把不同数据域混为一页；
- 本地数据中存在 `example.invalid` 二维码等模拟记录，无法作为真实业务结果展示；
- 当前“扫码入群人数”由群成员存量推算，不能证明客户由某个活码扫码并成功入群；
- 创建表单暴露员工 ID、群 ID 和 JSON，不能供业务人员直接操作。

本次优化的目标是：在不伪造业务数据的前提下，对齐圆弧 AI 的信息架构和主要交互，复用 MoChat 已有企微能力，补齐必要的查询、统计、分组、上传、导出和作废闭环。

## 2. 范围

### 2.1 本期包含

- `/acquisition/v2-channel-code` 渠道活码页面；
- `/acquisition/group-code` 群活码页面；
- 群活码的两种模式：
  - 无限群活码；
  - 自建群活码；
- 页面筛选、列表、分页、分组、创建/编辑、详情、统计、导出和作废；
- 与页面能力直接相关的后端字段、接口、数据库迁移、权限和审计；
- 真实数据来源治理、错误态、空态、加载态和宽屏适配；
- 单元测试、后端测试、浏览器验收与 Docker 交付验证。

### 2.2 本期不包含

- 重写已有企微客户联系、群聊和素材中心等基础领域；
- 把三个历史数据域合并成一套新表；
- 伪造扫码、加好友或入群统计来填充空页面；
- 对圆弧 AI 未展示的复杂海报编辑器进行像素级复刻；
- 修改短链、门店活码等其他营销菜单。

## 3. 调研结论

调研环境为圆弧 AI 当前在线界面，视口为 1280×720。参考环境列表无业务记录，因此列表字段、筛选和新增交互为已观察事实；无数据时不可见的行内操作不作为参考事实，需依据 MoChat 已有能力设计。

### 3.1 渠道活码

圆弧 AI 的页面由左侧分组栏和右侧工作区组成。右侧首行是紧凑筛选区，随后为操作按钮和数据表，不使用大型介绍头图。

已观察到的能力：

- 分组和关键词检索；
- 按活码名称、创建人、关联员工筛选；
- 添加活码、统计、刷新；
- 列表字段为二维码/名称、创建人/创建日期、使用人员/部门、客户标签、有效期、新增好友数；
- 批量导出、删除、分组；
- 新增向导为“基础设置 → 接待方式 → 设置海报”；
- 基础设置包含分组、名称、标签、客户备注、欢迎语、附件和有效期；
- 统计弹窗包含新增好友次数、流失好友次数、新增好友数、留存好友数、活码个数，并支持时间与名称筛选、导出。

### 3.2 无限群活码

已观察到的能力：

- 独立模式页签；
- 分组和关键词检索；
- 按名称、创建人和创建日期筛选；
- 添加群活码、刷新；
- 列表字段为二维码/名称、创建人/创建日期、扫码入群客户数、今日扫码入群；
- 批量导出和分组；
- 新增向导为“基础设置 → 设置海报”；
- 基础设置可选择最多 5 个群、设置满 200 人后自动建群、群名称和起始序号。

### 3.3 自建群活码

已观察到的能力：

- 独立模式页签；
- 名称筛选、查询和重置；
- 新增群活码、下载二维码；
- 列表字段为二维码、群活码名称、群活码类型、创建时间、扫码次数、关联活码数；
- 创建弹窗支持“企业微信群活码”和“自建群活码”两种承载方式；
- 自建模式支持名称、引导语、头像和多个群二维码上传；
- 上传说明限制最多 5 个群，每个群按 200 人容量组织。

## 4. 当前 MoChat 能力与缺口

| 业务面 | 可复用的真实能力 | 主要缺口 | 本期处理 |
| --- | --- | --- | --- |
| 渠道活码 | `channelCode` 列表、详情、创建、更新、联系人和单码统计；真实企微联系码创建 | 创建人、创建日期、员工/部门展示、有效期、聚合统计、导出、批量作废 | 扩展查询与生命周期字段，新增聚合统计、导出和作废能力 |
| 无限群活码 | `workRoomAutoPull` 创建、更新、详情、选员工/群、企微联系码和欢迎回调 | 页面分组、创建人/日期筛选、可靠扫码入群归因、导出；现有移动分组为空操作 | 新增群活码分组和事件账本，修复分组移动，列表只展示确认归因指标 |
| 自建群活码 | `roomInfinitePull` 创建、更新、删除、二维码轮换、素材存储和落地页 | 未接入当前群活码页、扫描仅有累计值、缺少分组/导出与细粒度权限 | 接入专用模式，复用上传和存储，新增扫描事件与权限资源 |
| 当前前端 | 通用 API 客户端、权限桥接、表格和表单基础组件 | 单页通用模型、原始 ID/JSON 输入、大头图、模拟记录直接展示 | 拆成专用工作区和业务表单，禁止前端构造或粉饰模拟数据 |

### 4.1 数据真实性规则

1. 二维码必须来自企微接口、文件上传存储或自建群活码落地页；前端不得生成业务记录或替换为“看起来真实”的地址。
2. `example.invalid`、`sim-*` 等历史模拟记录由迁移脚本按明确特征标记为 `simulation`，默认业务列表不展示；原记录保留以便审计，不在前端按 URL 临时过滤。
3. “扫码入群客户数”只统计能够关联到活码且收到成功入群事件的去重客户；当前群成员存量不能替代该指标。
4. 统计暂未接入或归因失败时显示“暂无可验证数据”或同步异常，不显示 `0` 冒充成功统计。
5. 创建人、员工、部门、标签等名称由服务端按当前企业和数据权限解析；前端不根据 ID 猜测名称。

## 5. 方案对比与选择

### 方案 A：仅修改前端外观

优点是交付快；缺点是无法补齐参考界面的真实字段，仍会保留错误的统计口径和原始 ID 表单。该方案不满足目标。

### 方案 B：双页面、三领域真实闭环（选定）

保留渠道活码、`workRoomAutoPull`、`roomInfinitePull` 三个已有数据域，共享视觉组件和查询适配层，不强行统一存储。只新增页面需要的生命周期、分组、事件和统计能力。

优点是能复用成熟的企微链路，数据迁移风险可控，页面语义也与圆弧 AI 对齐；代价是需要增加后端聚合接口和事件归因。

### 方案 C：新建统一活码领域并迁移所有历史数据

数据模型最整齐，但会扩大到企微配置、回调、落地页和历史统计的整体迁移，回归风险和周期均过高。本期不采用。

## 6. 总体架构

```text
渠道活码页 ── 专用前端适配器 ── channelCode 既有写链路
          └─ 查询/统计/导出/生命周期补充接口

群活码页 ─── mode=infinite ─── workRoomAutoPull 既有写链路
       └── mode=selfBuilt ─── roomInfinitePull 既有写链路
       └── 共享分组、事件归因、导出补充接口

企微回调 / 自建落地页 ── 活码事件账本 ── 去重统计与日统计
```

前端共享的只是分组栏、筛选区、表格外壳、分页和反馈组件；业务表单、列表字段和数据适配分别维护。后端继续以现有数据域作为写入事实源，新接口负责展示聚合，不通过内部 HTTP 调用旧接口。

## 7. 页面与交互设计

### 7.1 公共布局

- 保留系统全局导航和页面 banner，不再增加第二块大型渐变介绍卡；
- 页面内容卡与 banner 之间保持统一的 16px 间距，加载、空态、筛选和选择人员后不得跳变；
- 桌面端采用 224px 左侧分组栏和自适应主工作区；无分组的自建模式使用完整主工作区；
- 筛选项和主操作位于同一紧凑工具栏，次要操作收进“更多”；
- 表格横向空间优先给名称、人员和标签，多值内容折叠为前两项加数量；
- 分页固定在当前内容卡底部，不覆盖表格；
- 1280px 以下允许表格横向滚动，2560×1440 下内容利用可用宽度，不固定在窄列中央。

### 7.2 渠道活码页

#### 筛选与列表

- 左侧：分组树、当前分组数量、分组名称搜索、新建/重命名/删除分组；
- 筛选：活码名称、创建人、使用员工/部门、状态；
- 主操作：添加活码、统计；刷新按钮不展示，筛选、分页、创建成功和重试会触发明确的数据刷新；
- 表格：复选框、二维码/名称、创建人/创建日期、使用人员/部门、客户标签、有效期/状态、新增好友数、操作；
- 批量操作：导出、移动分组、作废；作废需要二次确认，并展示企微同步结果。

#### 新增与编辑

使用右侧抽屉或大对话框的三步向导：

1. 基础设置：分组、名称、客户标签、客户备注规则、欢迎语、附件；
2. 接待方式：自动通过、员工/部门、分流策略、备用员工；
3. 设置海报：用真实二维码生成预览，可选择原始二维码或 MoChat 固定品牌模板并下载。

有效期支持永久、7/15/30/90 天和自定义。有限有效期保存 `valid_from`、`valid_until`，到期任务调用企微联系码失效能力；企微同步失败时记录 `sync_failed` 并在列表提示，不得只在本地改状态。

#### 统计

统计对话框支持分组、日期范围和活码名称筛选。汇总卡展示新增好友次数、流失好友次数、新增好友数、留存好友数和活码数；下方列表按活码展示相同指标并可导出。所有指标沿用后端已有联系人状态变化口径，并在接口响应中返回口径说明和数据截至时间。

### 7.3 群活码页

顶部使用稳定页签，URL 参数 `mode=infinite|selfBuilt` 保存模式；切换页签时保留各自独立的筛选和页码，不把一类数据带入另一类。

#### 无限群活码

- 左侧分组栏；
- 筛选：名称、创建人、创建日期范围；
- 主操作：添加群活码；
- 表格：复选框、二维码/名称、创建人/创建日期、扫码入群客户数、今日扫码入群、状态、操作；
- 批量操作：导出、移动分组、作废；
- 新增向导：基础设置和海报预览；基础设置包含名称、接待员工、客户标签、引导语、按顺序选择最多 5 个群，以及满员后的建群策略。

“自动建群”只有在服务端具备明确的企微建群能力且验证成功时才开放；否则保留顺序切群并明确提示需要预先配置后续群，不能展示可点击但无效的开关。

#### 自建群活码

- 不展示无意义的左侧空分组栏；
- 筛选：名称、群活码类型、创建日期；
- 主操作：新增群活码、批量下载二维码；
- 表格：复选框、二维码、名称、类型、创建时间、扫码次数、关联二维码数、状态、操作；
- 创建表单复用 `roomInfinitePull`：名称、类型、引导语、头像、群二维码和单码上限；文件通过受控上传接口提交，前后端共同校验 JPG/PNG/JPEG 和 2MB 上限；
- 详情提供落地页链接、当前生效二维码顺序、各二维码容量和替换记录；作废使用软删除并保留审计。

### 7.4 反馈状态

- 首次加载：表格骨架，布局尺寸保持不变；
- 空数据：区分“当前企业无数据”“筛选无结果”“数据尚未同步”；
- 部分失败：保留已加载列表，在对应操作区展示可重试错误；
- 权限不足：隐藏无权按钮，直接访问写接口仍由服务端拒绝；
- 企微同步失败：记录本地业务操作和供应商错误，不把失败结果显示为已生效；
- 删除/作废/覆盖上传均需要确认，反馈精确到成功和失败记录。

## 8. 数据模型与接口边界

### 8.1 数据库增量

新增一组可回滚迁移，包含：

- 渠道活码生命周期字段：有效期类型、起止时间、业务状态、企微同步状态和失败原因；
- 群活码分组表，按企业隔离，并为无限群活码和自建群活码增加可空 `group_id`；
- 活码事件账本：企业、模式、活码、客户、群、事件类型、来源事件 ID、发生时间和原始关联键；
- 事件唯一索引，用来源事件 ID 保证回调幂等；
- 活码日统计索引；
- 页面查看、创建、编辑、统计、导出、移动分组、作废和上传等权限资源；
- 对确认的模拟记录增加 `data_source=simulation` 标识，默认查询排除但不物理删除。

### 8.2 查询契约

现有写接口继续承担真实创建和更新，新查询适配接口统一返回页面所需展示模型：

```ts
type LiveCodePage<T> = {
  items: T[];
  pagination: { page: number; perPage: number; total: number };
  asOf: string;
};

type ChannelCodeRow = {
  id: number;
  name: string;
  qrCodeUrl: string;
  group: { id: number; name: string } | null;
  creator: { id: number; name: string } | null;
  createdAt: string;
  employees: Array<{ id: number; name: string; departments: string[] }>;
  tags: Array<{ id: number; name: string }>;
  validity: { kind: "permanent" | "fixed"; from: string | null; until: string | null };
  state: "active" | "expired" | "invalidated" | "sync_failed";
  addedFriendCount: number | null;
};

type GroupCodeRow = {
  id: number;
  mode: "infinite" | "selfBuilt";
  name: string;
  qrCodeUrl: string;
  creator: { id: number; name: string } | null;
  createdAt: string;
  joinedCustomerCount: number | null;
  joinedTodayCount: number | null;
  scanCount: number | null;
  linkedCodeCount: number;
  state: "active" | "invalidated" | "sync_failed";
};
```

`number | null` 有明确含义：`0` 表示已接入统计且确实为零，`null` 表示没有可验证统计。前端必须分别渲染。

### 8.3 事件归因

- 无限群活码的联系码 `state` 先记录“扫码触达/添加员工”待归因事件；
- 客户成功进入目标群时，由群成员变更回调按企业、客户和最近有效待归因记录写入 `join_room`；
- 自建群活码落地页选择/展示二维码时记录 `scan`，使用请求 ID、会话令牌和时间窗去重；
- 无法关联到具体活码的群成员事件不计入活码入群数；
- 日统计从事件账本按企业时区 `Asia/Shanghai` 聚合，边界为本地自然日。

### 8.4 导出

导出复用当前筛选条件，由服务端重新查询数据并生成 UTF-8 BOM CSV，不导出前端当前页缓存。字段顺序与页面一致，并追加业务状态、数据截至时间和统计口径。导出受独立权限和企业数据范围约束。

## 9. URL、权限与审计

- 渠道活码 URL 状态：`groupId`、`name`、`creator`、`employeeId`、`state`、`page`；
- 群活码 URL 状态：`mode`、`groupId`、`name`、`creator`、`startDate`、`endDate`、`page`；
- 非法参数回退到默认值并使用替换历史，不制造浏览器返回死循环；
- 每个页面动作同时受前端能力判断和服务端 RBAC 校验；
- 创建、编辑、批量分组、导出、作废、企微同步失败与重试写入业务日志；
- 所有查询、写入和事件归因均强制按 `corp_id`/租户边界过滤。

## 10. 测试与验收

### 10.1 自动化测试

- 前端：模式切换、URL 恢复、筛选重置、分页、`null` 统计、权限按钮、创建向导、上传校验、批量操作和错误重试；
- 后端：企业隔离、筛选、分页、创建人解析、生命周期状态、回调幂等、入群归因、导出字段、部分失败和权限拒绝；
- 数据库：迁移升级/回滚、唯一索引、历史数据兼容和模拟数据标记；
- 样式契约：内容卡间距、无大头图、宽屏宽度、窄屏横向滚动和状态切换不跳变。

### 10.2 浏览器验收场景

1. 以 2560×1440、1440×900、1280×720 检查两页首屏布局；
2. 渠道活码按分组、名称、创建人、员工筛选并刷新 URL；
3. 新建渠道活码，确认真实二维码、员工、标签、欢迎语和有效期回显；
4. 打开统计，验证汇总与列表口径一致并导出 CSV；
5. 在群活码两种模式间切换，验证筛选和页码互不污染；
6. 创建无限群活码并验证最多 5 个群、顺序和真实企微同步反馈；
7. 创建自建群活码，验证文件类型/大小、二维码顺序、落地页和批量下载；
8. 对多条记录移动分组、作废，验证部分失败结果和审计记录；
9. 使用无统计数据、无权限、供应商失败和历史模拟记录验证异常路径；
10. Docker 重建后重复核心路径，确认不是仅由开发服务器缓存生效。

## 11. 发布与回滚

1. 先执行数据库迁移并发布兼容旧前端的后端；
2. 事件账本开始采集后再切换新统计口径，历史不可归因数据不回填为扫码入群；
3. 发布新前端，通过功能开关按企业启用新页面；
4. 完成浏览器验收后扩大启用范围；
5. 回滚前端时保留新增表和字段，不丢事件；后端回滚前先关闭新页面和回调写入；
6. 有限有效期任务或企微作废出现异常时停止任务并保留 `sync_failed` 待重试，不自动物理删除记录。

## 12. 已确定的产品决策

- 群活码同时覆盖无限群活码和自建群活码；
- 两种模式共用入口但使用独立数据模型和筛选状态；
- 页面不保留手动刷新按钮；
- 不展示大型二级介绍头图，不用摘要数字占据首屏；
- 真实统计缺失时显示未知态，不使用零值或存量推算冒充；
- 圆弧 AI 空列表中未观察到的行内操作，以 MoChat 已有能力和可审计闭环为准；
- 本轮先提交设计和实施文档供审阅，未经审阅不进入代码实施。
