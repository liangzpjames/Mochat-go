# 客户会话按钮样式与文案优化设计

## 1. 背景与目标

当前 `/chat/v2-customer` 已完成客户列表、关联会话和消息详情的三栏工作台，但操作按钮仍存在三类问题：

- 搜索、刷新、关注等动作视觉层级相同，按钮偏重，和圆弧 AI 参考页的轻量操作区不一致。
- “查询”“刷新”等文案在不同区域重复，用户难以快速判断作用范围。
- 操作状态、键盘焦点和无障碍名称不够统一。

本次只优化客户会话页面的按钮表达，不改变 API、URL 参数、权限、数据口径或业务行为。

## 2. 设计方案

### 2.1 文案映射

| 现有位置 | 现有文案 | 新文案 | 语义 |
| --- | --- | --- | --- |
| 客户搜索提交 | 查询 | 搜索 | 提交客户名称关键词 |
| 客户目录刷新 | 刷新 | 刷新客户 | 重新获取客户目录 |
| 关联会话刷新 | 刷新 | 刷新会话 | 重新获取当前客户的关联会话 |
| 消息详情刷新 | 刷新 | 刷新详情 | 重新获取当前会话详情 |
| 关注切换 | 重点关注 / 取消关注 | 关注客户 / 已关注 | 切换当前客户的关注状态 |
| 消息历史 | 加载更早消息 | 加载更早 | 加载当前会话更早的消息 |
| 消息搜索提交 | 查询 | 搜索 | 提交消息内容关键词 |

无障碍 `aria-label` 会继续提供完整作用域，例如“搜索客户”“刷新客户”“刷新会话”“刷新详情”“关注客户”。

### 2.2 视觉层级

- 使用统一的 `customer-conversation-action-button` 样式：约 32px 高、浅色背景、细边框、7px 圆角、紧凑内边距。
- 搜索提交使用蓝色主操作色；刷新、关注和历史加载使用浅底次要按钮；关注成功状态使用蓝色浅底和“已关注”文案。
- 操作按钮加入内联 SVG 图标，图标只增强识别，不承载唯一语义；窄宽度下允许隐藏图标文字以外的装饰，不改变可读文案。
- 保留 hover、focus-visible、disabled 和 loading 状态，禁用时保持当前请求中的“搜索中/刷新中/加载中…”反馈。
- 分页箭头继续保留“上一页/下一页”的 aria 名称，视觉统一为浅底圆角按钮，不更改页码和 URL 行为。

## 3. 组件与数据流

只调整以下已有组件的按钮标记和样式类：

- `customer-conversation-directory.tsx`：客户搜索与目录刷新。
- `customer-conversation-list.tsx`：关联会话刷新。
- `customer-conversation-detail.tsx`：详情刷新、关注切换、消息搜索、历史加载。
- `dashboard-pagination` 的客户页面样式覆盖：分页按钮视觉，不改通用组件接口。
- `index.css`：客户会话专用按钮样式和响应式规则。

所有按钮仍调用现有回调；列表、详情、关注状态和加载状态均继续来自现有 React Query 数据与 URL 状态，不新增前端业务常量。

## 4. 测试与验收

先新增失败测试，再实现：

1. 组件测试断言新文案、作用域 aria-label、加载/禁用文本和关注切换文本。
2. 样式契约测试断言按钮统一类、主次色、focus-visible 和分页规则。
3. 运行客户会话定向 Vitest，随后运行 Dashboard 全量测试、typecheck 和 build。
4. 在真实登录态浏览器中验证：客户搜索、客户刷新、关联会话刷新、详情刷新、关注切换、消息搜索、加载更早消息和分页；确认 URL、请求结果和错误告警没有回归。

## 5. 非目标

- 不修改左侧目录、三栏布局、导航菜单或顶部 banner。
- 不新增下载、导出或后端接口能力。
- 不替换圆弧 AI 的业务文案、数字或客户数据。
