# 企业微信会话内容存档真实试用与产品化设计

日期：2026-08-26

状态：待用户审阅

适用范围：MoChat Go 当前测试企业、服务器 `139.196.34.133`、企业微信“管理工具 → 会话内容存档”一个月试用

## 1. 背景与已确认事实

用户当前具备一个已认证企业，并可登录企业微信管理后台。该企业暂时没有与企业主体相同或具有关联关系的域名，因此自建应用的可信域名、网页授权和标准客户联系 API 接入仍受外部条件限制。

会话内容存档是独立能力。2026-08-26 的企业微信后台截图已经确认：

- “会话内容存档”页面允许单独配置接收事件服务器、可信 IP、消息加密公钥、Secret 和开启范围；
- 当前接收事件服务器已经保存为 `http://139.196.34.133/weWork/callback?cid=4`；
- 当前可信 IP 已经保存为 `139.196.34.133`；
- 服务版和企业版试用开启范围当前各为 2 人；
- 页面仍显示“设置消息加密公钥”和“立即开启”，因此不能视为已经完成真实开通；
- 页面可以查看或重新获取会话内容存档 Secret，但 Secret 不得出现在聊天、文档、命令行参数、日志、截图或 Git 中。

仓库与服务器当前已有两条相关链路：

1. 主应用 `GET/POST /weWork/callback?cid=<mc_corp.id>`：支持企业微信通用回调的 URL 验证、签名校验、AES 解密和 Redis 队列投递；`event.msgaudit_notify` 能被解析，但现有 worker 对该事件没有业务处理，只会成功确认。
2. 隔离 `wecom-archive-demo`：已在服务器部署企业微信官方 Finance SDK v3，具备 `GetChatData`、RSA 解密、`DecryptData`、seq 状态和 JSONL 证据能力；它使用独立的 `/wecom/callback`，尚未录入真实企业 CorpID、会话存档 Secret，也未取得真实消息证据。

因此，后台“已经保存接收事件 URL”只证明地址曾通过保存或验证，不证明真实消息已被拉取、解密、幂等保存或能在 Dashboard 中回读。

## 2. 目标与非目标

### 2.1 本轮目标

1. 在不把敏感信息写入任何持久化可见渠道的前提下，完成会话内容存档一个月试用的真实配置。
2. 证明当前企业至少一条受控真实消息可由官方 Finance SDK 拉取并解密。
3. 证明 `msgaudit_notify` 事件可到达服务器，并能作为主动拉取的加速信号。
4. 验证 seq 单调推进、重复拉取幂等、进程重启续拉、五日窗口和错误映射。
5. 明确主程序现有缺口，形成可以进入实施计划的最小产品化方案。

### 2.2 本轮非目标

- 不把标准通讯录、客户、客户群 API 的域名阻断误记为已解决。
- 不把隔离 Demo 的 JSONL 结果冒充主程序 MySQL、Dashboard 或 Sidebar 已接通。
- 不在真实会话上启用 AI 自动分析，也不把真实消息外发给模型。
- 不执行破坏性数据迁移，不覆盖现有生产数据库、命名卷或用户工作树。
- 不把测试范围扩展为正式购买、正式生产合规上线或全部三端业务验收。

## 3. 推荐方案

采用“现有主回调接收事件 + 隔离官方 SDK 主动拉取 + 定时轮询兜底”的双轨方案。

### 3.1 测试期

- 暂不修改企业微信后台已经保存的 URL：`http://139.196.34.133/weWork/callback?cid=4`。
- 在任何真实事件测试前，先只读核验 `mc_corp.id=4` 是否正好对应本次测试企业的 CorpID；若不对应，停止测试并生成正确的 `cid` URL，不能让真实事件进入其他租户。
- 核验当前线上容器确实接管 `/weWork/callback`、对应 Token/AES 配置有效且 `wework-callback` worker 正常运行。
- 为 `event.msgaudit_notify` 增加显式、可观测、幂等的处理：只投递“需要拉取”的内部任务，不在 HTTP 回调请求内执行 Finance SDK。
- 真实消息正文仍由隔离 Demo 的官方 Finance SDK 主动拉取。回调只通知“有新消息”，不会携带会话正文。
- 即使没有收到事件，仍保留低频定时拉取，防止通知丢失或 15 秒合并窗口造成遗漏。

### 3.2 生产化方向

- 将隔离 Demo 收敛为受控的 `archive-bridge`，仅向主应用提供本机或受认证的内部接口。
- 主程序负责租户隔离、任务账本、游标、幂等落库、权限和页面状态；bridge 只负责官方 C SDK 生命周期、拉取、解密和媒体分片。
- 事件触发与定时轮询共用同一条拉取任务和同一个 seq 检查点，不能维护两套游标。
- 生产入口应迁移到 HTTPS 和稳定域名；当前 HTTP + IP 只作为明确标注的试用条件，不作为正式上线标准。

## 4. 回调链路设计

### 4.1 企业微信侧事件

当开启范围内的成员收到或发送新消息时，企业微信最多按约 15 秒窗口合并推送 `msgaudit_notify`。事件仅表示“可能有新会话内容”，正文必须通过 Finance SDK 的 `GetChatData` 拉取。

### 4.2 服务端处理

1. `/weWork/callback?cid=4` 完成签名校验、AES 解密和 CorpID/租户绑定校验。
2. 对 `event.msgaudit_notify` 生成不含正文和凭据的任务：`tenant_id`、`corp_id`、事件时间、幂等键、接收时间。
3. HTTP 请求快速返回 `200 success`，不等待 SDK 拉取。
4. worker 使用 Redis `SET NX EX` 或现有队列幂等信封，在短窗口内合并重复通知。
5. worker 触发与定时任务相同的增量拉取，读取数据库中的当前 seq，从 `seq+1` 开始获取。
6. 成功保存一页后再推进游标；任何拉取、解密或写入失败均不得推进游标。

### 4.3 URL 决策

本轮默认保留：

```text
http://139.196.34.133/weWork/callback?cid=4
```

只有以下任一条件不满足时才修改：

- `cid=4` 与当前测试企业一一对应；
- 该路径由当前线上 MoChat Go 处理，而不是过期 PHP 或其他容器；
- 当前企业保存的回调 Token 和 EncodingAESKey 与 `cid=4` 的加密凭据一致；
- 公网请求经过反向代理后查询参数和请求体保持完整；
- 真实 `msgaudit_notify` 可在回调证据或任务账本中查到。

若不满足，应先修复绑定或反向代理，再由 MoChat 企业配置页面重新生成正确 URL。不得为了方便把 `cid` 去掉，也不得使用其他企业的内部编号。

## 5. 敏感信息交接与职责边界

### 5.1 用户完成的操作

1. 在企业微信会话内容存档页面选择 2 名明确的测试成员。
2. 将 MoChat 生成的 RSA 2048 公钥粘贴到“设置消息加密公钥”；私钥不离开服务器安全目录。
3. 在 Codex 打开的 SSH 交互终端中，由用户亲自输入服务器登录口令、企业 CorpID 和会话内容存档 Secret；终端脚本必须使用隐藏输入。
4. 确认开启一个月试用并点击“立即开启”。
5. 使用测试成员和一个明确知情的测试客户/测试群发送受控标记消息。

### 5.2 Codex 完成的操作

1. 检查 Git、镜像、容器、数据库、反向代理和回调绑定，创建可验证回滚点。
2. 生成 RSA 密钥对和配置模板，确保私钥及 Secret 文件权限最小化。
3. 完成服务器配置、容器重启、健康检查和 SDK 拉取。
4. 收集脱敏的事件、拉取、解密、seq、幂等和重启证据。
5. 发现部署阻断或明显回归时，只做最小必要修复并复验。

### 5.3 禁止事项

- Secret、私钥、SSH 口令、回调 Token、EncodingAESKey 不进入聊天、Git、文档、命令参数、进程列表、日志或截图。
- 不让用户把任何 Secret 发到 Codex 对话。
- 不在浏览器前端保存或回显完整凭据。
- 不把真实消息正文放入普通应用日志；验收证据默认只保存消息 ID、类型、时间、方向、seq、哈希和脱敏摘要。

## 6. 真实测试用例

所有消息使用无个人隐私、无真实业务信息的唯一标记，例如 `MOCHAT-ARCHIVE-20260826-A01`。

### 6.1 最小必测

1. 开启范围内两名员工之间双向文本。
2. 开启范围内员工与知情测试客户之间双向文本；分别记录客户同意和未同意时的边界。
3. 含开启范围员工的客户群文本；确认群类型和成员范围满足企业微信存档条件。
4. 发送完成后等待至少一个 15 秒通知窗口，验证真实 `msgaudit_notify`。
5. 执行主动拉取，确认标记消息可解密且发送方、接收方、时间和类型正确。

### 6.2 扩展验证

- 一张测试图片和一个小文件，用于暴露 `GetMediaData` 尚未产品化的缺口。
- 在不新增消息的情况下重复拉取，确认不重复保存。
- 重启 archive Demo 后继续拉取，确认 seq 从持久化状态续接。
- 在允许范围内临时使用错误 IP/错误凭据的可控故障注入仅限隔离环境；生产配置不做破坏性试验。
- 客户撤回同意或不在开启范围时，只记录真实缺失原因，不伪造可拉取结果。

## 7. 验收标准

### 7.1 回调验收

- `cid=4` 被证明属于当前测试企业。
- 收到至少一个真实 `event.msgaudit_notify`。
- 回调返回 HTTP 200，且处理耗时不依赖 SDK 拉取。
- 重复事件被合并或幂等处理，不造成拉取风暴。
- 事件证据不包含消息正文和敏感凭据。

### 7.2 SDK 拉取验收

- 官方 Finance SDK 正常加载，且服务器出口 IP 在企业微信可信 IP 中。
- 至少一条受控真实文本通过 `GetChatData` 返回并成功解密。
- `publickey_ver` 能找到对应私钥版本。
- seq 单调推进；失败不推进；重复拉取不产生重复消息。
- 进程重启后可从已提交 seq 继续。
- 明确记录媒体是否成功；未完成 `GetMediaData` 时必须标记为 `LIMITED`。

### 7.3 产品边界验收

- Demo 证据与主程序落库、Dashboard 回读明确分栏。
- 在主程序 `Archive.Fetch` 仍为 fail-closed 时，状态继续显示 `LIMITED`，不能宣称生产可用。
- AI 自动分析保持关闭。
- 标准员工、客户、客户群 API 仍按域名外部阻断单独记录。

## 8. 错误处理与诊断

需要把企业微信错误码映射为用户可执行提示，至少覆盖：

- 可信 IP 不匹配：展示服务器实测出口 IP、后台配置 IP 和发生时间，不展示 Secret。
- 服务未开启或试用过期：提示检查“立即开启”、开启范围和试用期限。
- 拉取窗口超出五日：停止追赶并报告不可恢复的数据窗口，不能跳过后伪装完整。
- 调用频率过高：指数退避，并由回调合并和定时任务避免高频空轮询。
- RSA 版本不匹配：保留版本化私钥 keyring，提示缺失的 `publickey_ver`。
- 无消息：区分“确实没有新 seq”“员工不在开启范围”“客户未同意”“群不符合范围”和“配置错误”。
- 回调成功但拉取失败：分别显示事件最后到达时间和 SDK 最后成功时间，避免把两个状态混成一个绿灯。

## 9. 产品化缺口与最小改造

### 9.1 P0：真实试用闭环

- 增加 `msgaudit_notify` 的显式 handler 和测试。
- 建立回调到 archive pull 的内部任务，不在 HTTP 请求内拉取。
- 增加每企业 seq 状态、拉取次数、最后成功/错误和脱敏证据。
- Dashboard 企业配置页面增加“事件服务器已验证”“可信 IP”“公钥版本”“试用状态”“开启范围”“最近通知”“最近拉取”的分项状态。
- 对 `cid` 绑定增加醒目说明：它是 MoChat 内部企业记录 ID，只用于生成回调 URL，不是租户登录账号、CorpID 或 Secret。

### 9.2 P1：主程序落库与回读

- 将隔离 Demo 提炼成 `archive-bridge`，主程序 `Archive.Fetch` 接入真实 source。
- 复用现有 archive provider、0138 任务账本和消息表，按 `msgid`/seq 幂等写入。
- Dashboard 会话页面只能展示真实已落库数据，并显示来源、同步时间和授权边界。
- 媒体通过独立 worker 分片下载、校验、存储和记账，失败不阻塞文本游标，但保留可重试状态。

### 9.3 P2：正式上线

- 申请并备案与企业主体一致或具有合法关联关系的域名，启用 HTTPS。
- 完成隐私告知、客户同意、访问审计、最小权限、保留期限、删除流程和密钥轮换。
- 为每个企业隔离 Secret、RSA keyring、游标、任务和数据权限。
- 建立监控：回调延迟、最后事件、最后拉取、seq 停滞、解密失败、媒体积压和试用/服务到期。

## 10. 数据、备份与回滚

### 10.1 变更前

- 记录权威 Git SHA、部署镜像摘要、容器配置和反向代理配置。
- 备份现有 archive Demo 配置、状态和证据目录，检查备份可读。
- 若涉及主数据库迁移，先做数据库备份并验证可恢复；本轮 SDK 级试用默认不写主 MySQL。

### 10.2 回滚

1. 停止新 archive pull 任务，保留现有证据和 seq 状态。
2. 恢复前一镜像和容器配置。
3. 若新增回调 handler 出现问题，关闭对应 feature flag，让通用事件 worker 恢复原行为。
4. 企业微信后台 URL 默认保持原值；只有该 URL 被证明错误时才恢复经截图记录的上一配置。
5. 不删除命名卷、生产数据库或密钥备份；真实测试消息的后续删除按合规保留策略处理。

## 11. 实施门禁

进入实施计划前，用户需要确认本设计，尤其确认以下三点：

1. 本轮先完成“真实 SDK 试用闭环”，不把它描述为正式生产上线。
2. 暂时保留 `http://139.196.34.133/weWork/callback?cid=4`，先核验绑定再决定是否修改。
3. 所有敏感值只由用户在交互式终端隐藏输入，Codex 不接收明文。

设计获批后，下一步应编写逐命令、逐测试、逐回滚点的中文实施计划，再进入代码修改、服务器配置和真实验收。
