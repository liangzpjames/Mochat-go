# SaaS 新客户默认企业修复设计

## 背景与根因

SaaS 控制台创建客户时，当前开户事务只创建租户、超级管理员、角色、菜单授权和套餐订阅，不创建 `mc_corp` 企业记录。Dashboard 登录虽然成功，但超级管理员按租户查询企业时得到空列表，因此只能看到“暂无可用企业”。

同时，当前“标准版”套餐及其租户套餐快照的 `maxCorps` 为 `0`，与“客户开户后可进入 Dashboard 基础界面”的验收目标冲突。

## 目标

- 新客户开户成功后，在同一事务内自动拥有一个可用的 Fake 企业。
- 新建超级管理员可以直接访问该企业；沿用现有“超级管理员可访问租户全部企业”的授权规则，不额外制造员工绑定数据。
- “标准版”套餐至少允许一个企业。
- 对已经开户但没有企业的非平台租户自动补齐，包含当前“测试”客户。
- 所有操作幂等，重复执行开户或迁移不会创建重复企业。

## 方案

### 新客户

在 `ProvisionSaaSAdminTenant` 的事务中增加默认企业保障函数。函数先按租户查询有效企业；若已存在则不操作，若不存在则创建：

- 企业名称：`<租户名称>演示企业`
- 企业微信 ID：`fake_tenant_<租户ID>`
- 企微密钥、回调信息：空值
- 租户 ID：当前新租户 ID

企业微信 ID 使用租户 ID 生成，便于识别且跨租户唯一。

### 已有客户

新增 `0099_saas_tenant_default_corp` 数据库迁移：

- 将启用中的“标准版”套餐 `max_corps` 从小于 1 调整到 1。
- 将使用标准版且 `limits_json.maxCorps` 小于 1 的租户套餐快照调整到 1。
- 为所有启用、非平台、当前没有有效企业的租户创建默认 Fake 企业。

回滚只回退套餐额度，不删除已经产生业务关联可能性的企业，避免破坏数据。

### Dashboard 行为

不修改 Dashboard 企业选择逻辑。现有超级管理员按 `tenant_id` 获取全部企业，且只有一个企业时前端会自动选中；补齐企业后即可沿用现有逻辑进入正常界面。

## 验证

- 先增加失败测试，证明迁移版本、Compose 新库挂载和默认企业 SQL 尚不存在。
- 增加开户默认企业参数生成的单元测试。
- 执行 Go 单元测试、迁移发现测试和构建。
- 重新部署 `mochat-go-desktop`，执行迁移，查询当前客户的套餐额度和企业记录。
- 在浏览器中使用 Dashboard 登录路径验证企业可见、自动选中和基础页面展示。
