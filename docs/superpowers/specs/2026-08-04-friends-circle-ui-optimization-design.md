# 朋友圈页面交互与样式优化设计

## 目标

在不修改朋友圈 Provider、HTTP 合同和安全边界的前提下，提升 `/acquisition/friends-circle` 的桌面端可读性、任务/素材切换体验，以及新增草稿右侧抽屉的完整度。

## 页面设计

- 顶部保留标题、Provider 状态和主操作，缩短说明文案并将“发布 Provider 未配置”改为轻量安全提示条。
- 任务与素材标签显示各自语义；筛选区仅展示当前类型真正可用的关键字字段，查询支持 Enter，重置仅在有筛选内容时启用。
- 列表使用状态徽标、内容摘要和更明确的操作列；任务展示发送方式、完成情况，素材展示类型与内容摘要。
- 空状态直接提供创建入口；查询刷新期间保留现有内容并显示按钮状态。

## 右侧抽屉设计

- 使用朋友圈专属抽屉样式，固定头部与底部，正文独立滚动；桌面宽度 520px，窄屏占满。
- 头部展示任务/素材类型、用途说明和图形化关闭按钮；点击遮罩、关闭按钮或 Escape 均可关闭。
- 表单提供名称、内容、字数统计、必填提示和类型说明；保存按钮固定在底部。
- 有未保存内容时关闭需二次确认；保存中禁止重复提交，保存失败保留输入并显示错误。

## 验收

- 自动化覆盖 Enter 查询、清空重置、抽屉打开、Escape 关闭、未保存确认、字数统计、任务和素材写入。
- 浏览器验证任务标签、素材标签、右侧抽屉、保存后刷新持久化和桌面端视觉效果。
- 正式发布和导出继续禁用，Manifest 仍为 `backend=partial`。

## 自审

- 无占位项；未扩大到企业微信发布、审批、上传或导出。
- 页面与抽屉行为均可通过现有 `BusinessWorkbenchApi` 完成。
- 未把本地草稿保存描述为正式发布成功。
