# Mochat 员工移动端紧凑化与本地验收入口设计

> 日期：2026-08-22<br>
> 状态：待用户审阅<br>
> 适用范围：`web/apps/sidebar`、Sidebar 专项 E2E/验收脚本，以及独立部署时公开 URL 的必要配置；不改变 Operation、Dashboard、SaaS Admin 或真实企业微信鉴权语义。

## 1. 背景与目标

首轮员工移动端已经完成 12 条路由、真实 API 状态、移动安全区和多尺寸验收，但人工查看发现两个问题：

1. 首页 Hero、入口卡片和业务分区卡片同时采用较大的内边距、圆角与间距，360px 宽度下首屏信息密度偏低；
2. 现有 Docker 验收地址只能打开公开登录页。点击“继续授权”后，后端把浏览器重定向到容器内部推导出的 `127.0.0.1:8081`，而主机映射端口为 `28081`；即使纠正端口，示例 `agentId=1` 也不存在，只会得到“应用不存在”，无法供用户逐页检查 UI。

本轮目标是提供“轻量紧凑”的员工移动布局，并提供一个明确属于开发验收、可点击、可逐页操作的本地入口。验收入口不得成为生产鉴权后门，也不得把测试夹具伪装成真实业务数据。

## 2. 已确认方案与取舍

用户已确认采用以下组合方案：

- **视觉方案：轻量紧凑。** 保留现有信息架构和页面分区，只收紧空间、圆角、首屏 Hero 与说明文字，不改成密集表格，也不移除业务状态。
- **验收方案：独立本地 Review Server。** 复用 Sidebar production build 和现有专项 E2E 固定夹具，在 `web/e2e` 提供仅绑定 `127.0.0.1` 的本地验收服务。它模拟授权回调和 Sidebar API，但不进入生产二进制、生产 Compose 服务或生产前端运行分支。
- **部署修正：显式公开 URL。** 独立 Compose 接受并传递公开 API/Sidebar URL，避免把容器监听端口误当成浏览器可达端口；真实 OAuth 仍要求有效企业微信应用和可信域名。

未采用的方案：

- 把所有首页入口改成无说明的图标列表：密度更高，但变化过大，不符合“稍微优化”；
- 在生产 Sidebar 中增加 query 参数绕过登录：实现简单但破坏鉴权边界，禁止采用；
- 向本地数据库写入伪造企业微信应用凭证：会混淆真实持久化数据与验收数据，禁止采用。

## 3. 紧凑视觉规范

### 3.1 全局节奏

| 项目 | 当前典型值 | 目标值 | 约束 |
| --- | --- | --- | --- |
| 页面横向留白 | 16–20px | 12–16px | 320px 窄屏仍不贴边 |
| 业务栈间距 | 16px | 10–12px | 不合并独立错误边界 |
| 舒适卡片内边距 | 16px 左右 | 12px | 表单字段仍有清晰分组 |
| 主卡片圆角 | 14–16px | 12px | 状态 Chip 保留胶囊形态 |
| 卡内标题下间距 | 12px | 8px | 正文行高不低于 1.4 |
| 首页 Hero | 当前首屏约 154px 高 | 缩减约 25% | 保留身份提示和主行动语义 |

所有按钮、链接式按钮、选择器和复选区域继续满足至少 44×44px 触控目标。紧凑化只减少装饰性留白，不压缩可操作热区。

### 3.2 首页

- Hero 降低上下留白和标题字号级差，保留“企业微信工作台”和“从当前客户会话开始工作”。
- 八个业务入口继续两列排列；图标尺寸略收小，标题保持醒目，说明最多两行并使用稳定截断。
- 缩小卡间距后，360×800 首屏应完整看到至少三行入口以及第四行的起始内容，底部导航不得遮挡。

### 3.3 客户详情与写入页面

- 客户身份摘要、三项快捷操作、概览/轨迹/画像/SOP 继续保持独立层级。
- 摘要头像、标题与编号缩小无效空白；字段行采用 10–12px 纵向节奏和细分隔线。
- 备注、标签、画像表单收紧卡片外框，但输入框、按钮和键盘避让尺寸不变。

### 3.4 素材、SOP 与批量任务

- 素材筛选卡、素材项、SOP 内容块、批量筛选和联系人项统一收紧到 10–12px 间距。
- 操作按钮仍保持 44px 高；素材预览和长名称不得造成横向溢出。
- 空态、错误态和加载态卡片可减少外围留白，但不能弱化说明和重试按钮。

## 4. 本地 Review Server

### 4.1 边界

Review Server 位于 `web/e2e`，默认监听 `127.0.0.1:28083`，只用于本机人工验收：

- 静态文件来自 `@mochat/sidebar` 的 production build；
- 数据来自现有 `sidebar-employee-mobile.spec.ts` 已明确标注的固定夹具；
- 页面顶部显示“本地验收数据 · 重启后重置”，避免被误认为生产数据；
- 不连接真实企业微信，不发送真实消息、不调用外部联系人能力；相关按钮显示现有诚实不可用反馈；
- 进程退出后所有写入状态消失，不修改 MySQL、Redis 或任何 Docker 命名卷；
- 服务只监听 loopback，并拒绝非本机 Host、未知 API 和未携带固定验收令牌的业务请求。

### 4.2 授权与路由

- `/sidebar-app/login?agentId=7&target=/` 展示真实登录 UI；点击“继续授权”请求 Review Server 自己的 `/sidebar/agent/auth`。
- Review Server 只接受固定 `agentId=7` 和安全内部 `target`，随后重定向到现有 `/sidebar-app/auth` 回调页面；回调由生产前端现有逻辑写入本地 cookie。
- 进入首页后，用户可通过真实导航检查各页面；另提供一个仅由 Review Server 注入的“验收路由”下拉入口，覆盖全部 12 条路由。
- `/auth`、`/codeAuth` 等安全页面仍展示各自语义；不把错误回调伪装成成功。

### 4.3 数据与写入行为

- 客户、标签、画像、素材、个人 SOP、群 SOP 和批量任务的数据结构与专项 E2E 保持同源。
- 备注、标签、画像和群 SOP 写入更新 Review Server 进程内的验收状态，刷新后可回读；服务重启后恢复初始夹具。
- 每个响应携带明确的验收 request ID；未知 URL 返回 404/500，不随机成功。

## 5. Docker 公开 URL 修正

`deploy/standalone/docker-compose.yml` 显式传入：

- `MOCHAT_API_BASE_URL`：浏览器/企微可回调的 API 公网地址；
- `MOCHAT_SIDEBAR_BASE_URL`：浏览器可访问的 Sidebar 地址；
- `MOCHAT_OPERATION_BASE_URL`：浏览器可访问的 Operation 地址。

本地默认值与端口映射一致，部署者可用现有环境变量覆盖为 HTTPS 域名。该修正只保证生成的地址可达，不为不存在的 `agentId` 伪造授权结果。

## 6. 测试与验收标准

实施必须按测试先行完成：

1. 为紧凑样式增加可测量的密度契约，先证明当前 Hero、卡片间距或卡片高度超出目标；
2. 为 Review Server 增加 Node 测试，覆盖 loopback 绑定、Host 拒绝、安全 target、固定 agent、认证令牌、未知 API、写入后回读和重启重置；
3. 为 Compose 增加配置渲染测试，断言公开端口不会再回落到容器内部 `8081/8082`；
4. 完成后重新运行 Sidebar 全部测试、typecheck、lint、build，移动基础门禁和相关 E2E；
5. 在 320×568、360×800、390×844、430×932 和 844×390 下检查：首页密度、长文本、触控面积、横向溢出、固定导航、安全区和键盘遮挡；
6. Review Server 地址必须可由普通本地浏览器点击，登录按钮能进入首页，12 路由均可达；控制台、未处理 Promise 和意外 4xx/5xx 为零；
7. 生产 Docker 地址仍保持真实鉴权：不存在应用返回“应用不存在”，不允许被 Review Server 夹具影响。

## 7. 兼容、迁移与回滚

- 不修改数据库 schema，不迁移业务数据。
- CSS 调整集中在 Sidebar 样式与必要的 Sidebar 页面 class，不把 Sidebar 密度规则泄漏到 Operation。
- Review Server 是新增开发工具，可单独回滚；删除该工具不会影响生产 Sidebar。
- Compose 公开 URL 可通过环境变量恢复原行为；若部署已显式配置域名，本次变更不覆盖它。
- 视觉改动使用独立原子提交，出现回归时可单独回滚到本轮开始提交 `32ef7f8`。

## 8. 非目标

- 不提供真实企业微信凭证、可信域名或会话上下文；
- 不绕过生产鉴权，不让固定验收令牌进入生产 Go 服务；
- 不修改 Operation、Dashboard、SaaS Admin、Phase 7 或会话存档；
- 不借紧凑化重写业务信息架构，也不删除加载、空态、错误和不可用反馈。
