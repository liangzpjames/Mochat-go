# AI 设置菜单整体优化设计

## 1. 目标与决策

本设计优化 Dashboard“AI 设置”菜单下全部实际页面，范围以仓库菜单、路由、权限目录、HTTP 注册、数据库表和参考产品实测为准。实际范围严格为：

- `/ai-setting/ai-knowledge-base`：AI 知识库；
- `/ai-setting/agent`：智能体管理。

“AI 设置”本身是可折叠菜单分组，不是独立路由。没有代码与权限资源支撑的“知识文档”“模型配置”“提示词编排”“工具市场”不纳入本轮，也不以静态数据伪装。

本轮采用“合同加固 + 真实能力边界 + 两页完整交互”方案：保留现有知识库、智能体元数据 CRUD 兼容链路，修复状态、引用、租户、错误和审计问题；前端补齐查询、状态筛选、固定分页、URL 恢复、完整反馈和响应式布局。不会扩展 Phase 7 会话存档，也不会把未接入的文档上传、向量索引、模型调用或智能体发布描述成可用能力。

未采用的方案：

1. 仅调整颜色、卡片和间距：改动小，但会保留停用失效、跨企业引用和“启用即能运行”的错误产品语义。
2. 一次实现文档解析、向量库、模型、提示词、工具、发布与调试：可形成完整 AI 平台，但明显扩大本任务和 Provider 范围，且无法在现有合同上诚实闭环。

## 2. 现状

### 2.1 前端与路由

菜单和路由来自 `web/apps/dashboard/src/benchmark/manifest.json`，两页由 `page-registry.tsx` 注册并通过 `main.tsx` 注入 `createAISettingsApi`。侧栏根据 `/access/profile` 返回的有效页面权限过滤；两页均无权限时整个“AI 设置”分组隐藏。

当前两页一次性加载完整数组，只提供新建、编辑和删除：

- 无关键词查询、状态筛选、分页和 URL 状态；
- 删除失败没有页面反馈或进行中保护；
- 智能体页把知识库加载失败误显示成“暂无知识库”；
- 关联列只显示 ID 数量，不显示实际名称或失效引用；
- 知识库“文档数”由用户手工填写，不来自文档、对象存储或索引链路；
- “启用”容易被理解成已可被 AI Provider 消费，但当前两张表没有任何运行时消费者。

### 2.2 后端、存储与权限

真实 API 为：

| 页面 | 方法与路径 | 存储 |
|---|---|---|
| AI 知识库 | `GET/POST /dashboard/ai-settings/knowledge-bases`；`PUT/DELETE /dashboard/ai-settings/knowledge-bases/{id}` | `mochat_go_ai_knowledge_bases` |
| 智能体管理 | `GET/POST /dashboard/ai-settings/agents`；`PUT/DELETE /dashboard/ai-settings/agents/{id}` | `mochat_go_ai_agents` |

所有 SQL 均以登录 principal 的 `tenant_id + corp_id` 限定，客户端 `corpId` 不决定数据范围。现存关键缺口：

- `status=0` 会被 `intStatus` 强制转换为 `1`，停用无法持久化；
- 智能体的 `knowledge_base_ids` 未验证是否属于当前租户/企业，删除知识库也不检查引用；
- 删除未记录操作者，CRUD 没有业务审计记录；
- 存储错误原文直接返回，可能暴露数据库实现；
- 智能体页面权限没有知识库 GET 资源，单独授权智能体页时会出现 403 依赖断链；
- 页面权限目前按仓库既有模型授予整个页面 CRUD，不提供独立只读动作权限。

### 2.3 基线

实现前基线为 Dashboard `137` 个测试文件、`779` 个用例通过；`internal/dashboard`、`internal/store`、`internal/server`、`internal/migration` 测试通过。视觉与交互以仓库已验收的 Dashboard 壳层、筛选区、数据卡片、表格、抽屉、分页、反馈及宽屏契约为基准，不改主导航和顶部栏。

## 3. 圆弧 AI 调研结论

已在登录态从 `https://web-ai-analysis-work-wechat.yuanhu.com/#/ai-setting/agent` 真实点击调研。

### 3.1 AI 知识库

- 主页面分“知识库”“知识内容”两个 Tab；知识库列表提供关键词、查询、重置、新增、管理、编辑、删除和分页。
- 新增/编辑包含名称、描述与校验；删除有二次确认。
- “管理”抽屉内分“文件知识”“问答对”，包含筛选、分页、同步、添加、导入、批量操作等。
- 知识内容提供类型、状态、日期筛选和列表。
- 当前 MoChat 没有文件、问答对、同步、素材或索引 API，故只借鉴信息层级、筛选节奏、弹层与反馈，不复制这些能力。

### 3.2 智能体管理

- 首页以三张智能体卡片进入详情；详情包含策略开关、规则配置、基础信息、使用流程和高级规则新增表单。
- 当前 MoChat 只有名称、说明、知识库 ID 和状态，不具备提示词、模型、工具、规则、员工范围、发布或运行链路，故本轮不会复制相关字段。
- 可借鉴“先看能力状态，再进入配置”的层级：MoChat 页面会明确显示“配置元数据”和“运行能力未接入”的区别。

### 3.3 参考产品缺陷

- 1280 宽度时内容被侧栏遮挡并出现横向滚动；
- 窄屏主要整体缩放，未形成适合操作的响应式重排；
- 部分智能体详情不支持 Escape 或遮罩关闭；
- 查询状态不进入 URL；
- 多层抽屉与弹窗关闭行为不一致。

上述缺陷不复制。MoChat 延续共享 Dashboard 对话框/抽屉契约，支持关闭按钮、遮罩、Escape、焦点恢复和窄屏全宽。

## 4. 范围矩阵与数据来源

| 控件/数据 | 前端来源 | API/后端 | 存储/口径 | 空值或缺口语义 |
|---|---|---|---|---|
| 知识库总数、启用/停用数 | 查询返回数组统计 | KB GET | 当前 principal 的 tenant+corp 未软删记录 | 0 表示当前企业无元数据记录 |
| 登记文档数 | `documentCount` | KB CRUD | 持久化登记字段，不代表已上传或可检索文档 | 页面明确标为“登记值”，表单不再宣称内容已接入 |
| 智能体总数、启用/停用数 | 查询返回数组统计 | Agent GET | 当前 principal 的 tenant+corp 未软删记录 | 0 表示当前企业无元数据记录 |
| 关联知识库 | Agent ID 数组与 KB 列表联结 | Agent CRUD + KB GET | 仅允许引用同 tenant+corp 且未删除的知识库 | 失效旧 ID 明确标记，不计入可用知识库 |
| 查询/状态筛选 | URL `q/status/page/pageSize` + 真实返回数组 | 不新增伪接口 | 在已获取的企业真实数据上确定性过滤、分页 | 无结果显示“当前筛选无匹配”，不是“未接入” |
| 运行能力 | 固定产品能力说明 | 无 Provider 合同 | 当前模块没有 AI Provider、文档索引或运行消费者 | 显示“仅配置元数据；运行能力未接入”，不能显示成功/就绪 |
| 操作审计 | 后端事务写入 | CRUD 同事务 | 新审计表记录 tenant、corp、actor、entity、action、entity ID、变更字段和时间 | 审计失败则 CRUD 回滚，不伪成功 |

## 5. 交互模型

### 5.1 共享列表行为

- 页面头只保留标题、简短能力边界和唯一主操作，不增加大块介绍卡。
- 查询区集中放关键词、状态、查询、重置和刷新；查询提交时写入 URL 并回到第 1 页。
- 分页固定为 10/20/50 条，`page`、`pageSize` 与 URL 一致；刷新后恢复。
- 加载、接口错误、无记录、筛选无结果、权限依赖错误分别展示，不互相冒充。
- 时间用本地可读格式，原始空值回退为“—”。

### 5.2 AI 知识库

- 列表展示名称、说明、登记文档数、配置状态、更新时间和操作。
- 新建/编辑校验名称 2–128 字符、说明长度、登记文档数非负且为整数、状态只能是 0/1。
- “配置启用”只表示该元数据可供未来能力消费，页面同步显示文档上传/检索未接入。
- 删除前确认；被智能体引用时后端拒绝，前端显示明确冲突原因和引用智能体名称或数量。
- 删除、保存、启停成功后刷新真实查询；失败时保留编辑内容并展示稳定中文反馈。

### 5.3 智能体管理

- 列表展示名称、说明、实际关联知识库名称、配置状态、更新时间和操作。
- 关联选择只列当前企业未删除知识库；停用知识库允许保留既有关联但不能新选，并清晰标注。
- 知识库请求处于加载、403 或错误时，关联表单禁用保存并显示原因，不能显示为“0 个”。
- 无可用知识库时提供跳转知识库页的引导；仅有智能体页权限时仍可通过补充的 KB GET 资源读取依赖数据。
- 删除、编辑、启停与失败反馈规则同知识库页。

### 5.4 弹层与关闭

- 复用 `DashboardDialog`；关闭按钮、遮罩和 Escape 均有效。
- 有未保存修改时，关闭先提示确认；无修改直接关闭。
- 关闭后焦点回到触发按钮；保存中禁止重复提交与关闭导致的不确定状态。
- 窄屏使用全宽或接近全宽弹层，内容区内部滚动，不能产生文档级横向滚动。

## 6. 后端合同与安全边界

### 6.1 输入与错误

- 只接受单个 JSON 对象，限制请求体大小，拒绝未知字段和尾随 JSON。
- 名称、说明、登记文档数、状态、知识库 ID 数组在后端再次校验。
- 状态仅允许 `0` 或 `1`；缺失或非法值返回 400，不再默认改为启用。
- 对外返回稳定机器码与安全消息，不返回原始 SQL/驱动错误；不存在、引用冲突、验证失败分别使用 404/409/400。

### 6.2 租户与引用

- tenant/corp/actor 只来自登录 principal；继续忽略客户端企业声明。
- 智能体创建/更新前验证每个知识库 ID 都属于当前 tenant+corp 且未删除。
- 知识库删除前检查当前 tenant+corp 智能体引用；存在引用时拒绝删除。
- 仓储读取 JSON 失败必须返回错误，不能静默变成空数组。

### 6.3 审计

- 创建 `mochat_go_ai_settings_audits`，至少包含 tenant、corp、actor、entity_type、entity_id、action、changed_fields、created_at。
- 创建、更新、删除与审计在同一数据库事务内完成。
- 审计只记录字段名和实体 ID，不记录描述正文、密钥或 Provider 凭证。

### 6.4 RBAC

- 修复智能体页面权限对知识库 GET 的依赖：智能体页面权限同时覆盖 Agent CRUD 和 KB GET；页面只有智能体授权时不再因关联查询 403。
- 保留当前仓库“页面权限即页面 CRUD”的兼容模型。本轮不新增独立只读/管理权限码，因为这需要改变 53 页权限目录、角色授权 UI 和现有角色迁移，属于全 Dashboard 权限产品模型变更；报告中将其列为已知边界，不把按钮隐藏描述成后端授权。
- Dashboard Guard 仍按 method+path fail closed，handler 保留 principal/authorizer 防线。

## 7. 视觉原则与响应式

- 保留现有 Dashboard 导航、顶部栏、内容背景和 banner；不修改菜单组名称与顺序。
- 复用 `Phase35PageShell`、`DashboardFilterPanel`、`DashboardPagination`、`DashboardDialog`、`ConfirmAction` 和现有数据状态组件。
- 2560×1440 下内容填满右侧工作区，指标和列表不固定窄宽；1366×900 下无异常横向滚动。
- 低于桌面断点时筛选字段换行、表格进入局部横向滚动、操作区保持可见；390×844 与小高度下对话框可滚动且按钮可达。
- hover 不使用位移、缩放或滤镜，避免文字模糊；状态使用文字与颜色双重表达。

## 8. 测试与验收标准

### 8.1 自动化

- 前端 API client 覆盖八个 CRUD 请求、方法、路径、body 与错误传播。
- 页面覆盖 URL 查询/重置/分页、真实关联名称、停用、创建/编辑 payload、删除确认与失败、知识库依赖错误、未接入能力提示、Escape/遮罩/焦点和窄屏样式合同。
- Go handler 覆盖 `status=0`、非法状态、严格 JSON、稳定错误码、Agent update/delete、同企业引用校验、引用删除冲突、租户隔离。
- MySQL 仓储或事务合同覆盖 CRUD 与审计原子性、软删操作者、损坏 JSON；迁移合同覆盖新表、索引、非破坏性回滚边界和最新版本。
- 运行 Dashboard 全量测试、lint、typecheck、production build，相关 Go 包、RBAC、benchmark、全页面 evidence 门禁和 `git diff --check`。

### 8.2 Docker 与浏览器

- 使用 `mochat-go-desktop` 保留卷 Compose，只重建必要 app；MySQL、Redis 和具名卷不删除。
- 两个路由都实测查询、重置、分页、新增、编辑、启停、删除确认/取消、冲突/失败、刷新持久化、Escape、遮罩和关闭按钮。
- 分辨率至少覆盖 2560×1440、1366×900、390×844 和小高度桌面；检查页面级横向溢出、弹层滚动、控制台与关键网络请求。
- 外部 Provider、文档上传、索引与智能体真实运行不执行，也不宣称通过。

## 9. 回滚边界

- 前端改动限于 AI 设置 feature、必要共享样式/测试和 evidence 动作契约。
- 后端改动限于 AI Settings 模块、其迁移/测试和智能体页面 KB GET 权限映射。
- 新审计表的 down migration 只删除本轮审计表和新增权限映射，不删除知识库/智能体业务数据。
- 不触碰 `docs/PROJECT_PROGRESS.zh-CN.md`、`.workbuddy/`、`tmp/`、调试脚本、旧 `web/saas-admin/`、Phase 7 或其他任务差异。
