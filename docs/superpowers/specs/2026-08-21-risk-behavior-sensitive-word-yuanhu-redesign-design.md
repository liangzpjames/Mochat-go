# 风险行为与敏感词菜单优化设计

> 文档日期：2026-08-21
> 审阅状态：已完成设计、实施与运行环境验收
> 目标路由：`/ai-insight/v2/risk`、`/ai-insight/v2/sensitive-word`

## 1. 目标与停止点

本轮设计覆盖“风险预警”分组下的“风险行为”和“敏感词”两个菜单。页面借鉴圆弧 AI 已沉淀的信息架构、视觉密度和操作节奏，但所有列表、数字、状态、详情和操作都必须来自 MoChat 的真实接口与存储。

设计目标：

1. 保留现有菜单导航、菜单名称、路由和顶部 banner；
2. 移除纯介绍性质的大块顶部卡片，页面内容直接进入标题、标签、查询和业务结果；
3. 两页共用统一的风险预警工作台骨架，但保留独立接口、权限和数据模型；
4. 风险行为形成“风险记录—风险详情—人工处置”和“规则列表—规则编辑”闭环；
5. 敏感词形成“命中记录—会话详情”和“词组—词条—状态/移动/删除”闭环；
6. 以 `2560×1440` 为主要验收尺寸，常规桌面宽度不拥挤、不抖动、不出现模糊 hover；
7. 明确区分“当前无数据”“接口缺字段”“产品能力未实现”“同步或权限异常”，不把缺口显示成 0；
8. 设计阶段完成后进入实施；实施结果、真实数据缺口和验收证据回填到本文档及配套实施文档。

## 3. 方案比较与结论

### 方案 A：保留当前组件，只换样式

- 优点：改动小；
- 缺点：风险行为仍然使用动态字段和通用 API，分页、URL、详情和后台数据流问题不会解决；敏感词配置仍是横向堆控件。

### 方案 B：合并成单一“风险中心”

- 优点：可共享统计和导航；
- 缺点：会改变现有菜单语义和用户操作路径；风险规则与敏感词词库的数据模型、权限和处理动作不同，合并后反而增加理解成本。

### 方案 C：共享工作台骨架，保留独立领域页面（采用）

建立统一的风险预警页头、标签、查询栏、状态条、表格、抽屉和分页组件；风险行为使用独立类型化 API 和风险记录模型，敏感词继续使用词库与命中模型。两个菜单保持独立，视觉和交互统一。

该方案不会把旧布局强行换色，也不会为了对齐参考页增加 MoChat 没有的数据。

## 4. 共享设计规则

### 4.1 页面骨架

1. 页面容器 `max-width: none`，占满主内容区；
2. 标题区不是卡片，只显示菜单标题、最多一行短说明和必要主操作；
3. 查询、重置、刷新放在同一查询区，页头不再出现第二个刷新；
4. 标签使用下划线式导航，不使用厚重分段卡片；
5. 数据源告警仅在真实能力异常时出现一条紧凑状态条，不展示大段说明框；
6. 结果区采用全宽表格或双栏工作区，表头、操作列和分页位置统一；
7. 表格整行可打开详情；行内复选框、开关和操作按钮阻止冒泡；
8. 抽屉通过关闭按钮、遮罩和 `Escape` 关闭，关闭后焦点回到触发行；
9. hover 只改变边框、背景或颜色，不使用 `transform`、缩放和位移；
10. 页码统一使用 `DashboardPagination`，固定每页 20 条。

### 4.2 2560×1440 原型骨架

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 风险行为 / 敏感词                                           [必要主操作] │
│ [业务标签 A]  [业务标签 B]                                                │
├──────────────────────────────────────────────────────────────────────────────┤
│ 筛选字段...                                      [查询] [重置] [刷新]     │
├──────────────────────────────────────────────────────────────────────────────┤
│ 状态/数量短条（仅真实汇总或真实能力告警）                                  │
├──────────────────────────────────────────────────────────────────────────────┤
│ 全宽结果区 / 左右工作区                                                     │
│                                                                            │
│                                                             右侧详情抽屉 → │
├──────────────────────────────────────────────────────────────────────────────┤
│ 共 N 条                         固定 20 条                   ‹ 1 2 3 ›      │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 响应式

- `2560×1440`：内容填满外框；结果区不限制为 1320px；右侧详情宽 560–620px；
- `1440×900`：查询字段允许换行，表格关键字段保留，次要技术字段只在详情出现；
- `1024px` 以下：敏感词配置左右栏改为单列；详情抽屉宽度为 `min(100%, 560px)`；
- 页面只保留一个主滚动区域；抽屉和词组侧栏可独立滚动。

## 5. 风险行为页面设计

### 5.1 一级结构

标签保持：

1. `风险记录`；
2. `规则配置`。

URL 使用 `tab=records|rules` 保存当前分区。切换分区时清除对方的选中详情和页码，但保留各自已提交筛选。

### 5.2 风险记录

#### 查询区

字段顺序：

1. 发生日期起止；
2. 风险行为；
3. 风险等级；
4. 审核状态；
5. 会话类型；
6. 关联员工；
7. 查询、重置、刷新。

输入过程不请求后端。点击“查询”或在输入框按 Enter 后才提交筛选并把页码重置为 1。刷新只刷新已提交条件。

员工选择使用真实员工目录，不允许用户手填数据库 ID。风险行为下拉来源于风险规则/记录可用行为码，由前端做固定中文枚举映射；无法识别的历史行为码显示原值并标记“未配置中文名称”，不丢弃数据。

#### 汇总短条

使用与列表相同的租户、企业、员工范围和日期条件返回：

- 当前条件总记录数；
- 待处理数；
- 高风险数；
- 已处理数。

这些值由后端聚合返回。接口未返回时显示“汇总不可用”告警，不把缺失值显示为 0。

#### 表格

主列表只展示业务字段：

| 字段 | 来源 | 展示 |
|---|---|---|
| 风险行为 | `behavior` + 规则名称 | 中文标签 + 规则名称 |
| 风险等级 | `riskLevel` | 高/中/低颜色标签 |
| 关联对象 | `relatedUser` | 姓名、员工/客户身份；资料缺失时显示“对象资料缺失” |
| 会话类型 | `conversationType` | 客户会话/群聊/员工会话 |
| 触发内容 | `triggerMessage` | 单行省略，完整内容在详情 |
| 审核状态 | `auditStatus` | 待处理/已确认/已忽略/已复核/未知状态 |
| 发生时间 | `occurredAt` | 当前企业时区格式化 |

记录 ID、规则 ID、策略 ID、会话 ID和消息 ID不占主列表列，仅在详情“技术信息”折叠区展示。

待处理记录可勾选。选中后在表格上方出现批量操作条：“确认风险”“忽略风险”；提交前弹出确认框，可填写备注。已处理记录不可重复勾选。

#### 详情抽屉

整行点击打开右侧抽屉：

1. 风险等级、行为、状态和发生时间；
2. 触发消息，命中关键词高亮；
3. 关联员工/客户和会话类型；
4. AI 摘要区：只有 `aiSummary` 有真实内容时展示；否则不留空卡；
5. 审计时间线：操作者、动作、备注、时间；
6. “查看完整会话”跳到本系统会话页面并带入可识别的 `conversationId`/`messageId`；无法定位时按钮不渲染，并显示一条紧凑数据缺口；
7. 待处理记录可在抽屉底部确认或忽略，成功后保留筛选并刷新当前页。

### 5.3 规则配置

#### 查询和列表

查询字段：规则名称、状态、监听主体、风险行为；右侧主操作为“新增规则”。

列表字段：规则名称、风险行为、匹配内容、监听主体、风险等级、累计命中、状态、操作。规则整行可查看，编辑、启停和删除是独立操作。

删除已有风险记录的规则时，沿用后端约束并显示“已有风险记录，请停用规则”；不在前端伪删除。

#### 新增/编辑抽屉

字段：

- 规则名称；
- 监听主体：员工、客户、员工与客户；
- 风险行为类型；
- 匹配关键词；
- 风险等级；
- 白名单；
- 规则状态。

首期真实评估器只支持文本包含匹配，因此不展示正则、语音识别、图片识别或模型分类器。`notifyType` 当前没有真实通知 Provider，表单不展示通知方式，新建规则固定写入 `none`。

`aiInsightEnabled` 字段已存在，但当前没有生成 AI 摘要的模型链。页面不提供“AI 分析”开关；编辑旧规则时保留原值，新建规则写入 `false`。AI 能力状态在数据缺口清单中明确说明。

### 5.4 风险记录自动生成

当前 `POST /dashboard/risk/evaluate` 能对单条消息执行关键词评估，但没有证据表明会话存档同步后会自动调用它。因此“风险记录自动扫描”属于产品数据流缺口，而不是页面空数据。

实施方案增加独立风险扫描任务：

```text
企业微信会话存档 Provider
  → mc_work_message_1..10
  → 风险扫描游标
  → 当前企业启用的风险规则
  → 文本提取与关键词匹配
  → mochat_go_risk_records（幂等）
  → 风险记录列表/汇总/详情
```

扫描任务只处理已有文本提取能力支持的消息；音频、图片和文件内容不推断风险。页面状态条从后端读取“扫描是否启用、最后扫描时间、最近错误”，未启用或异常时显示短告警。

## 6. 敏感词页面设计

### 6.1 一级结构

标题改为与菜单一致的“敏感词”。标签保持：

1. `命中记录`；
2. `敏感词配置`。

移除三张概览大卡。总数、当前条件和扫描状态以一行短条呈现，首屏优先展示列表。

### 6.2 命中记录

#### 查询区

字段：

1. 关联员工（真实员工选择器）；
2. 客户群（真实群聊选择器）；
3. 词组；
4. 敏感词；
5. 触发来源（客户/员工）；
6. 会话场景；
7. 触发日期起止；
8. 查询、重置、刷新。

宽度不足时第二行换行。查询仍采用显式提交，不在输入或选择过程中连续请求。

#### 列表

| 字段 | 来源 | 展示 |
|---|---|---|
| 敏感词 | `sensitiveWordName` | 高亮词标签 |
| 触发人 | `triggerName` + `source` | 姓名 + 客户/员工身份 |
| 会话场景 | `triggerScenario` | 客户会话/群聊等真实场景 |
| 消息摘要 | `contentPreview` | 后端从真实消息内容提取的短文本 |
| 触发时间 | `triggerTime` | 当前企业时区格式化 |

整行点击打开详情抽屉。固定每页 20 条，页码、筛选和 `matchId` 写入 URL。

#### 命中详情抽屉

详情复用 `/dashboard/sensitiveWordsMonitor/show` 返回的真实消息序列：

- 头部展示敏感词、触发人、来源、场景和时间；
- 消息按发送时间排列，区分发送方；
- `isTrigger=1` 的消息高亮；
- 文本、结构化消息和未知消息使用现有会话消息格式化器；
- 加载失败保留抽屉和重试按钮；
- 关闭按钮、遮罩和 `Escape` 均生效。

### 6.3 敏感词配置

采用左右两栏：

```text
┌────────────── 词组（260px） ──────────────┬──────────────── 敏感词条 ────────────────┐
│ 搜索词组                                  │ 搜索词条  状态          [新增敏感词]       │
│ 全部词条                 6                │                                          │
│ 默认敏感词库             6                │ 词条 / 状态 / 员工命中 / 客户命中 / 时间 │
│ ...                                       │                                          │
│ [+ 新增词组]                              │                               分页       │
└───────────────────────────────────────────┴──────────────────────────────────────────┘
```

左栏占据完整列高，不因选择不同词组发生宽度和按钮抖动。词组显示真实词条数和启用数；接口缺少计数时显示“统计不可用”，不填 0。

右栏查询字段为词条关键字和状态，固定每页 20 条。列表展示：词条、词组、状态、员工命中数、客户命中数、创建时间、操作。后端当前已经返回 `employeeNum`、`contactNum`、`createdAt`，前端必须保留并展示，不再丢弃。

“新增敏感词”打开抽屉，支持逗号、顿号、分号和换行批量拆词，实时显示去重后的有效词数；选择真实词组后提交。套餐额度错误、重复、并发冲突和权限错误显示在抽屉内，不让用户从全局 toast 猜原因。

词组新增/改名使用小弹窗；词条启停、移动和删除使用行内操作与确认层。删除只软删除词条，历史命中记录继续保留敏感词名称。

### 6.4 敏感词扫描状态

敏感词自动扫描链已存在：

```text
会话存档同步
  → mc_work_message_1..10
  → cron-sensitive-word-monitor
  → mc_work_message_id(type 21..30) 游标
  → mc_sensitive_words_monitor
```

页面增加只读扫描状态：扫描是否启用、最后游标更新时间、最近错误。没有命中记录时：

- 扫描正常：显示“当前条件没有命中记录”；
- 扫描未启用：显示能力告警；
- 会话存档 Provider 异常：显示同步告警；
- 权限范围为空：显示权限空态。

## 7. 数据来源矩阵

### 7.1 风险行为

| 控件/字段 | 前端接口 | 后端/存储 | 口径与空值 |
|---|---|---|---|
| 风险记录列表 | `RiskBehaviorApi.records` | `RiskBehaviorHandler.Records` → `mochat_go_risk_records` | 按 tenant、corp、员工权限、筛选和时间范围分页 |
| 风险汇总 | `RiskBehaviorApi.summary` | 新增同口径聚合查询 | 缺接口/查询失败显示“汇总不可用”，不显示 0 |
| 风险详情 | `RiskBehaviorApi.recordDetail` | 风险记录 + `mochat_go_risk_record_audits` + 可定位的归档消息 | 归档消息缺失时仍展示风险快照，并标记无法定位完整会话 |
| 批量处置 | `RiskBehaviorApi.audit` | `AuditRiskRecords` + 审计表 | 只允许 `confirmed`/`ignored`；逐企业和权限校验 |
| 规则列表 | `RiskBehaviorApi.rules` | `mochat_go_risk_rules` + strategies | 累计命中来自 `trigger_count` |
| 规则写入 | create/update/status/remove | 现有风险规则 writer | 有历史风险记录的规则不能删除 |
| 员工选择 | `RiskBehaviorApi.staffOptions` | 复用员工/部门目录 | 只返回当前用户允许范围 |
| 自动扫描状态 | `RiskBehaviorApi.scannerStatus` | 配置 + 风险扫描游标/运行结果 | 未启用、异常、从未运行必须区分 |

### 7.2 敏感词

| 控件/字段 | 前端接口 | 后端/存储 | 口径与空值 |
|---|---|---|---|
| 命中记录 | `SensitiveWordApi.matches` | `mc_sensitive_words_monitor` | 按 corp、员工权限、群、词组、词条、来源、场景、时间分页 |
| 消息摘要 | `contentPreview` | `mc_sensitive_words_monitor.content` | 只由后端安全提取；不可解析显示消息类型，不输出 JSON |
| 命中详情 | `matchDetail` | `conversation_json` 或当前消息字段 | 没有会话序列时返回单条触发消息，不伪造上下文 |
| 词组 | `groups` | `mc_sensitive_word_group` + 词条聚合 | 词组计数由 SQL 聚合；不可用时明确告警 |
| 词条列表 | `list` | `mc_sensitive_word` + 命中聚合 | 员工/客户命中数和创建时间为真实字段 |
| 新增/改名/移动/启停/删除 | 现有 mutation API | 事务、版本、幂等、审计、SaaS 配额 | 409、403、配额和业务错误在操作容器内展示 |
| 员工/群聊选择 | `filterOptions` | 员工目录、客户群目录 | 不允许手填内部 ID |
| 扫描状态 | `monitorStatus` | cron 配置 + `mc_work_message_id` 21..30 | 未启用、无游标和最近异常分开 |

## 8. 已确认的数据与能力缺口

| 缺口 | 分类 | 本轮处理 |
|---|---|---|
| 风险记录自动扫描没有接入会话存档增量链 | 产品能力未完整实现 | 实施风险扫描任务和独立游标；完成前页面显示“自动扫描未启用” |
| 风险规则有 `aiInsightEnabled`，但没有 AI 摘要生成 Provider | 产品能力未实现 | 不展示开关、不生成摘要；仅有真实 `aiSummary` 时展示 |
| 风险详情没有专用详情/审计读取接口 | 后端未提供 | 新增详情接口，读取风险快照和审计历史；会话上下文只在可定位时返回 |
| 风险记录历史状态出现 `reviewed`，写接口只支持 `confirmed/ignored` | 历史数据口径不一致 | 读取兼容“已复核”，新操作仍只写两种受支持状态 |
| 敏感词记录筛选要求手填员工和客户群 ID | 功能存在但前端未接好 | 接入真实员工/群聊选择器 |
| 敏感词后端返回命中数与创建时间，前端解析时丢弃 | 数据存在但前端未展示 | 扩展类型和解析，直接展示真实值 |
| 敏感词词组缺少词条数/启用数 | 后端未返回聚合 | 扩展词组查询聚合；失败不显示伪造 0 |
| 敏感词命中列表没有消息摘要、来源/场景筛选和扫描状态 | 后端未返回 | 扩展读取接口和状态接口，不改历史记录 |
| 生产会话存档 bridge 可能未配置 | 同步/配置状态 | 页面根据真实状态告警，用户后续补企业微信官方 SDK bridge |

## 9. 类型与接口边界

风险行为从通用 `BusinessWorkbenchApi` 中移出，使用独立类型：

```ts
type RiskRecordPage = {
  items: readonly RiskRecord[];
  total: number;
  page: number;
  perPage: 20;
  summary: RiskRecordSummary | null;
};

type RiskRecordSummary = {
  total: number;
  pending: number;
  highRisk: number;
  processed: number;
};
```

敏感词现有类型扩展但保持 API 领域独立：

```ts
type SensitiveWordItem = {
  id: number;
  groupId: number;
  groupName: string;
  name: string;
  status: 1 | 2;
  employeeHitCount: number;
  customerHitCount: number;
  createdAt: string;
  version: string;
};
```

页面组件不得消费 `Record<string, unknown>`，不得根据第一条响应动态生成表头，也不得直接渲染原始 JSON。

## 10. URL 与查询规则

### 风险行为

- 记录：`tab`、`startAt`、`endAt`、`behavior`、`riskLevel`、`auditStatus`、`conversationType`、`employeeIds`、`page`、`recordId`；
- 规则：`tab`、`ruleKeyword`、`ruleStatus`、`subject`、`ruleBehavior`、`rulePage`、`ruleId`。

### 敏感词

- 记录：`tab`、`employeeIds`、`roomId`、`groupId`、`wordId`、`source`、`scenario`、`startAt`、`endAt`、`page`、`matchId`；
- 配置：`tab`、`groupId`、`wordKeyword`、`wordStatus`、`wordPage`。

草稿输入与已提交查询分离。只有查询、重置、分页和明确选择详情才更新 URL 或请求后端。

## 11. 权限与安全

1. 所有接口沿用服务端 principal 的 tenant/corp，不接受前端 `corpId` 覆盖；
2. 风险记录、详情和敏感词命中详情使用同一员工数据范围；列表可见但详情不可见的记录必须返回 404/403，不泄露内容；
3. 风险审计和规则管理需要 manage 权限；无权限时不渲染可写按钮；
4. 敏感词新增、改名、移动、启停和删除继续使用现有 add/edit/delete 动作权限；
5. 批量操作使用稳定幂等键；危险操作必须确认；
6. 触发消息和会话内容按普通文本渲染，不注入 HTML；
7. 技术错误不直接泄露 SQL、表名、密钥或 Provider token。

## 12. 错误、空态与反馈

| 场景 | 展示 |
|---|---|
| 当前条件没有记录 | 紧凑业务空态，保留筛选区 |
| 自动扫描未启用/从未运行 | 状态条告警并说明需要启用的服务，不伪装成无风险/无命中 |
| 会话存档 Provider 异常 | 同步告警 + 重试；列表保留最后成功数据 |
| 汇总失败但列表成功 | 只把汇总标记为不可用，列表继续展示 |
| 详情失败 | 抽屉保留并显示重试，不关闭、不清空列表 |
| mutation 409 | 表单内提示“数据已变化，请刷新后重试” |
| SaaS 配额不足 | 新增敏感词抽屉内展示后端额度文案 |
| 权限不足 | 权限状态，不渲染写操作 |
| 页面刷新 | 从 URL 恢复已提交筛选、分页和详情 |

后台刷新不得用全屏 loading 替换已显示内容。所有刷新只显示轻量状态，控件宽高保持稳定。

## 14. 实施边界

本轮实施包含：

- 两页前端重组；
- 风险行为类型化 API、查询/详情/汇总增强和自动扫描链；
- 敏感词已有字段补回、筛选/词组统计/状态增强；
- 独立样式、测试、RBAC 资源、Docker 部署和浏览器验收。

本轮不包含：

- LLM 风险分类、AI 摘要生成、语音转写、图片 OCR；
- 邮件、短信、企微群机器人等风险通知 Provider；
- 风险或敏感词导出；
- 修改左侧导航、顶部 banner 或其他风险预警菜单；
- 复制圆弧 AI 的企业数据、文案或未重新观测的功能。

## 15. 审阅结论项

本设计默认采用以下结论，用户审阅时只需指出需要调整的项：

1. 两个菜单保持独立，不合并；
2. 两页共用工作台骨架和抽屉交互；
3. 风险行为补齐自动扫描链，避免仅靠手工评估接口；
4. AI 摘要和通知 Provider 不在本轮伪接入；
5. 敏感词配置采用左侧词组整列、右侧词条整列；
6. 所有列表固定每页 20 条，查询显式提交；
7. 数据能力异常使用紧凑告警，不使用顶部介绍框。
