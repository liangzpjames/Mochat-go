# AI 设置编辑器与知识库上传增量设计

日期：2026-08-24

## 1. 背景与目标

本增量承接已完成的 AI 设置菜单优化，只处理以下两项体验问题：

1. “会话分析助手”“智能分析助手”的编辑弹窗改为横向信息布局，在常规桌面宽度下一次展示更多配置，同时保留窄屏和小高度可用性。
2. 新建知识库时允许顺带选择一个文档上传，但文件不是必填项；数据必须走现有知识库创建与文档上传持久化接口。

不改变两类助手的业务边界，不开放新增助手，不增加外部 Provider 能力，不触及 Phase 7 会话存档。

## 2. 现状依据

- 助手编辑已由 `AgentPage` 中两个 `DashboardDialog` 承载，保存分别使用既有会话分析助手与智能分析助手配置接口。
- 知识库创建与文档上传已具备独立真实接口：先创建知识库可获得 ID，再可向该知识库上传 `.txt`、`.md`、`.pdf`、`.docx` 文档。
- 当前“管理文档”已能展示解析状态和失败信息，因此新建流程无需引入新的复合后端合同。
- Dashboard 现有弹窗提供 Escape、遮罩关闭、加载态和未保存确认能力，本增量继续沿用。

## 3. 方案比较与选择

### 3.1 助手编辑器

- 方案 A：宽屏横向弹窗。桌面端将基础信息、知识库、分析范围/规则并排，提示词横向并列；窄屏自动回落单列。
- 方案 B：右侧抽屉。可容纳较长内容，但改变现有交互模型，且桌面横向空间利用不如宽弹窗直接。
- 方案 C：页签或步骤表单。能降低单屏密度，却增加切换成本，也违背“一次展示更多信息”的目标。

采用方案 A。弹窗最大宽度约 1180px，内部使用十二列响应式网格：桌面端三个主要区块各占四列；会话分析的两类提示词在下一行并排。中等宽度改为两列，窄屏改为单列；小高度仅滚动内容区，操作区保持可见。

### 3.2 新建知识库时上传文档

- 方案 A：前端顺序编排现有两个接口。知识库创建成功后，仅当用户选择文件时上传。
- 方案 B：新增后端复合接口并做事务式补偿。文件存储与数据库难以形成真正原子事务，且明显扩大本次合同范围。
- 方案 C：创建后自动打开“管理文档”。仍需额外一次选择和确认，不符合“一起上传”。

采用方案 A。文件保持可选，未选择时行为与现在一致。

## 4. 交互模型

### 4.1 助手编辑弹窗

- 桌面端首行并排展示基础设置、知识库、会话范围或分析规则。
- 会话分析助手的“客户分析提示词”和“员工质检提示词”并排展示。
- 保存、取消、未保存确认、Escape、遮罩关闭和焦点恢复语义不变。
- 保存过程中禁止重复提交和关闭。

### 4.2 新建知识库

- 新建弹窗新增“初始文档（可选）”文件选择框，接受 `.txt`、`.md`、`.pdf`、`.docx`，提示 20MB 限制。
- 文件不参与必填校验；名称等原有字段仍按既有规则校验。
- 仅选择文件也属于未保存修改，Escape 或遮罩关闭应出现放弃确认。
- 提交后先创建知识库：
  - 未选择文件：创建成功即完成。
  - 选择文件且上传/解析成功：明确提示知识库和文档均可用。
  - 知识库创建成功、上传请求失败：保留已创建知识库，提示用户到“管理文档”重试。
  - 文档已保存但解析失败：明确提示知识库已创建、文档当前不可用，可在“管理文档”处理。
  - 知识库创建失败：保留弹窗和输入，不发起上传。
- 不做自动删除补偿，避免已创建资源因网络抖动被破坏或重试产生不透明结果。

## 5. 数据、权限与安全边界

- 沿用当前租户 `corpId`、RBAC 资源和知识库/文档接口，不新增绕过权限的入口。
- 文件类型、大小和解析结果以后端校验为准；前端 `accept` 只用于选择提示，不能代替安全校验。
- 不把文档内容或 Provider 密钥写入前端静态数据、日志或提交。
- 上传失败不得展示伪成功；部分成功必须明确区分“知识库已创建”和“文档未可用”。

## 6. 响应式与视觉原则

- 复用 Dashboard 当前卡片、字段、按钮、弹窗反馈和间距规范。
- 常规桌面宽度优先横向利用空间，不通过缩小字号或压缩可点击区域换取密度。
- 小于约 980px 时主要配置区块改为两列；小于 768px 时全部单列，提示词文本域同样单列。
- 小高度场景内容区滚动，页脚按钮不随表单滚出视野。

## 7. 验收标准

1. 两个助手编辑弹窗在桌面端均呈横向多栏布局，字段和保存行为完整；窄屏无横向溢出。
2. 新建知识库不选文件仍可成功创建，且不调用上传接口。
3. 新建知识库选择支持文件后，使用新知识库真实 ID 调用上传接口并显示真实状态。
4. 创建成功但上传失败时不删除知识库，页面给出可操作的部分失败反馈。
5. 文件选择参与未保存状态；关闭、Escape、遮罩与加载态符合既有弹窗规范。
6. 相关组件测试、布局契约测试、Dashboard 全量测试、类型检查、范围 lint、生产构建与真实浏览器验收通过。
