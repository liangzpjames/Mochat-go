# Dashboard 权限编辑器界面优化设计

## 目标

优化“员工权限”和“角色管理”的权限编辑体验，使 49 个普通 Dashboard 页面权限在桌面端和 390px 窄屏上都能清晰查找、选择和设置数据范围，同时保持现有 RBAC 数据合同、二次确认、版本冲突保护和超管专属权限边界不变。

## 已确认范围

- 员工权限弹窗不展示继承权限。继承权限仍由后端计算，但本页面不再呈现来源列表。
- 员工权限弹窗保留多角色选择与直接权限设置。
- 角色权限继续在独立的角色编辑界面设置，并与员工直接权限共用一致的页面权限选择体验。
- 不改变 `/dashboard/access/*` API、`expectedVersion`、权限 code、scope 或存储结构。
- 四个 `superadminOnly` 页面始终不进入可授予列表。

## 交互设计

### 员工权限

弹窗顶部显示简洁摘要，包括已选角色数和已选直接权限数。角色以可换行卡片网格展示，停用角色保持可见但不可新增选择；已有停用角色不在本次界面被误激活。

直接权限使用共享权限选择器：

- 支持按页面名称或权限 code 搜索。
- 按 catalog 的 `groupCode` 分组，组标题显示当前已选数量与本组总数。
- 每个权限独立复选；选中后数据范围下拉框才可操作。
- 数据范围显示为“本人 / 部门 / 全企业”，提交值保持 `self / department / tenant`。
- 权限区域拥有固定最大高度和内部滚动，不再让整个弹窗无限增高。

### 角色权限

角色编辑弹窗复用同一个共享权限选择器。名称、备注、权限摘要和权限分组形成清晰层级；每项角色权限可独立选择数据范围。系统角色仍不显示编辑、启停、删除入口。

### 响应式与可访问性

- 桌面端权限行采用“权限名称 + 数据范围”的双列布局。
- 390px 下改为单列，选择框占满可用宽度，不产生文档级横向滚动。
- 分组使用可识别标题，搜索框和范围选择器均有稳定的可访问名称。
- 保存操作继续先展示变更摘要，再经 `ConfirmAction` 确认；409 保留当前表单。

## 组件边界

- 新增 `access-permission-selector.tsx`：只负责 catalog 过滤、搜索、分组、权限勾选和 scope 更新。
- `access-staff-page.tsx`：负责员工详情、角色选择、直授权限状态与保存。
- `access-role-page.tsx`：负责角色字段、角色权限状态与 CRUD。
- `styles/index.css`：增加权限编辑器样式和 390px 响应式规则。

## 验收标准

- 员工弹窗不出现“继承权限”及继承来源内容。
- 员工角色与直接权限数量摘要准确。
- 49 个普通页面可按组浏览和搜索，四个超管专属页面不可选。
- 员工直授权限和角色权限均可提交独立 scope。
- 停用角色不可新增选择，系统角色不可编辑。
- 首次点击保存不写入，确认后才调用 mutation；409 不清空表单。
- 桌面端与 390px 均可操作且无文档级横向溢出。
