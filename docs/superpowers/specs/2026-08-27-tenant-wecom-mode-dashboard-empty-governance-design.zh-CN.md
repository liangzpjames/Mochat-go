# 租户企微模式、Dashboard 空态与超级管理员治理修复设计

## 背景与目标

当前 SaaS 开户事务会创建租户、唯一企业、待配置绑定和首个 Dashboard 超级管理员，但不会记录租户选择的企微对接模式。企微模式随后由 SaaS 租户详情中的候选、验证、切换和回滚流程维护，导致自建应用凭据与 Dashboard“唯一企业资料”的权威配置重复。与此同时，待配置企业绑定会被 Dashboard 访问守卫视为全局阻塞条件，使绝大多数页面返回 `CORP_CONFIGURATION_REQUIRED`，新租户无法在未配置企微时正常使用 Dashboard。

SaaS 的 Dashboard 超级管理员治理界面还会默认选中唯一超级管理员并开放必然失败的“停用”动作；替换候选为空时仍展示下拉框；跨租户或关闭详情后可能保留旧错误和幂等状态。

本次修复目标是：开户时必须选择且永久锁定企微模式；按模式隔离配置入口和凭据来源；未配置企微时 Dashboard 查询正常返回空数据；由服务端给出超级管理员治理动作能力，前端不再诱导用户提交必然失败的操作。

## 方案选择

不采用“只修前端按钮”的方案，因为它无法阻止旧接口切换模式，也无法消除前后端治理规则漂移。不采用“保留候选槽但隐藏切换入口”的方案，因为隐藏不等于不可变，且继续保留重复凭据来源。

采用不可变企微模式策略：开户事务把模式写入租户唯一企业绑定；自建应用继续使用 Dashboard 企业资料现有的加密凭据存储，第三方代开发应用使用 SaaS 管理的独立加密授权记录。运行时根据不可变模式选择唯一凭据来源。现有候选、切换和回滚能力从对外 API 与 SaaS 页面移除。

## 数据模型与迁移

1. 在租户企业绑定上增加非空的 `wecom_integration_mode`，取值仅为 `self_built` 或 `third_party_delegated`。该字段是租户企微模式的唯一权威事实。
2. 新租户开户事务必须写入该字段；开户幂等指纹、治理审计和操作日志都记录模式，但不记录任何 Secret。
3. 现有租户优先从当前有效企微集成记录回填模式；无法判断时回填 `self_built` 并在迁移合同中明确这是兼容默认值。
4. `mochat_go_wecom_integrations` 保留为第三方授权和运行状态记录。新建自建租户不在该表保存 SaaS 侧 Secret；第三方租户可存在一个 `current`、`unconfigured` 记录，后续在 SaaS 安全写入或轮换 Provider App ID 和永久授权码。
5. 应用服务不提供更新绑定模式的命令；任何配置写入都必须先核对请求入口与绑定模式一致。旧切换、回滚和跨模式候选端点返回稳定的“模式不可变”业务错误或从路由表移除。
6. 回滚迁移只删除新增字段及新增约束，不删除既有企业资料、凭据或业务数据。

## 开户与配置所有权

SaaS“开通客户”表单增加必选企微模式。模式随现有套餐、订阅、管理员和激活入口在同一事务内落库。

自建应用模式：

- SaaS 仅显示模式、配置完成度和最近更新时间，不展示或编辑 CorpID、AgentID、Secret、RSA 密钥。
- Dashboard“唯一企业资料”继续负责企业 CorpID 验证、应用 AgentID/Secret、通讯录、回调及会话存档配置。
- 企微运行时只读取 Dashboard 企业资料域的加密凭据。

第三方代开发应用模式：

- SaaS 租户详情提供 Provider App ID、永久授权码和能力范围的安全写入/轮换入口。
- 凭据仍只写入加密存储，响应、审计、错误和日志只返回脱敏状态。
- Dashboard 企业资料页只读显示模式和配置状态，不出现自建应用 Secret 表单。
- 开户时允许不填写第三方凭据；此时状态为“待配置”，不阻塞 Dashboard 使用。

## Dashboard 未配置空态

企业绑定的 `pending` 只表示企微尚未验证，不再等同于 Dashboard 全局不可用。

- 身份、租户停用和 RBAC 仍按原规则失败关闭。
- 已授权查询接口继续进入正式 handler，从本地租户/企业作用域查询业务表；无数据时返回稳定的 `200` 空结构，而不是 403、501 或结构不匹配的错误信封。
- 新租户超级管理员在没有员工绑定时使用租户级数据范围，不能因为 `workEmployeeId=0` 被误判为无权访问。
- 依赖企微外部能力的写操作（同步、发送、验证、回调测试等）根据 Provider 状态禁用，并展示模式对应的配置入口；服务端仍保留配置前置检查，防止绕过前端。
- 数据概览返回零统计、空趋势、空排行和正常分页；缺少 Provider 可作为非错误限制信息展示。
- Docker 运行配置启用仓库已经实现且属于 Dashboard 菜单的模块，所有 API 使用统一 `{code,msg,data}` 信封。

## Dashboard 超级管理员治理

治理读模型由服务端返回身份事实以及可执行动作：重发激活、停用、恢复、作为当前超管、作为替换候选，并为不可执行动作返回稳定阻塞原因。

- 重发激活仅适用于启用、未激活的超级管理员。
- 停用仅适用于已激活且启用的超级管理员，并且租户必须仍有另一名可登录超级管理员。
- 恢复仅适用于已激活但已停用的超级管理员。
- 替换要求当前对象是可登录超级管理员，候选是同租户、已激活、启用且不是当前对象的身份。
- 无可执行对象时展示说明性空态，不自动选中无效目标，不展示可提交按钮。
- 前端选择从服务端能力过滤结果派生；租户切换、详情关闭和成功操作会清除旧选择、旧错误及对应幂等键。
- 请求键按租户、动作和目标隔离；版本冲突时刷新权威治理列表，只保留刷新后仍有效的选择。
- 后端继续执行最后一名超级管理员、租户隔离、版本和幂等检查，前端能力只用于改善交互，不能替代安全边界。

## API 与错误处理

开户请求增加 `wecomIntegrationMode`。企微配置读模型增加不可变模式、配置所有者和配置完成度。第三方配置使用专用写入/轮换端点；自建模式调用该端点返回模式不匹配。

治理读模型增加 `availableActions` 和 `blockedReasons`，且不包含密码、MFA 秘钥、激活令牌或任何凭据密文。业务错误使用稳定机器码；前端将其映射为中文可操作反馈。旧错误不得跨租户或跨弹窗生命周期残留。

## 测试与验收

测试先行覆盖：

- 开户模式必选、合法枚举、幂等指纹和事务回滚。
- 新旧租户模式回填及模式不可变。
- 自建与第三方配置入口、凭据来源和租户隔离。
- pending 企业绑定下的访问档案、租户级超级管理员作用域和主要查询空结构。
- 治理动作矩阵、唯一超管、未激活、停用、恢复、替换、并发版本与请求键隔离。
- SaaS 表单、详情状态、空候选、错误清理和 Dashboard 企业资料条件渲染。

完成后运行相关 Go/前端测试、`go test ./... -count=1`、四前端 lint/typecheck/test/build、RBAC 与迁移合同、Provider completion、Dashboard 页面证据和 `git diff --check`。最终使用独立 Docker 项目迁移并启动，创建未配置的自建与第三方本地验收租户，实际登录 Dashboard 做全路由巡检和重点页面点击；SaaS 重点验收开户模式、第三方配置和超级管理员治理的所有状态。
