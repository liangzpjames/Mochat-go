# 员工移动端参考图高还原重构设计

## 1. 结论与范围

本轮在既有 `web/apps/sidebar` 员工移动侧边栏基础上，采用“视觉完整复刻、业务数据真实”的方案重构。目标不是继续调整现有八宫格，而是把根页面重建为参考图中的“客户 / 会话 / 我的”三工作区，并以相同的视觉语言改造客户详情、联系人列表、素材、SOP、批量加好友和授权恢复页面。

保留既有 12 条路径、`/sidebar-app` 部署前缀、员工 JWT 和企业微信 JS-SDK 安全语义。根路径通过查询参数承载工作区：`/?tab=customers`、`/?tab=conversations`、`/?tab=profile`；缺省为“客户”。这不会新增或破坏历史路径。

用户已授权为仓库中已经存在、但 Sidebar 尚未提供的真实数据新增员工专用接口。接口必须从当前员工身份派生 `employee_id` 与 `corp_id`，禁止复用 Dashboard 管理员会话或相信客户端传入的企业、员工范围。

以下能力继续明确排除：真实企业微信会话存档、敏感词命中、风险行为、订单/商机系统以及 Phase 7。没有上游数据的能力不会用固定数字、随机结果或测试夹具伪装为生产功能。

## 4. 新增真实 API 设计

### 4.1 `GET /sidebar/workbench/summary`

响应：

```json
{
  "employee": {
    "id": 7,
    "name": "员工甲",
    "avatar": null,
    "departmentNames": ["销售部"],
    "corpName": "示例企业"
  },
  "customers": {
    "total": 0,
    "addedToday": 0,
    "taggedTotal": 0,
    "ownedRoomTotal": 0
  },
  "tasks": {
    "contactSopPending": 0,
    "roomSopPending": 0,
    "batchAddPending": 0
  }
}
```

所有计数允许为真实的 `0`，但必须由 SQL 聚合得到：`total` 为当前员工未删除客户关系中的去重客户数；`addedToday` 按服务端配置时区统计当天建立的未删除关系；`taggedTotal` 为当前员工至少拥有一个有效企业标签的去重客户数；`ownedRoomTotal` 为当前员工担任群主且未删除的客户群数。查询至少绑定员工表未删除、员工 `corp_id`、客户关系 `employee_id + corp_id + deleted_at`、标签/客户/群/任务自身 `corp_id`。不得接受客户端的 `employeeId` 或 `corpId` 覆盖身份。

### 4.2 `GET /sidebar/workContact/index`

查询参数：`keyword`、`page`、`perPage`，其中 `perPage` 上限为 50。响应包含分页、联系人 ID、外部联系人 ID、姓名、头像、备注、关系状态、添加时间和标签摘要。

列表只返回当前员工在同企业内持有且未删除的客户关系。不能直接代理 `/dashboard/workContact/index`，也不能继承 Dashboard 的部门 RBAC 语义。

### 4.3 `GET /sidebar/workbench/tasks`

查询参数：`kind=contactSop|roomSop|batchAdd`、`state=pending|done`、`page`、`perPage`。返回统一任务摘要：`id`、`kind`、`title`、`subjectName`、`scheduledAt`、`state`。

每类任务必须通过现有任务日志/分配表验证当前员工和企业范围；查不到、越权或已删除时不得返回。详情继续调用既有 `/contactSop/getSopInfo`、`/roomSop/getSopInfo`、`/contactBatchAdd/detail`。

### 4.4 错误与兼容

- `401`：员工会话失效，回到 `/login` 并保留安全内部目标。
- `403`：身份有效但无当前资源权限。
- `404`：员工、客户或任务不存在于当前企业范围。
- `422`：参数格式错误。
- `500/503`：展示分区错误与重试，不把失败当作零。
- 接口只新增，不修改既有字段语义；无需数据库迁移，优先使用既有索引。若真实 Schema 缺少必要索引，只能新增可回滚索引迁移，不能改写业务数据。

## 5. 视觉语言

- 基准画布按 390×844 设计，同时覆盖 360×800、430×932、320×568 和横屏。
- 网页内容不绘制手机状态栏和企业微信原生导航，避免在真实 WebView 中形成双标题；浏览器证据将参考图裁去原生栏后再对照网页内容区。
- 页面背景使用接近参考图的浅蓝灰；内容面板为纯白，主卡圆角约 14–16px，内部卡圆角约 12px，阴影低对比。
- 标题层级为 28/22/18/16px，正文 14–16px；减少当前页面中过多的小号说明文字。
- 横幅采用仓库内原创 SVG/渐变插画，不直接裁剪参考截图，也不依赖外部 CDN。
- 快捷入口使用各业务专属的彩色渐变 SVG 图标；不再使用相同的四宫格线框图标。
- 数据卡保持两列，但内容较少时使用整行列表而非强行卡片化。
- 底部导航固定三栏，图标 26–28px、文字 13px，包含 `env(safe-area-inset-bottom)`。
- 所有操作目标最小 44×44px；悬浮按钮避开底栏和安全区；表单聚焦时固定操作栏随视觉视口上移。

## 6. 组件边界

Sidebar 专用组件：

- `SidebarWorkspaceShell`：三工作区标题、横幅、底栏和安全区。
- `SidebarHeroBanner`：客户/会话的原创插画横幅。
- `MetricCard`、`ShortcutGrid`、`TaskSection`：真实数据概览与业务入口。
- `EmployeeProfileCard`、`SettingsList`：我的工作区。
- `EmployeeContactList`：搜索、分页、空态与客户跳转。

`@mochat/mobile-foundation` 只在确有 Operation 共用价值时补充颜色 token、视觉视口/安全区工具和无业务含义的列表容器；客户、SOP、员工和工作区逻辑不得进入共享包。

## 7. 状态机与交互

每个分区独立使用 `idle → loading → ready|empty|unavailable|error → retrying`，避免一个统计接口失败导致整页不可用。写操作使用 `ready → submitting → success|partial|error`，提交期间禁用重复动作。

- 根工作区切换更新 `tab` 查询参数，刷新和返回后保持选择。
- 搜索在提交或 300ms 防抖后请求；新请求开始时废弃旧响应，避免竞态覆盖。
- 列表滚动位置在详情返回后恢复。
- 未接入模块可点击查看原因，但不会展示假数字或假成功。
- 清理缓存只删除 Sidebar 自己的会话键和本地 UI 偏好，不清理浏览器或其他 Mochat 端数据。

## 8. 测试与验收标准

1. 测试先行：先新增失败的 API 权限、SQL 范围、契约解析、工作区状态与视觉布局测试，再实现。
2. 4 张参考图分别产生同尺寸裁切的“参考图—实现图”证据；人工复核信息层级、卡片比例、颜色、图标、底栏和空白节奏。
3. 360×800、390×844、430×932 下三工作区首屏主体不出现横向滚动；320×568 可滚动使用；844×390 聚焦表单不被遮挡。
4. 客户列表验证真实内容、空态、加载、错误重试、长名称、分页、搜索、返回与滚动恢复。
5. 工作台数字必须可追溯到同企业、当前员工 SQL；接口错误不得显示为 `0`。
6. 12 条既有路径全部可达；授权类路径不因视觉改造弱化鉴权。
7. 所有按钮和导航触控目标不小于 44×44px，无未处理 Promise、控制台错误、横向溢出和底部遮挡。
8. Sidebar、mobile-foundation、相关 Go 包、移动基础门禁、生产构建、Docker 和浏览器 E2E 全部通过后才可交付。

## 9. 迁移、兼容与回滚

- 保持历史路径和参数兼容；旧的根页面入口通过 `tab` 查询参数逐步替换，无数据库数据迁移。
- 新 API 为增量路由，旧客户端不会调用；出现问题时可分别回滚前端工作区、接口 handler 和 store 查询。
- Docker 只重建 `app`，保留 MySQL、Redis 和全部命名卷。
- 当前分支基线仍为 `b9a47cab45ec872bc81e61a20b06a8a3529311b2`，`origin/main` 已推进；最终集成前需显式变基或挑选提交并重跑全部门禁，不能直接把本分支验收结果外推到主线。

## 10. 非目标再次确认

- 不修改 Operation、Dashboard UI、SaaS Admin 或监督台账。
- 不实现或伪造会话存档、风险行为、敏感词、订单、商机和客服在线状态。
- 不把 Review Server 固定夹具打入生产 bundle。
- 不用截图裁片冒充可访问控件，不用静态数字冒充数据库聚合。
