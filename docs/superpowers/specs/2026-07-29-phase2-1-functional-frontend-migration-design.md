# Phase 2.1 前端功能迁移设计

## 1. 背景

Phase 2 已完成 Dashboard、Sidebar 和 Operation 的 React 路由接管、静态托管、构建发布和截图门禁，但大部分路由仍由通用页面承接。Phase 2.1 负责把旧 Vue 源码中现有的页面功能迁移到 React，使每个页面具备可浏览、可点击、可验证的基础业务能力。

旧 Vue 参考源码固定使用：

- `web/legacy/dashboard`
- `web/legacy/sidebar`
- `web/legacy/operation`

Phase 2.1 不机械复制 Vue 文件结构和视觉实现。业务字段、接口、权限和操作语义以旧 Vue 为基线，界面与组件按照当前 React 技术体系重新组织。

## 2. 目标

Phase 2.1 完成后：

- Dashboard 61 条、Sidebar 12 条、Operation 10 条 manifest 路由全部由明确的 React 功能模块承接。
- 旧 URL、查询参数、hash 和深链继续兼容。
- 列表、详情、筛选、分页、表单、弹窗、抽屉、步骤和状态操作具备基础可用性。
- 每个适用功能至少完成一次新建、查看、编辑、状态变更和删除闭环。
- Dashboard 可通过真实本地账号进入完整工作台。
- Sidebar 和 Operation 可通过 fake OAuth 进入真实业务页面。
- 所有页面都经过人工浏览器打开和基础点击验证。
- 通用迁移占位页不再承接业务路由。

Phase 2.1 通过前不得开始 Phase 3。

## 3. 非目标

- Phase 2.1 不要求所有页面接入真实企业微信或微信开放平台。
- Phase 2.1 不要求视觉像素级复刻旧 Vue。
- Phase 2.1 不重新设计旧系统中不存在的新业务能力。
- Phase 2.1 不以 mock 前端请求替代真实 Go API 链路。

外部平台调用使用可控 fake 服务完成确定性验收。浏览器到 Go API、Go API 到 MariaDB/Redis 的链路必须真实运行。

## 4. 实施分解

Phase 2.1 拆成三个可独立验收的子项目：

1. Dashboard 后台业务功能迁移。
2. Sidebar 企业微信聊天侧边栏迁移。
3. Operation 微信营销活动 H5 迁移。

实施顺序：

1. 共享基础、企业、成员、部门、客户、标签、素材、角色与权限。
2. 欢迎语、群管理、自动拉群、群发、SOP、敏感词。
3. 渠道活码、门店活码、雷达、抽奖、自动标签、裂变和群运营。
4. Sidebar 客户、素材和 SOP 页面。
5. Operation 任务宝、群裂变、抽奖、群打卡、门店活码等活动页面。

每个功能域完成后立即独立测试和浏览器验收，不等待所有页面一次性完成。

## 5. React 架构

采用 feature-based 组织方式。目录按功能复杂度渐进拆分，不强制简单功能创建无意义文件。典型复杂功能结构：

```text
features/contact-message-batch/
  api.ts
  types.ts
  schemas.ts
  query-keys.ts
  routes.tsx
  pages/
  components/
  forms/
  tests/
```

职责边界：

- API 模块只负责 Go API 调用、请求参数和响应转换。
- 领域类型隔离旧接口的临时字段结构。
- schema 统一表单默认值、验证和提交转换。
- 查询键集中管理缓存边界。
- 路由模块把旧 URL 和深链映射到 React 内部视图。
- 列表、详情、新建和编辑复用领域组件和表单。
- 简单功能可以合并文件；出现多页面、多数据源或多种写操作时再拆分。
- Dashboard、Sidebar 和 Operation 可以共享基础组件与领域契约，但不能互相依赖页面组件。

共享基础包括：

- 分页表格和筛选栏。
- 加载、空数据、错误和无权限状态。
- 状态标签、确认操作和反馈消息。
- 素材、员工、客户、客户群和标签选择器。
- 上传、预览和素材引用。
- 权限感知按钮和路由边界。

所有业务路由必须映射到明确功能模块。Phase 2.1 审计禁止业务路由重新指向通用迁移页。

## 6. 旧 URL 兼容策略

React 内部按功能组织，不按 Vue 文件逐页复制。旧系统的列表、新建、编辑、详情和统计 URL 可以收敛到同一功能模块，通过路由状态、抽屉、弹窗或页内步骤展示。

兼容要求：

- 所有旧 URL 可以直接打开。
- 必需的实体 ID、活动 ID 和来源参数继续生效。
- query 和 hash 在跳转、刷新和返回后不丢失。
- 可分享页面的筛选、分页、详情和当前标签保存在 URL。
- 不再使用的旧 URL 必须明确重定向到等价视图，不能静默落到首页。

## 7. 单功能迁移流程

每个功能域按以下流程迁移：

1. 从旧 Vue 源码提取路由、页面状态、字段、按钮、接口、权限、跳转、弹窗、资源和异常行为。
2. 核对 Go API 契约。缺少接口或字段时先补齐后端，不在前端写死业务数据。
3. 建立稳定的 TypeScript 领域模型和旧接口响应转换。
4. 实现列表、筛选、详情、创建、编辑和状态操作。
5. 建立验收数据和 fake 外部平台响应。
6. 完成组件测试、API 契约测试和浏览器测试。
7. 人工打开该功能的每个旧 URL，执行基础点击和代表性写操作闭环。
8. 保存验收结果后，才在功能矩阵中标记完成。

## 8. 数据流

统一数据流：

```text
页面路由
→ 功能模块
→ React Query hook
→ 领域 API
→ Go API
→ MariaDB/Redis 或 fake 外部平台
```

约束：

- 页面不得直接调用 `fetch`。
- 服务端状态由 React Query 管理。
- 表单临时状态保留在组件内，不引入全局业务状态仓库。
- 企业、用户、权限和认证会话由应用级 Provider 管理。
- 写操作成功后精准刷新相关查询，不清空全部缓存。
- 文件、素材、员工、客户和客户群选择器返回稳定 ID。
- API 响应在功能域边界转换，页面不依赖旧接口的偶然字段结构。

## 9. 错误处理

- `401`：清理会话并安全返回登录页。
- `403`：显示无权限页面或禁用具体操作。
- `404`：区分路由不存在和业务数据不存在。
- `409`：保留用户输入，提示数据已变化并提供重新加载。
- `422` 或业务校验失败：映射到表单字段或明确页面提示。
- `5xx` 或网络失败：展示可重试状态，不丢失未提交表单。
- fake 外部平台失败：使用真实外部失败结构，展示原因和重试入口。
- 未知异常：进入应用错误边界并记录路由、功能和请求标识。

日志和错误证据不得包含密码、Token、密钥、验证码或完整敏感凭据。

## 10. 测试策略

每个功能域必须通过四层验证：

1. 静态门禁：ESLint、TypeScript、依赖策略和生产构建。
2. 组件测试：加载、空状态、错误状态、权限、表单验证和关键交互。
3. API 契约测试：请求方法、参数、分页、响应转换、错误码及租户/企业隔离。
4. 浏览器验收：真实 Go、MariaDB、Redis、验收数据和 fake 外部平台。

功能域的测试必须能够独立运行。共享基础变更还需运行所有依赖该基础能力的功能测试。

## 11. 浏览器验收

每个旧 URL 的验收记录至少包含：

- 输入 URL、最终 URL、页面标题和主要可见内容。
- 已点击的筛选、分页、标签页、按钮、弹窗、抽屉和步骤。
- 适用的新建、查看、编辑、状态变更和删除结果。
- 网络请求摘要及非预期 `4xx/5xx` 数量。
- console error 和 warning。
- 桌面端截图。
- Sidebar 和 Operation 的移动端截图。
- 不适用操作及原因。

通过标准：

- 非预期 `4xx/5xx` 为 0。
- console error 为 0。
- warning 清零或逐条记录并获得明确接受。
- 页面没有空白、溢出遮挡、不可点击控件或错误跳转。
- 表单必填、错误提示、空状态、加载状态和无权限状态可识别。
- 每个功能的代表性写操作能够完成并在页面中看到结果。

## 12. 功能完成矩阵

Phase 2.1 维护逐功能矩阵，至少包含：

- 应用和功能域。
- 旧 Vue 来源文件。
- 旧 URL。
- React 模块。
- Go API 契约。
- 读操作状态。
- 写操作状态。
- 权限状态。
- fake 外部平台状态。
- 组件测试状态。
- 浏览器验收状态。
- 截图和问题链接。

矩阵不得以路由能渲染代替功能完成。`placeholder`、`route-only` 和未说明的跳过项均阻塞 Phase 2.1 完成。

## 13. Phase 2.1 最终门禁

Phase 2.1 只有同时满足以下条件才可完成：

- Dashboard 61 条、Sidebar 12 条、Operation 10 条路由全部映射到明确功能模块。
- `MigratedDashboardPage`、Sidebar 通用页和 Operation 通用页不再承接业务路由。
- 功能矩阵没有 `placeholder`、`route-only` 或未说明跳过项。
- 所有适用功能完成基本读取和写入闭环。
- 所有旧 URL 完成人工浏览和基础点击。
- fake 外部平台验收可重复执行。
- Dashboard 真实本地登录和工作台可用。
- Sidebar 和 Operation fake OAuth 业务入口可用。
- 四个前端完成 lint、typecheck、test 和生产构建。
- 浏览器验收不存在非预期请求错误或控制台错误。

只有该门禁通过后，Phase 3 才能开始。
