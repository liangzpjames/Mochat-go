# Dashboard 全局退出能力设计

## 背景

Dashboard 登录用户没有可用企业时，`CorpProvider` 直接渲染“暂无可用企业”，导致 Dashboard 布局和账号操作完全不可见，用户无法主动退出。正常业务页面也缺少统一的账号退出入口。

## 目标

- 无可用企业时展示清晰的空状态、当前登录账号提示和退出按钮。
- 正常 Dashboard 顶部栏始终提供退出入口。
- 退出时优先通知服务端注销当前会话；无论服务端请求成功与否，都必须清除本地会话并返回登录页。
- 会话操作与企业选择、页面布局解耦，便于后续扩展个人资料和切换账号。

## 设计

新增 Dashboard 会话操作上下文，由应用入口注入当前用户标识和统一 `logout` 方法：

1. `logout` 调用 `PUT /dashboard/user/logout`。
2. 在 `finally` 中清除本地认证信息、清空查询缓存并跳转 `/login`。
3. `DashboardLayout` 从上下文读取会话信息，在顶部栏显示账号和退出按钮。
4. `CorpProvider` 在企业列表为空时使用同一上下文渲染居中的空状态卡片和退出按钮。

上下文本身不直接依赖浏览器存储、API 客户端或路由器，所有副作用由应用入口注入。

## 错误处理

- 服务端注销失败不能阻止本地退出。
- 退出进行中禁用按钮，避免重复请求。
- 空状态保留明确说明，提示用户联系管理员分配企业权限。

## 测试与验收

- 单元测试验证空企业状态包含退出按钮并调用统一退出方法。
- 单元测试验证正常 Dashboard 顶部栏包含账号和退出按钮。
- 单元测试验证服务端注销失败时仍清理本地会话并跳转登录页。
- 构建并重新部署后，在真实浏览器分别验证空企业状态和退出后的登录页。
