# Phase 3.4 第四批素材底座与阶段收尾设计

日期：2026-08-04  
状态：已由执行代理按用户授权自审批准

## 1. 范围与目标

本批完成 `/acquisition/material-management`，并以真实素材 Provider 支撑活码、精准群发和朋友圈的统一素材选择。页面覆盖公共、部门、个人素材与聊天侧边栏可见性，提供分组、查询、新增、移动、批量删除、引用检查和状态反馈。完成后执行 Phase 3.4 九页全量回归、Docker 部署、浏览器验收、截图和 manifest 更新。

## 2. 方案决策

复用现有 `mc_medium`、`mc_medium_group`、`MediumHandler`、`MediumGroupHandler` 与上传存储账本，不建立第二套素材库。为现有素材增加兼容性字段：

- `scope_type`：`public`、`department`、`personal`；旧数据默认 `public`。
- `scope_id`：部门 ID 或个人用户 ID；公共素材为 `0`。
- `sidebar_visible`：是否允许聊天侧边栏选取。
- `status`：`processing`、`available`、`failed`、`disabled`；旧数据默认 `available`。

所有读取继续从认证会话获取 `corp_id`，不接受客户端提交企业 ID。个人作用域只允许当前用户读取和写入；部门作用域依据当前员工所属部门或管理员权限；公共作用域沿用企业管理权限。删除和批量删除必须先执行引用检查，被朋友圈、群发、欢迎语或活码引用的素材返回 `409`，不得硬删除。

## 3. 后端契约

沿用并规范以下接口：

- `GET /dashboard/medium/index`：支持 `searchStr`、`mediumGroupId`、`type`、`scopeType`、`status`、`sidebarVisible`、`page`、`perPage`。
- `POST /dashboard/medium/store`：新增文本素材；文件类素材复用 `/dashboard/common/upload` 后保存路径与元数据。
- `PUT /dashboard/medium/update`：编辑名称、内容、作用域、侧边栏可见性和分组。
- `PUT /dashboard/medium/groupUpdate`：移动单条素材分组。
- `POST /dashboard/medium/batchGroupUpdate`：批量移动。
- `POST /dashboard/medium/referenceCheck`：返回引用来源与是否允许删除。
- `DELETE /dashboard/medium/destroy`、`POST /dashboard/medium/batchDestroy`：引用检查通过后软删除。
- `GET/POST/PUT/DELETE /dashboard/mediumGroup/*`：分组查询、创建、编辑、删除并重分配素材。
- `GET /dashboard/materialSelector/index`：为朋友圈、群发、活码和聊天侧边栏提供稳定的只读选择合同，仅返回 `available` 且符合可见范围的素材。

批量写入必须在同一事务中按企业隔离处理；部分 ID 不存在、越权或被引用时整体失败并返回可解释的 `409`/`403`，不产生半成功状态。

## 4. 前端信息架构

页面采用圆弧式素材工作台结构：顶部标题和容量/Provider 状态；主标签为公共素材、部门素材、个人素材、聊天侧边栏；左侧分组树，右侧为类型与关键字筛选、批量工具栏和素材卡片/表格。新增素材使用右侧抽屉，先交付真实文本素材与已上传文件路径登记，未具备的外部同步明确显示状态而不伪成功。

核心交互包括：

- 查询、重置、标签与分组切换；URL 保留 `scope`、`group`、`type`、`keyword`。
- 新增文本素材、创建分组、移动分组、批量移动与批量删除。
- 删除前展示引用检查结果；被引用时禁用确认并列出来源。
- 保存期间锁定字段；脏数据关闭确认；焦点进入、循环和关闭恢复。
- 加载、空数据、筛选无结果、无权限、冲突、网络失败和重试状态。
- 窄屏下分组树折叠为顶部选择器，抽屉占满可用宽度。

## 5. 数据流与复用

React 页面通过现有 `BusinessWorkbenchApi` 调用 Dashboard 路由；响应适配器统一旧 envelope、分页、类型与内容摘要。统一素材选择接口返回 `id`、`name`、`type`、`contentPreview`、`group`、`scope`、`status` 和 `sidebarVisible`，其他营销页面只保存素材 ID 与必要快照，不复制素材内容。

聊天侧边栏继续复用 `/sidebar/medium/index`，但只返回 `sidebar_visible=1` 且当前员工有权访问的素材。外部企业微信临时 media ID 刷新仍由现有 Provider 完成。

## 6. 测试与验收

严格按 TDD 执行：先增加 Go handler/store/迁移合同测试与 React 页面测试并观察失败，再实现最小闭环。至少覆盖企业隔离、个人/部门可见性、批量事务、引用冲突、素材选择合同、页面新增/筛选/移动/删除、抽屉键盘交互和失败重试。

最终门禁包括 Go 单元与集成测试、Dashboard typecheck/lint/Vitest/build、53 页 benchmark、Phase 3.4 九路由注册、Docker `readyz`、数据卷确认，以及 1440×900 浏览器新增、刷新持久化、分组移动、引用阻断和截图。

## 7. 完成边界

本批不伪造文件上传、企业微信同步或素材引用。若现有上传 Provider 可用则复用；不可用时只允许文本素材写入并明确阻断文件提交。Phase 3.4 只有在九页门禁全部通过、素材管理不再是 placeholder、manifest 证据完整后才能标记阶段完成；朋友圈正式发布 Provider 仍是独立遗留项，不因素材底座完成而伪装为已发布能力。
