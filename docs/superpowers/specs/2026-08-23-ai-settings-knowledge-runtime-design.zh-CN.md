# AI 设置知识库运行链路与默认会话分析助手设计

## 1. 目标与产品决策

本轮把现有“知识库元数据 + 无消费者智能体”改造成可被 AI 洞察实际消费的闭环：

1. 知识库支持真实文档上传、解析、状态展示、删除与刷新后持久化；文档数只由持久化文档记录统计，不再允许人工填写。
2. 每个租户企业固定且仅有一个系统智能体“会话分析助手”。用户不能新增、改名或删除，只能维护分析说明、启停状态和关联知识库。
3. AI 洞察“会话分析”在每日分析任务中读取该助手。启用时使用其分析说明，并从已启用知识库的解析成功文档中检索有限上下文；停用时诚实停止生成新的会话分析。
4. AI 洞察页面展示当前助手、启停状态、关联知识库和可用文档数，让配置用途在消费页面可见。

本轮不扩展 Phase 7、不实现真实企微会话存档、不增加用户自定义智能体、不建设模型市场、工具编排或通用向量数据库。

## 2. 现状证据

### 2.1 仓库现状

- `mochat_go_ai_knowledge_bases.document_count` 由前端表单人工填写；没有文档表、文件存储、解析结果或检索合同。
- `mochat_go_ai_agents` 允许任意新增、编辑、启停和删除，但仅保存名称、说明和知识库 ID。
- `ConversationAnalysisRunner` 使用固定系统提示词，来源指纹只包含会话消息；它不读取智能体或知识库。
- 因此当前两页虽然 CRUD 真实持久化，但对 AI 洞察输出没有任何影响。

### 2.2 圆弧 AI 登录态调研

已真实点击 `AI 设置 → AI 知识库 → 管理 → 文件知识 → 添加 → 文件`：

- 知识库主列表展示名称、描述、关联智能体、更新时间、文档数和管理入口。
- 文档管理弹层提供文件知识/问答对分组、名称与状态筛选、同步、添加和批量操作。
- 文件上传明确支持 `.pdf/.doc/.docx`、单文件不超过 60 MB；文档列表展示“添加成功”等处理状态。
- 智能体页以固定能力卡片为主，没有强调任意创建；“会话分析助手”作为系统用途出现。
- AI 洞察“会话分析”本身未清晰展示使用了哪个智能体，这是本轮在 MoChat 中主动补足的可解释性。

圆弧的业务层级值得参考，但其宽屏横向溢出、多层弹层和关闭行为不一致不复制。MoChat 继续使用当前 Dashboard 已验收的页面壳、筛选区、卡片、表格、对话框、分页、反馈和响应式规则。

## 3. 方案比较

### 方案 A：只上传和保存原文件

实现成本最低，但 AI 洞察不能读取内容，仍然只是“有文件、没作用”，不满足目标。

### 方案 B：本地解析、分块和确定性相关度检索（采用）

上传后在服务端解析文本、持久化文档与分块；会话分析根据当前会话内容对有限候选分块做确定性相关度排序，把最高相关且受长度预算约束的内容注入模型请求。无需外部向量服务或新凭证，能够在现有部署中真实闭环，并能通过测试证明数据来源。

### 方案 C：向量嵌入与语义检索

效果上限更高，但需要新增 embedding Provider、模型合同、向量索引、凭证、容量与重建任务，显著扩大范围。本轮不采用；未来可在不改变页面合同的前提下替换检索实现。

## 4. 文档能力边界

### 4.1 支持格式

首期支持：

- `.txt`、`.md`：仅接受有效 UTF-8 文本；
- `.docx`：使用 ZIP/XML 标准结构读取 `word/document.xml`；
- `.pdf`：使用纯 Go PDF 文本提取库读取文字层。

明确不支持：旧二进制 `.doc`、加密文档、损坏文档、只有扫描图片且无文字层的 PDF。前后端均展示具体可操作错误，绝不把“已保存文件”伪装成“可用于分析”。

### 4.2 限额与解析

- 单文件上限 20 MB；单知识库最多 100 个未删除文档。
- 单文档最多保留 500,000 个 Unicode 字符；超限拒绝，不静默截断。
- 分块以约 1,200 字符、100 字符重叠生成；每块记录顺序和内容。
- 原文件保存到 `FileStorageRoot` 的同卷私有兄弟目录 `ai-knowledge-private`，不位于 `/static/` 可公开访问目录。
- 对象键由服务端生成，只包含 tenant/corp/knowledge-base/document 标识；原始文件名仅作为显示元数据并经过路径清理。
- 上传先写临时文件并完成格式校验、解析和分块，再原子移动到最终私有路径并写数据库；任一步失败都清理临时文件且不返回伪成功。

### 4.3 文档状态

文档记录只存在两种持久化状态：`ready`（解析成功，可检索）与 `failed`（原文件已安全保存但解析失败，不参与检索）。解析失败响应明确返回失败状态和安全错误摘要；用户可删除失败记录后重新上传。文档数区分“全部文档”和“可用于分析”。

## 5. 数据模型与 API

新增迁移 `0156_ai_settings_knowledge_runtime`：

- `mochat_go_ai_knowledge_documents`：tenant、corp、knowledge_base_id、文件名、扩展名、MIME、对象键、字节数、SHA-256、状态、错误摘要、字符数、分块数、创建/更新/软删与操作者。
- `mochat_go_ai_knowledge_chunks`：tenant、corp、knowledge_base_id、document_id、顺序、内容、字符数。
- `mochat_go_ai_agents.system_key`：系统用途；`session-analysis` 在 tenant+corp 内唯一。

知识库 `document_count` 保留为兼容输出，但查询时由未删除文档聚合计算；创建/更新请求中的旧 `documentCount` 字段可被兼容接收但完全忽略，不再写入业务值。

新增真实接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/dashboard/ai-settings/knowledge-bases/{id}/documents` | 当前企业内文档列表 |
| `POST` | `/dashboard/ai-settings/knowledge-bases/{id}/documents` | multipart 单文件上传、解析和持久化 |
| `DELETE` | `/dashboard/ai-settings/knowledge-bases/{id}/documents/{documentId}` | 删除文档、分块和私有原文件 |

智能体接口收敛：

- `GET /dashboard/ai-settings/agents` 确保并只返回系统“会话分析助手”；
- `PUT /dashboard/ai-settings/agents/{id}` 只允许更新说明、知识库关联和启停；名称固定；
- `POST` 与 `DELETE` 不再注册，返回真实 405，不提供前端入口；
- 旧自定义智能体记录原样保留在数据库但不再显示或运行，避免破坏性删除。

## 6. 会话分析消费模型

### 6.1 运行时加载

`ConversationAnalysisRunner` 仅在 `AnalysisTypeSession` 时加载系统助手：

1. 若没有记录，则幂等创建默认“会话分析助手”；
2. 若助手停用，记录本次会话分析运行失败原因，不调用 AI Provider；
3. 把助手说明作为受边界包裹的企业分析指导，不能覆盖“只依据证据、合法 JSON”等系统安全约束；
4. 只读取助手关联的、已启用知识库下状态为 `ready` 的分块；
5. 从最多 2,000 个候选块中按会话文字的中文双字片段、字母数字词和标题命中确定性打分，最多选 8 块、总计不超过 12,000 字符；
6. 知识内容只作为业务背景，不能成为 `evidenceMessageIds`；分析证据仍只能引用真实会话消息 ID。

### 6.2 重新分析与指纹

知识库或助手修改必须影响运行结果。运行时生成 `settingsFingerprint`（助手更新时间、状态、关联知识库及 ready 文档 SHA-256 的稳定哈希），与原会话消息指纹组合为有效来源指纹。即使会话消息未变化，只要设置或文档变化，下一次任务仍会重新分析；完全无变化时继续跳过重复调用。

### 6.3 Provider 诚实边界

上传、解析和检索不依赖外部 AI Provider，可以独立成功。真正生成 AI 洞察仍要求现有 Provider 状态为 ready；未配置凭证时继续返回/记录现有明确失败，不宣称分析通过。

## 7. 页面交互

### 7.1 AI 知识库

- 主列表保留关键词、状态、URL 分页、新增、编辑、启停和删除。
- 移除“登记文档数”输入，列表改为真实“可用/全部文档数”。
- 每行新增“管理文档”，打开宽对话框；包含文件名/状态筛选、真实文档表格、上传按钮、失败原因、删除确认和分页。
- 上传使用原生文件选择器，选择后明确展示名称、大小和支持格式；保存中防重复；成功后刷新文档与知识库统计；失败保留弹层并展示机器码映射反馈。
- 删除知识库时若有关联智能体或未删除文档，由后端拒绝并提示先解除/清空，避免隐式级联丢失。

### 7.2 会话分析助手

- 页面只展示一个系统卡片，固定名称“会话分析助手”，说明“用于 AI 洞察 / 会话分析”。
- 不显示新建、删除、关键词筛选或无意义分页。
- 编辑允许填写“分析说明”、选择已启用知识库和启停；同时展示关联知识库的可用文档数。
- 停用确认明确说明会停止新的会话分析，但不删除历史洞察。

### 7.3 AI 洞察会话分析

- 页面头部增加助手运行摘要：名称、启停、关联知识库数量、可用文档数量、最后配置时间。
- 停用或配置读取失败使用明确状态，不把旧分析结果冒充最新生成结果。
- 页面仍只读取持久化洞察，不在打开页面时触发模型调用。

### 7.4 弹层和响应式

- 复用 `DashboardDialog` 与 `ConfirmAction`；关闭按钮、遮罩、Escape、焦点恢复和脏数据确认保持一致。
- 2560×1440、1366×900 下填满工作区；窄屏筛选纵向排列，文档表格局部滚动；390×844 和小高度下弹层内容与底部按钮均可达。

## 8. 权限、租户与安全

- tenant、corp、actor 只来自登录 principal；所有知识库、文档、分块和助手 SQL 都包含 tenant+corp 范围。
- 文档嵌套路由先验证父知识库属于当前范围，再访问文档；不能通过 ID 猜测跨企业读取或删除。
- 文件扩展名、声明 MIME 和实际内容结构共同校验；文件名使用 `filepath.Base`，最终路径验证必须位于私有根目录。
- 文档内容不通过列表 API 返回，不写入审计；审计只记录实体、动作和字段名。
- 新文档路由加入 `dashboard.ai_setting.knowledge_base` 的 API 资源；AI 洞察摘要通过自身 workspace API 返回，不要求用户额外拥有 AI 设置页面权限。
- 助手说明属于低优先级业务指导，服务端固定安全提示词始终优先，防止上传文档或说明改变 JSON 合同、证据边界或系统角色。

## 9. 验收标准

- 四种支持格式均有解析单测；旧 `.doc`、超限、路径穿越、损坏/扫描 PDF、跨企业访问均有失败测试。
- 上传后文档与分块真实入库，知识库计数由查询聚合；刷新后仍存在，删除后不再进入检索且私有文件被移除。
- 每企业始终只返回一个默认助手；POST/DELETE 被拒绝；助手停用与关联知识库能持久化。
- 会话分析请求实际包含助手说明和相关知识块；知识变更会改变有效指纹；知识块不能作为消息证据。
- AI 洞察页面显示助手消费摘要；知识库和助手页面没有虚假能力声明。
- 目标 Go/前端测试、Dashboard 全量测试、typecheck、lint、production build、迁移、RBAC、benchmark、全页面 evidence、`git diff --check` 全部通过。
- 保留卷 Docker 完成 0156 迁移、健康检查、真实登录上传/编辑/启停/删除/刷新持久化与多尺寸浏览器验收；没有有效外部 Provider 凭证时只验收到请求前的配置与诚实受限状态，不宣称模型调用通过。

## 10. 回滚与保护边界

- 代码改动限于 AI Settings、AI Insight 消费摘要/runner、必要 bootstrap/config/RBAC、迁移、前端页面和测试。
- 旧智能体数据保留；不清理或覆盖历史记录。down migration 会删除本轮文档/分块表和 `system_key`，因此只允许在确认不需要保留本轮上传数据时执行。
- 不修改 `docs/PROJECT_PROGRESS.zh-CN.md`、`.workbuddy/`、`tmp/`、调试脚本、旧 `web/saas-admin/` 或 Phase 7；不删除 Docker 卷，不覆盖其他任务成果。
