# 群聊会话圆弧 AI 对标改造设计

日期：2026-08-19  
目标路由：`/chat/v2-group`  
参考路由：`https://web-ai-analysis-work-wechat.yuanhu.com/#/chat/v2-group`  
停止点：完成本设计文档和实施文档后暂停，不进入编码。

## 1. 范围与约束

本轮只改造“会话 → 群聊会话”。菜单导航、应用顶部 Banner、企业切换、全局搜索以及其他页面保持不变；客户会话、员工会话、全局消息、会话轨迹和会话导出不联动重构。

改造必须遵守以下原则：

1. 页面结构以圆弧 AI 的群聊工作台为参照，不在现有全局消息卡片页上继续堆叠控件。
2. 所有群、成员、统计、消息、风险和超时信息必须来自 MoChat 的真实接口与存储。
3. 参考产品存在但 MoChat 不具备的数据能力必须明确显示“未接入”或“数据受限”，不得显示为 `0`。
4. 群名称、成员身份、消息发送人无法确定时使用真实空态或通用身份，不允许根据文案或时间人工猜测。
5. 查询输入只更新前端草稿，点击“查询”或按回车后才访问后端。
6. 分页数量固定，列表、统计、详情和权限使用同一数据口径。
7. 实施遵循测试先行，只重建 Docker `app` 服务，保留 MySQL、Redis 和现有 D 盘数据卷。

## 2. 现状基线

### 2.1 当前 MoChat 页面

`/chat/v2-group` 当前仍由 `ConversationGlobalPage` 以 `fixedConversationType="room"` 渲染，页面结构是：

- 顶部多张会话指标卡；
- 一整行全局搜索条件；
- 三列消息摘要卡片；
- 点击卡片后进入通用详情。

该结构的问题是：

1. 一个客户群会按归档员工拆成多条“员工 → 群”会话，不是以群为主对象。
2. 页面在 2560×1440 下横向铺卡，但无法形成连续的群目录、消息和群资料工作流。
3. 群主、群成员、建群时间、群公告、群状态、已解散群等数据没有进入会话页面。
4. 当前 12 条本地群消息的 `to_user_id=0`，通用查询把它们展示成“群聊 0”。这些消息的 `room_id` 实际保存了正确客户群 ID，属于后端尚未归一化，而不是无数据。
5. 群内入站消息没有持久化发送人的微信 ID，历史记录只能显示“群成员”。

### 2.2 圆弧 AI 有数据状态重新采样

本次在 2026-08-19 对参考页重新采样，外部群数量为 5，其中 1 个群有存档消息、4 个群显示“未存档群聊”。采样到的真实结构为：

1. **左列群目录**
   - “外部群 / 内部群”页签及数量；
   - 群名称搜索和筛选入口；
   - 群卡片展示群名称、最新消息或“未存档群聊”、时间；
   - 固定分页；
   - 底部固定“已解散群”入口。
2. **中间消息主列**
   - 群名称和群备注入口；
   - 刷新、会话下载；
   - 横向消息类型筛选；
   - 消息内容搜索和日期筛选；
   - 沟通天数、历史消息、客户发送、员工发送；
   - 按日期分组的消息气泡流。
3. **右侧固定资料列**
   - 建群时间；
   - 历史消息、客户发送、员工发送；
   - 群成员数量、头像、名称以及群主/员工/客户身份；
   - 超时记录和风险记录。
4. **筛选交互**
   - 筛选以右侧抽屉展开；
   - 条件包括相关员工、相关客户、群类型、解散状态；
   - 员工条件继续打开组织架构选择器，支持组织架构和重点关注；
   - 抽屉底部固定“查询 / 重置”。
5. **未存档群状态**
   - 群仍可被选中；
   - 中间消息区显示“暂无数据”；
   - 右列仍展示建群时间、成员和为零的真实统计。

参考页在 2560×1440 下的主要内容宽度约为：群目录 313px、消息主列约 1688px、资料列约 252px。参考页在 1440×900 下产生横向滚动，本方案只借鉴信息结构，不复制该响应式缺陷。

## 3. 方案选择

### 3.1 方案 A：三列群工作台（采用）

左侧按群选择，中间查看该群的完整消息，右侧持续展示群资料、成员和记录。宽屏充分填充，业务主对象始终是客户群，也最符合重新采样后的参考结构。

### 3.2 方案 B：两列群目录 + 群详情

实现较简单，但会把群成员、统计、风险和超时信息挤入消息主列，无法复现参考页右侧整列的信息层级。重新采样后不再采用。

### 3.3 方案 C：员工 → 群 → 消息三列

可复用员工会话目录，但会把群错误地从属于员工；同一群会重复出现，跨员工的群消息也无法形成单一时间线。不采用。

## 4. 目标信息架构

### 4.1 27 寸宽屏结构

主内容区使用连续三列，不添加顶部介绍框：

```text
┌──────────────── 320px ───────────────┬────────────── minmax(720px, 1fr) ──────────────┬──── 300px ────┐
│ 外部群 / 内部群能力                  │ 群名称、状态、消息查询与刷新                    │ 建群时间       │
│ 群名搜索 [查询][刷新][筛选]          │ 消息类型：全部/文字/图片/语音/视频/文件/链接    │ 消息统计       │
│                                      │ 沟通天数 / 消息总数 / 客户发送 / 员工发送       │ 群成员         │
│ 群卡片（整卡可点）                   │                                                   │ 风险记录       │
│ 群卡片                               │ 按日期分组的完整消息流                           │ 超时记录       │
│ ...                                  │                                                   │ 能力限制提示   │
│ 分页                                 │                                                   │                │
│ 已解散群                             │                                                   │                │
└──────────────────────────────────────┴───────────────────────────────────────────────────┴────────────────┘
```

页面高度为视口减去应用顶部区域和页面外边距，三列各自独立滚动；主工作台本身不出现横向滚动。

### 4.2 群目录列

1. 页签显示“外部群 N”。“内部群”因当前产品能力未接入，显示“内部群 · 未接入”，不能显示 `0`，并禁止发起空查询。
2. 群名称输入框只维护草稿；点击“查询”或回车后更新 URL 和目录请求。
3. “刷新”仅刷新目录查询，放在查询按钮旁边。
4. “筛选”打开右侧抽屉，包含：
   - 相关员工：群主、群内员工或归档关联员工；
   - 相关客户：群成员关系中的客户；
   - 客户群分组：来自真实客户群分组；
   - 群状态：正常、跟进人离职、离职继承中、离职继承完成；
   - 解散状态：未解散、已解散。
5. 群卡片展示：群头像占位、群名称、群主、成员数、最新消息或“未存档群聊”、最新消息时间、群状态短标签。
6. 点击群卡片任意非独立控件区域都选中群；选中状态只使用边框、背景和文字颜色，不使用位移或缩放。
7. 列表固定每页 50 条。底部显示总数、页码、上一页和下一页。
8. “已解散群”固定在左列底部，点击后切换目录模式并显示真实数量。

### 4.3 消息主列

1. 头部展示群名称、外部群标签和状态；群公告只读显示在可折叠的次级信息中，不伪装成“群备注”编辑能力。
2. 不提供当前系统无法完成的“会话下载”按钮。
3. 消息类型采用横向紧凑控件：全部、文字、图片、语音、视频、文件、链接。只展示当前解析器和后端筛选支持的类型。
4. 搜索会话内容采用草稿 + “查询”按钮；“刷新”放在查询按钮旁，仅刷新当前群消息。
5. 日期变化可以直接查询，因为一次交互只产生一个确定请求；消息类型切换也只触发一次请求。
6. 统计使用当前权限范围和当前群的全部归档消息口径，不随关键词、日期或消息类型过滤而变化：
   - 沟通天数；
   - 消息总数；
   - 客户发送；
   - 员工发送。
7. 消息列表按时间正序显示、日期分组，初次加载最近 50 条；“加载更早消息”使用游标追加并去重。
8. 群存在但没有归档消息时显示“该群暂无已归档消息”，不隐藏右侧群资料。
9. 已解散群只读展示历史消息，不提供会造成状态变更的操作。

### 4.4 右侧资料列

右列始终属于当前选中群，不跟随消息关键词或消息类型重新请求。

1. 群概况：建群时间、群主、客户群分组、状态、成员总数。
2. 群统计：历史消息、客户发送、员工发送；值来自与中间统计相同的服务端聚合。
3. 群成员：默认展示最近同步的 50 人，支持“全部 / 员工 / 客户 / 已退出”切换和加载更多；群主、员工、客户、已退出使用短标签区分。
4. 风险记录：展示该群在当前权限范围内最近 10 条真实风险记录，空时显示“暂无风险记录”。
5. 超时记录：展示该群在当前权限范围内最近 10 条真实超时记录，空时显示“暂无超时记录”。
6. 能力限制：使用紧凑提示列出内部群、历史发送人、单群下载等受限能力，不使用大段介绍卡。

## 5. 响应式规则

### 5.1 1600px 及以上

显示三列：`320px minmax(720px, 1fr) 300px`。2560×1440 是主验收尺寸，消息主列必须吃满剩余宽度，右列保持完整高度。

### 5.2 1200–1599px

显示群目录和消息主列，右侧资料列改为可关闭抽屉。消息头部提供“群信息”按钮；抽屉支持关闭按钮、遮罩点击和 `Escape`。不得像参考页一样产生横向滚动。

### 5.3 769–1199px

默认显示消息主列；群目录和群资料分别由两个按钮打开抽屉。没有选中群时直接显示群目录。抽屉遮罩和焦点返回必须可用。

### 5.4 768px 及以下

采用“群列表 → 消息 → 群资料”的分步单列。选择群进入消息页，可返回列表；群资料为全屏抽屉。所有按钮和分页文字保持水平，不出现竖排或缩放模糊。

## 6. URL 与交互状态

业务状态写入 URL，纯视觉抽屉状态不写 URL。

| 参数 | 含义 | 默认值 |
|---|---|---|
| `roomMode` | `active` / `dissolved` | `active` |
| `roomKeyword` | 已提交的群名称关键词 | 空 |
| `roomPage` | 群目录页码 | `1` |
| `roomId` | 当前群 ID | 空 |
| `employeeIds` | 相关员工，可重复 | 空 |
| `customerIds` | 相关客户，可重复 | 空 |
| `roomGroupIds` | 客户群分组，可重复 | 空 |
| `roomStatuses` | 群状态，可重复 | 空 |
| `messageKeyword` | 已提交的消息关键词 | 空 |
| `messageTypes` | 消息类型，可重复 | 空 |
| `messageDate` | `YYYY-MM-DD` | 空 |

规则：

1. 群目录筛选改变时回到第 1 页，并清除已不在结果中的 `roomId`。
2. 选择新群时保留目录条件，但清空消息关键词、类型、日期和历史游标。
3. 输入群名称或消息内容不改变 URL；提交后才更新 URL。
4. URL 中非法枚举、非正整数和不可访问群 ID 使用 `replace` 规范化。
5. 刷新页面后恢复目录条件和选中群，但不恢复打开的抽屉。

| 风险记录 | `roomProfile` | `mochat_go_risk_records` | 表存在则返回最近记录；无记录为空态；表不存在为能力未接入 | 企业、会话和员工范围 |

## 8. 群 ID 归一化

现有群消息不能只使用 `to_user_id`。群消息的有效群 ID 定义为：

```sql
CASE
  WHEN wm.to_user_type = 2
  THEN COALESCE(NULLIF(wm.to_user_id, 0), NULLIF(wm.room_id, 0), 0)
  ELSE wm.to_user_id
END
```

该规则进入共享归档查询层，并覆盖全局消息、员工会话、客户会话和新的群聊工作台，避免同一批消息在不同页面解析成不同群。必须补以下测试：

1. `to_user_id` 有值时优先使用；
2. `to_user_id=0` 且 `room_id` 有值时使用 `room_id`；
3. 两者都为 0 时记入 `unmatchedRoomMessages`，不生成“群聊 0”卡片；
4. 归一化后仍需验证群属于当前企业；
5. 不能根据消息正文推断群 ID。

当前本地 12 条 `SIM-MSG-*` 群消息可通过此规则正确关联到群 3001、3003、3005 和 3006，无需人工改数据。

## 9. 群消息发送人身份补链

### 9.1 问题

归档 bridge 已解析 `from`，但写入 `mc_work_message_*` 时只保存 `sender_type`，没有保存原始发送人微信 ID。对于历史群消息，系统只能知道“外部成员发送”，不能稳定知道是哪位客户。

### 9.2 方案

新增旁表 `mochat_go_work_message_participant_identity`：

```text
id
corp_id
msgid
seq
sender_wx_id
room_wx_id
created_at
updated_at
UNIQUE(corp_id, msgid, seq)
INDEX(corp_id, sender_wx_id)
INDEX(corp_id, room_wx_id)
```

归档写入事务在保存消息时同步 upsert `from` 和 `roomid`。群消息查询按 `corp_id + msgid + seq` 关联旁表，再通过 `mc_work_contact_room.wx_user_id`、`mc_work_contact.wx_external_userid` 和 `mc_work_employee.wx_user_id` 获取名称和头像。

历史记录无法无损回填：

- 能解析时显示真实发送人；
- 无身份时显示“群成员”；
- `capabilities` 返回 `historicalGroupSenderIdentity=false` 及原因；
- 不根据群内只有一个客户等条件进行猜测。

## 10. 后端接口设计

### 10.1 `GET /dashboard/workMessage/roomDirectory`

请求：目录模式、关键词、员工/客户/群分组/状态筛选、页码，`pageSize` 固定 50。

响应：

```text
rooms[]
counts { external, dissolved, internal: null }
total, page, pageSize
unmatchedRoomMessages
limitations[]
capabilities[]
```

`unmatchedRoomMessages > 0` 时左列显示紧凑告警“有 N 条群消息无法关联客户群”。

### 10.2 `GET /dashboard/workMessage/roomProfile`

请求：`roomId`。

响应包含群资料、全量消息统计、成员计数、最近 10 条风险记录、最近 10 条超时记录及 capabilities。该接口不接受消息关键词，避免搜索时反复加载群资料。

### 10.3 `GET /dashboard/workMessage/roomMessages`

请求：`roomId`、关键词、消息类型、日期、`pageSize=50`、可选 `before`。

响应：`messages[]`、`nextBefore`、`hasMore`、消息身份能力。消息按数据库倒序取数，服务端或前端在单页内转为正序；跨页合并按稳定消息 ID 去重。

### 10.4 `GET /dashboard/workMessage/roomMembers`

请求：`roomId`、`mode=all|employee|customer|left`、`page`、`pageSize=50`。

响应：成员列表、各模式计数、总数和页码。已退出成员只在 `left` 模式显示。

### 10.5 `GET /dashboard/workMessage/roomFilterOptions`

请求：`kind=employee|customer|group`、关键词、页码、`pageSize=50`。

响应只包含与当前用户可见群相关的真实选项，供筛选抽屉中的选择器使用。

## 11. 权限模型

1. 所有接口先经过 `dashboard.chat.v2_group` 页面权限和会话存档可用性校验。
2. 企业管理员或租户级数据权限可查看企业内所有客户群消息。
3. 部门/员工范围只能看与允许员工相关的群；消息和统计只聚合允许员工关联的归档记录。
4. 右侧成员中超出员工范围的内部员工不返回姓名和头像；外部客户仅在群对当前用户可见时返回。
5. `roomId` 必须属于当前企业且通过可见群校验，否则返回 404，不暴露跨企业或无权限群存在性。
6. 风险和超时记录同时校验企业、群 ID 和可访问员工会话 ID。

## 13. 加载、空态与错误

1. 首次目录加载：只在左列显示骨架，不能让整个工作台消失。
2. 切换目录条件：保留上一页占位尺寸，防止按钮和列宽抖动。
3. 切换群：消息和资料分别加载，左列保持可操作。
4. 消息筛选：保留当前消息框架和输入焦点，消息区显示轻量加载态。
5. 群无消息：显示“该群暂无已归档消息”，右侧资料照常显示。
6. 群无成员：显示“客户群成员尚未同步”，属于同步/配置异常，不是普通空态。
7. 内部群：显示“内部群会话能力未接入”，不能发送后端查询。
8. 会话存档未开通或不可用：使用现有 `ConversationArchiveState` 阻断消息区，同时允许在权限允许时展示客户群基础资料。
9. 群 ID 无法映射：目录顶部显示条数告警，无法映射的数据不混入正常群列表。
10. 接口错误：错误只替换对应列，提供同语义重试，不清空其他列。
