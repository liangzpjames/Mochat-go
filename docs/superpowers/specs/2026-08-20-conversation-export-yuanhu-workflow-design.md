# 会话导出圆弧式工作流设计

日期：2026-08-20
目标路由：`/chat/export`
参考路由：`https://web-ai-analysis-work-wechat.yuanhu.com/#/chat/export`
停止点：完成本设计文档和实施文档后暂停，不进入代码开发。

## 1. 目标与边界

本轮只改造“会话 → 会话导出”。菜单导航、应用顶部 banner、企业切换、全局搜索以及其他会话页面保持不变。

目标是把当前“查询 100 条会话摘要后由浏览器拼 CSV”的临时能力，升级为可实际交付的会话明细导出流程：

1. 先选择按员工、客户或群聊导出。
2. 再筛选并勾选真实对象。
3. 设置时间范围、会话范围和拆分方式。
4. 由服务端异步生成受权限约束的 UTF-8 CSV/ZIP 工件。
5. 在本页查看任务状态并下载自己的导出结果。

必须遵守以下约束：

- 不增加纯介绍性质的大块顶部卡片。
- 所有候选对象、数量、消息和导出状态来自 MoChat 真实接口与数据库。
- 不复制圆弧 AI 的业务数据、能力状态或数字。
- 无数据、接口缺失、功能未实现、同步/权限异常必须区分。
- 查询输入只更新草稿，点击“查询”或按回车后才访问后端。
- 候选列表和任务列表固定每页 20 条，不开放单页数量选择。
- 不导出媒体文件二进制；图片、语音、视频、文件和链接只导出已归档的类型、文本摘要与可用元数据。
- Docker 只重建必要的 `app` 服务，保留 MySQL、Redis 和 D 盘现有命名卷。

## 2. 当前 MoChat 基线

当前页面由 `web/apps/dashboard/src/features/conversation-global/conversation-export-page.tsx` 渲染，数据来自 `ConversationGlobalApi.search()`，对应 `GET /dashboard/workMessage/toUsers`。

现有流程为：

- 页面加载时读取全局会话摘要，固定请求 `page=1&pageSize=100`；
- 仅支持一个“关键词”条件；
- “导出当前结果”在浏览器内把当前页摘要拼成 CSV；
- CSV 只有会话 ID、员工、对象、类型、最后消息和时间；
- 没有选择对象、日期范围、会话范围、消息明细、任务状态、重试、下载鉴权和工件留存。

主要问题：

1. 导出的不是会话明细，只是最多 100 条摘要。
2. 总数大于 100 时会被静默遗漏，按钮文案仍容易被理解为完整导出。
3. 浏览器端拿到什么就导出什么，无法由后端统一执行数据范围和对象归属校验。
4. 页面沿用已被明确取消的顶部介绍框，并存在单独的右侧刷新按钮。
5. 页面结构与圆弧 AI 的“类型选择 → 对象选择 → 导出参数”流程不一致。
6. 没有可追踪的导出任务，刷新或关闭页面后无法恢复进度。

当前权限资源 `dashboard.chat.export` 只绑定 `GET /dashboard/workMessage/toUsers` 和 `GET /dashboard/workMessage/detail`，尚无专用导出后端能力。

## 3. 圆弧 AI 重新采样结论

本次直接采样了参考页的可见界面和隐藏确认弹窗结构，没有触发实际导出。

### 3.1 第一步：选择导出类型

- 页面顶部是两步进度条，不是介绍 banner。
- 主区横向排列三张大卡片：按员工导出、按客户导出、按群聊导出。
- 卡片整体可点击，选中态使用边框、勾选和轻阴影。
- 底部居中放置“下一步”。

### 3.2 第二步：选择对象

按员工导出：

- 员工姓名、部门、员工筛选；
- 表格列包含员工名称、已存档客户会话数、已存档外部群会话数、已存档内部会话数、已存档内部群会话数；
- 没有任何存档会话的员工不可选。

按客户导出：

- 客户昵称、客户类型、客户状态、好友标签；
- 表格列包含昵称、备注名、标签、类型、已存档群聊会话数、已存档单聊会话数和创建时间。

按群聊导出：

- 群名称、群聊类型、部门、员工筛选；
- 表格列包含群名称、群类型、群成员数量和创建时间。

共同交互：

- 查询与重置位于同一筛选栏；
- 表格支持复选和全选当前页；
- 底部左侧是“上一步 / 确认（已选择 N）”，右侧是总数和分页；
- 员工、客户默认 20 条/页，参考页群聊为 100 条/页。

### 3.3 导出确认弹窗

弹窗包含：

- 开始日期和结束日期；
- 与当前对象类型对应的会话范围；
- 拆分文档或合并文档；
- 单文件最多 10 万条消息、时间范围最多 2 年的限制提示；
- 取消和确认。

本方案借鉴上述信息架构，但使用 MoChat 可验证的真实字段和 CSV/ZIP 工件，不照搬参考产品的文件格式、内部群能力或任务中心实现。

## 4. 方案比较

### 方案 A：继续浏览器端导出摘要

改动最小，但无法导出完整消息、无法保证总量、无法恢复任务，也不能形成可靠的后端权限边界。不采用。

### 方案 B：服务端同步流式导出

可以导出真实消息，开发量低于异步任务；但 10 万条消息的查询、格式化和压缩会长期占用 HTTP 连接，刷新或断线后不能恢复，失败也没有任务记录。不采用。

### 方案 C：两步选择 + 服务端异步导出任务（采用）

页面结构最接近参考流程，任务可恢复、可审计、可限流，后端能够在创建和执行阶段统一校验企业、员工数据范围和对象归属。代价是需要新增任务表、后台 worker、工件存储和下载接口，但这是把“会话导出”从演示能力升级为正常功能所必需的建设。

## 5. 目标页面结构

### 5.1 页面外框

页面不显示“会话存档 / 会话导出 / 功能说明”顶部介绍卡，也不放独立右侧刷新按钮。主工作区直接占满 Dashboard 内容外框：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ① 选择导出类型 ───────────────────────────── ② 选择会话      [导出记录] │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│          [按员工导出]          [按客户导出]          [按群聊导出]           │
│                                                                              │
│                              [下一步]                                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

进入第二步后：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ① 选择导出类型 ───────────────────────────── ② 选择会话      [导出记录] │
├──────────────────────────────────────────────────────────────────────────────┤
│ 关键词 / 类型 / 状态 / 组织筛选                         [查询][刷新][重置] │
├──────────────────────────────────────────────────────────────────────────────┤
│ □ 真实候选对象表格，表头固定，内容区填满剩余高度                            │
│ □                                                                            │
│ □                                                                            │
├──────────────────────────────────────────────────────────────────────────────┤
│ [上一步] [确认（已选择 N）]                         共 N 条  ‹ 1 / N ›      │
└──────────────────────────────────────────────────────────────────────────────┘
```

“导出记录”打开右侧抽屉；创建任务成功后自动打开抽屉，不修改应用顶部 banner 的“任务中心”区域。

### 5.2 27 寸宽屏

- 工作区宽度为可用内容区 `100%`，不再使用 `max-width: 1320px` 居中限宽。
- 工作区高度为 `calc(100dvh - 72px - 32px)`，最小高度 620px。
- 第一步卡片区最大内容宽度 1180px，三卡等宽，避免在 2560×1440 下被无限拉宽。
- 第二步筛选栏、表格和底部操作栏横向填满；表格内容区独立纵向滚动。
- 导出记录抽屉宽 420px，遮罩和关闭按钮均可关闭，`Escape` 可关闭。

### 5.3 普通桌面与移动端

- `1200–1599px`：卡片仍为三列，筛选条件允许换行，表格可在自己的容器内横向滚动。
- `768–1199px`：第一步卡片改为一列或紧凑三列；第二步表格保留关键列，次要信息并入对象单元格。
- `<768px`：进度条改为紧凑状态条，卡片纵向排列，导出记录抽屉占满宽度。
- hover、选中、分页和按钮不使用 `transform` 或缩放，避免文字模糊和布局抖动。

## 6. 页面交互设计

### 6.1 第一步

1. 默认不替用户选择类型；若 URL 有合法 `exportType`，恢复该类型。
2. 点击卡片任意区域选中，键盘 `Enter/Space` 同样生效。
3. 未选择时“下一步”禁用。
4. 进入第二步时写入 `step=select&exportType=employee|customer|room&page=1`。

### 6.2 第二步查询

- 输入框和下拉框只维护草稿。
- 点击“查询”或按回车后才把条件提交到 URL，并发起一次候选列表请求。
- “刷新”位于“查询”旁，只重新请求当前已提交条件，不提交未确认草稿。
- “重置”清除该类型的所有筛选、页码和已选对象，然后发起一次默认查询。
- 页码变化只改变 `page`；`pageSize` 固定 20，前后端都拒绝其他值。
- 全选只选择当前页可选项，不隐式选择其他页。
- 跨页选择保留；顶部或底部持续显示“已选择 N 项”。
- 无归档消息的对象显示真实数量 `0` 且复选框禁用；能力未接入则显示“未接入”，不能写成 `0`。

### 6.3 三类候选对象

员工：姓名、部门、状态；展示客户单聊、外部群聊、内部单聊、内部群聊数量。当前系统没有内部会话归档能力，因此对应列显示“未接入”，不参与可选判断。

客户：昵称/备注、客户类型、关系状态、标签；展示单聊和群聊会话数。客户类型来自 `mc_work_contact.type`，标签来自 `mc_work_contact_tag_pivot` 与 `mc_work_contact_tag`，关系状态来自 `mc_work_contact_employee`。

群聊：群名、群类型、部门/员工；展示成员数、归档消息数和创建时间。当前仅支持外部客户群，内部群显示“未接入”。

### 6.4 导出确认

点击“确认（已选择 N）”后打开弹窗：

- 时间范围必填，结束日期不得早于开始日期，跨度最多 2 年；按 `Asia/Shanghai` 解释为 `[开始日 00:00:00, 结束日次日 00:00:00)`。
- 员工导出可选“客户单聊 / 外部群聊”；客户导出可选“单聊 / 所在客户群”；群聊导出固定为“群消息”。
- 至少选择一个当前可用的会话范围。
- 拆分：每个已选对象一个 CSV，统一打包 ZIP。
- 合并：所有已选对象写入一个 CSV，再打包 ZIP。
- 前端展示服务端预检得到的预计消息数；总量为 0 或超过 100,000 时禁止创建任务并显示明确原因。
- 点击最终“创建导出任务”只提交一次；使用 `idempotencyKey` 防止重复点击生成重复任务。

### 6.5 导出记录抽屉

- 固定每页 20 条，只显示当前用户在当前企业创建的任务。
- 状态：排队中、生成中、已完成、失败、已过期。
- 展示类型、对象数、消息数、文件数、时间范围、创建时间、完成时间和失败原因。
- 排队中/生成中任务每 3 秒轮询；没有活动任务时停止轮询。
- 已完成且未过期时显示“下载”；失败时显示原因和“按原条件重试”。
- “刷新”位于任务列表查询区，不在页面顶部重复出现。
- 抽屉可通过关闭按钮、遮罩和 `Escape` 关闭。

## 7. 前后端接口

### 7.1 候选对象

`GET /dashboard/workMessage/exportCandidates`

查询参数：

```text
exportType=employee|customer|room
keyword=
departmentId=
customerType=
customerStatus=
tagIds=1&tagIds=2
roomType=external
employeeIds=1&employeeIds=2
page=1
pageSize=20
```

响应包含 `items`、`total`、`page`、固定 `pageSize=20`、`capabilities` 和 `limitations`。不同类型的行使用可区分联合类型，不能以空字段伪装统一模型。

### 7.2 创建任务

`POST /dashboard/workMessage/exportTasks`

```json
{
  "exportType": "customer",
  "selectedIds": [2001, 2002],
  "startDate": "2026-08-01",
  "endDate": "2026-08-20",
  "conversationScopes": ["direct", "room"],
  "fileMode": "split",
  "format": "csv_zip",
  "idempotencyKey": "browser-generated-uuid"
}
```

创建接口重新校验对象归属、员工数据范围、日期、范围、最大对象数 100 和最大消息数 100,000。成功返回 `201`；相同幂等键返回原任务。

### 7.3 任务列表与下载

- `GET /dashboard/workMessage/exportTasks?page=1&pageSize=20&status=`
- `GET /dashboard/workMessage/exportDownload?taskId=123`

下载接口只允许任务创建者、相同 tenant 和相同 corp 下载；必须验证任务已完成、未过期、工件路径位于配置根目录内。响应使用附件下载，不返回本地绝对路径或公开静态 URL。

## 8. 后端数据流

```text
用户筛选候选对象
  → exportCandidates handler
  → principal 解析 tenant/corp/user 与员工数据范围
  → export candidate store 聚合真实目录和归档数量

用户创建任务
  → exportTasks POST
  → 重新校验对象、范围、日期和消息数
  → 写入 mochat_go_work_message_export_tasks（pending）

后台 worker
  → 领取 pending 任务并设置 running + lease
  → 使用任务保存的企业、对象和员工范围查询 mc_work_message_1..10
  → 流式写入 CSV，拆分或合并后写 ZIP 临时文件
  → 原子改名到 /app/storage/conversation-exports/... 并记录摘要/大小
  → 设置 succeeded；错误设置 failed

用户下载
  → exportDownload handler
  → 校验当前 principal、任务归属、状态、过期时间和安全路径
  → 流式返回 ZIP，并增加下载次数
```

worker 使用 MySQL 任务表领取和租约，不把 Redis 当作唯一任务真相；应用重启后可恢复超时的 `running` 任务。运行状态仍记录到现有 `taskrunner` 执行台账。

## 9. 数据来源矩阵

| 控件/字段 | 前端 API | 后端/存储来源 | 口径与空值 |
|---|---|---|---|
| 员工候选、姓名、状态 | `exportCandidates?exportType=employee` | `mc_work_employee` | 当前 corp、未删除、受员工范围约束 |
| 部门树与部门筛选 | 同上 | `mc_work_department`、`mc_work_employee_department` | 组织未同步时返回 limitation，不隐藏全部员工 |
| 员工客户/群会话数 | 同上 | `mc_work_message_1..10` 聚合 | 仅可访问员工、当前可用 archive source |
| 客户昵称、类型、创建时间 | `exportCandidates?exportType=customer` | `mc_work_contact` | 资料已删但有归档时保留“资料缺失”对象 |
| 客户备注与关系状态 | 同上 | `mc_work_contact_employee` | 多员工关系按当前数据范围聚合 |
| 客户标签 | 同上 | `mc_work_contact_tag_pivot`、`mc_work_contact_tag` | 标签表缺失属于能力异常，不显示假标签 |
| 客户单聊/群聊数量 | 同上 | 归档分表、`mc_work_contact_room`、`mc_work_room` | 与客户会话页使用相同关联口径 |
| 群名称、群主、成员、创建时间 | `exportCandidates?exportType=room` | `mc_work_room`、`mc_work_contact_room`、`mc_work_employee` | 已删除群按任务规则不可新选；历史任务仍可显示快照 |
| 群归档消息数 | 同上 | 归档分表，有效群 ID 规则 | `to_user_type=2`，群 ID 使用共享归一化规则 |
| 预计/实际消息数 | 创建任务/任务列表 | 同一导出查询的 `COUNT(*)` 与实际写入计数 | 不一致时以实际计数为准并记录告警 |
| 导出任务状态 | `exportTasks` | `mochat_go_work_message_export_tasks` | 无任务是正常空态；表缺失是未接入错误 |
| 下载文件 | `exportDownload` | D 盘 `app-storage` 下的会话导出目录 | 过期或文件缺失分别返回 410/500，不返回空文件 |

所有归档查询继续使用现有 `effectiveArchiveSource`、10 张消息分表和员工数据范围规则；不得另写一套忽略真实/模拟来源的导出 SQL。

## 10. 能力缺口分类

| 能力 | 分类 | 本轮处理 |
|---|---|---|
| 员工、客户、外部群目录和归档消息 | 已有数据，缺专用导出接口 | 本轮实现专用候选、任务和下载链路 |
| 客户类型、关系、标签 | 数据存在，当前导出页未返回 | 本轮聚合返回 |
| 内部员工单聊、内部群聊 | 产品/归档能力未接入 | 明确显示“未接入”，不伪造数量或选项 |
| 历史群入站发送者身份 | 部分历史数据未保存 | 导出“群成员/未知”，并在任务 limitation 中说明 |
| 媒体文件二进制打包 | 产品功能未实现，且涉及容量/权限 | 本轮只导出类型、摘要和元数据；不显示为已支持 |
| 全局任务中心接入 | 当前 Dashboard 顶部无对应可复用数据流 | 本轮在本页提供导出记录抽屉，不改顶部 banner |
| 企业未开通会话存档 | 配置/权限状态 | 阻止进入导出选择并显示授权告警 |
| 组织、标签、群同步缺失 | 同步/配置异常 | 对应筛选显示 limitation，保留仍可安全展示的对象 |

## 11. 导出工件规则

- 格式固定为 UTF-8 BOM CSV，外层 ZIP；文件名使用中文类型、对象安全名称、日期和任务 ID。
- CSV 列：对象类型、对象 ID、对象名称、会话 ID、员工 ID、员工名称、发送者、方向、消息类型、消息文本/摘要、发送时间、归档来源、归档来源 ID。
- 防止 CSV 公式注入：以 `= + - @` 开头的文本在写出前加单引号。
- 所有值使用标准 CSV writer 转义；不手工拼接逗号和引号。
- 拆分模式最多 100 个 CSV；合并模式一个 CSV；均以 ZIP 统一下载。
- 工件先写同目录临时文件，成功后原子改名；失败时删除临时文件。
- 默认保留 7 天，过期后 worker 删除工件并把任务标记为 `expired`。
- 数据库只保存相对路径、SHA-256、大小和文件名，不保存主机绝对路径。

## 12. 安全与权限

1. tenant、corp、user 和员工范围只取服务端 principal，忽略客户端同名字段。
2. 创建任务时验证每个 `selectedId` 属于当前 corp 且在用户员工范围内。
3. 任务保存当次允许的员工 ID 快照；worker 不接受前端再次传入范围。
4. 下载只允许创建者本人，管理员也不能通过猜测 ID 下载他人的文件。
5. 工件路径使用安全根目录拼接并校验 `filepath.Rel`，拒绝 `..`、绝对路径和根目录外路径。
6. API 不返回本地路径、密钥、归档原始凭据或媒体磁盘地址。
7. 任务创建使用幂等键；领取使用数据库事务和租约，防止多 worker 重复生成。
8. 任务失败原因对用户只返回可理解的业务错误；详细 SQL/文件系统错误仅写服务日志。

## 13. 状态与错误语义

- `loading`：首次加载候选对象或任务。
- `refreshing`：保留现有内容，按钮显示处理中，不清空表格。
- `empty`：真实查询成功但没有可导出对象或任务。
- `forbidden`：没有页面或员工数据范围权限。
- `provider-unavailable`：企业未开通会话存档。
- `capability-unavailable`：内部会话、媒体打包等功能未接入。
- `sync-limited`：组织、标签、群或关系同步不完整。
- `error`：接口、数据库、worker 或文件系统异常，可重试但不能降级成假数据。
