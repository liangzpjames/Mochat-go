# 会话页面顶部介绍框精简设计

## 目标

所有会话页面不再显示仅用于介绍页面用途的顶部横幅。页面级刷新入口迁移到对应查询表单的查询按钮旁边。

## 结构设计

- 删除 `conversation-global-header` 整块页头，包括“会话存档”、页面标题、介绍文字及右侧“刷新消息”按钮。
- 保留查询概览、状态快捷筛选、类型快捷筛选、查询表单、结果列表和详情抽屉。
- 筛选操作顺序固定为“查询、刷新、重置”。刷新不改变 URL 和筛选条件，只重新请求当前查询。
- 刷新请求进行中时按钮禁用并显示“刷新中…”，避免重复请求。
- 全局消息、客户会话和群聊会话由 `ConversationGlobalPage` 统一调整。
- 独立的 `EmployeeConversationPage` 同样删除顶部介绍框，将员工列表刷新迁移到左侧“搜索”旁；会话列表刷新保留，因为它只刷新当前员工的会话结果。

## 样式设计

- 删除仅服务于已移除页头的 `.conversation-global-header` 和 `.conversation-global-eyebrow` 样式。
- 继续使用筛选栏现有主按钮/次按钮样式；刷新按钮作为次按钮，和重置按钮保持一致的视觉层级。
- 响应式布局沿用筛选栏既有规则，移动端三个操作按钮仍按单列排列。

## 数据与交互

全局、客户和群聊页面的刷新按钮调用当前 `listQuery.refetch()`，不重置页码、关键词、状态、类型、日期、员工或消息类型。员工页面的查询区刷新调用 `employeeQuery.refetch()`，不改变员工搜索词；会话列表刷新仍调用 `listQuery.refetch()`。后端接口和数据结构不变。

## 验收标准

1. 所有共用会话页面均无顶部介绍横幅。
2. 全局、客户和群聊页面只存在一个“刷新消息”按钮，位于查询表单内、紧邻“查询”。
3. 员工页面没有顶部介绍框，员工刷新位于“搜索”旁；选中员工后的会话列表刷新继续保留。
4. 点击刷新后当前 URL 不变，请求重新执行一次。
5. 相关组件测试、类型检查和生产构建通过。
