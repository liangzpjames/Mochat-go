# Phase 3.4 Provider 全线收口设计

日期：2026-08-04

状态：已由 delegated worker 自审并进入实施

## 目标

把 `marketing-tools` 的九页从“页面已注册/局部查询可用”推进到可复核的业务合同：本地能力具备真实持久化、租户隔离、权限、错误状态和刷新复核；依赖企业微信的能力具备正式 adapter、持久化状态机和可验证失败路径。外部凭据未配置时，只能显示明确阻断，不写入伪造成功。

## 方案取舍

1. 保留阻断页并只补报告：无法满足获客链接、客服、短链和朋友圈状态机要求，不采用。
2. 直接把旧 Dashboard 响应拼接到 React：可以减少代码，但无法提供统一 Provider、租户边界、错误语义和跨页面素材合同，不采用。
3. 新增 Phase 3.4 Provider 合同，复用已有渠道活码、自动拉群、群发和素材底座：本地可完成的 CRUD/统计/审计落 MySQL；企业微信外发由可插拔 adapter 负责，缺少配置时返回 `503` 并保留 `failed`/`publishing` 等状态。采用此方案。

## 后端边界

- 登录上下文决定 `tenant_id`、`corp_id`、`user_id` 与数据权限，客户端提交的企业字段只用于兼容解析，不能覆盖服务端作用域。
- 群活码复用自动拉群的企业微信 contact-way Provider，但新增 Phase 3.4 适配响应和详情/停用入口；不把标签建群伪装成通用群活码。
- 获客链接、微信客服和活码短链各自拥有持久化记录。获客链接/客服同步在没有正式外部 Provider 时保存可审计草稿或授权状态，激活/同步返回 `503`；短链使用本地不可猜测 token、目标白名单、停用状态和访问审计。
- 一键加群复用自动拉群写入/二维码 Provider，精准群发复用客户群发和群聊群发写入/执行 Provider；React 增加真实草稿和详情操作，外发失败显示服务端错误，不展示成功假数据。
- 朋友圈拆成本地任务/素材 Provider 与 `FriendsCirclePublisher` 两层。发布前原子抢占 `draft -> publishing`，外部错误进入 `failed`；回调只接受签名和企业归属匹配的事件，更新进度/失败明细；导出只导出当前企业的持久化结果。
- 素材选择器只返回当前企业、作用域可见、`available` 素材；引用保护覆盖现有欢迎语及新增 Phase 3.4 引用关系。

## 前端边界

- 九页继续使用 Dashboard shell 和 `BusinessWorkbenchApi`，不直接依赖旧响应形状；每个 adapter 统一处理 envelope、分页、空态、错误重试和 `503` Provider 阻断。
- 获客链接/客服/短链显示真实状态与可执行动作；一键加群和精准群发提供创建/详情/刷新主流程；朋友圈提供任务/素材双标签、草稿抽屉、发布阻断、进度/失败明细/导出状态。
- `MaterialSelector` 作为只读弹窗合同接入朋友圈、精准群发和渠道/群活码可引用入口，返回 `{id,name,type,preview}`，不复制正文。
- 浏览器验收必须验证遮罩、抽屉/弹窗布局、键盘关闭、刷新后的持久化和错误状态；截图放在 `D:\workspace\mochat-go\output\phase3.4\screenshots`，最终证据复制到阶段目录。

## 错误和验收语义

`400` 表示输入无效，`401` 未登录，`403` 无权限，`404` 资源不存在或不属于当前企业，`409` 重复/版本冲突或存在引用，`422` 非法状态转换，`503` 外部 Provider 未配置或暂不可用。只有对应 Go 测试、前端测试、真实 Docker 请求和浏览器截图同时存在，Manifest 才能提升 `backend` 或 `acceptance`。

## 外部阻塞记录

本机不提供企业微信朋友圈发布账号、回调签名密钥或获客链接/客服的正式外部授权。因此本次允许完成正式 adapter、授权/发布状态机、失败回写、回调校验、导出合同和本地草稿闭环，但不得把 `backend` 标为 `ready` 或把相关页面标为 `e2e-passed`，除非本机后续提供可验证凭据并重新完成外部验收。

- 不修改 `.workbuddy/`、`docs/superpowers/plans/2026-07-29-phase3-frontend-acceptance.md`、`web/saas-admin/`。
