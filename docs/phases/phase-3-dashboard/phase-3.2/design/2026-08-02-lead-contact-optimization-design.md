# 线索池与联系人页面体验优化设计

## 范围

本轮仅优化 `/customer/clue/default` 与 `/customer/contact`。商机、公海和客户标签不在本轮修改范围内。页面借鉴圆弧的信息层级，但只呈现现有 API 和权限模型支持的真实能力。

## 线索池

- 使用统一的 SCRM 页面头部、真实结果摘要、组合筛选、操作工具栏和数据表格。
- 新增线索作为可折叠/分区业务入口，保留企业内重复检查。
- 批量分配与行级状态流转分离；只有可操作状态允许选择。
- 表格突出客户、来源、负责人和状态，保留业务标识、版本冲突提示及游标分页。
- 支持刷新、空状态、403、422、409 和批量部分失败反馈，不增加渠道对接、删除或导出等后端不存在的操作。

## 联系人

- 列表采用与线索池一致的头部、摘要、筛选、工具栏和分页结构。
- 标签筛选继续使用真实标签 ID 合同，不伪造圆弧的标签选择接口。
- 联系人详情改为右侧抽屉，按客户资料、企微关系、分配、公海、标签、商机和跟进分区展示。
- 抽屉支持加载、失败重试、Escape 关闭、焦点进入与恢复；详情 ID 与筛选继续保存在 URL。
- 写操作严格遵循联系人编辑权限及既有组件内部权限，不增加批量删除、转移或好友关系编辑。

## 视觉与验证

- 新样式全部限定在 `.scrm-lead-page`、`.scrm-contact-page` 和共享 `.scrm-*` 组件范围，避免影响其他页面。
- 桌面端强调卡片层级和紧凑表格，窄屏将筛选、摘要及详情区域单列展示。
- 先补失败测试，再实现页面；运行两页目标测试、Dashboard 全量测试、类型检查、生产构建和浏览器验收。
