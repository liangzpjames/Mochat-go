# Phase 3.3 会话与风险预警设计

日期：2026-08-02  
状态：设计基线  
工作分支：`phase3.3/session-risk-warning`

## 1. 设计结论

Phase 3.3 沿用既有 Phase 3 设计，不调整业务顺序。当前阶段先处理会话与风险预警，因为风险规则、超时、流失、拦截和沉默客户都依赖可授权、可检索、可追溯的会话或客户事件数据。营销工具、SCRM 扩展、报表、AI 和企业设置按既有 Phase 3.4 至 3.6 顺序后置。

阶段共 15 个页面：会话域 9 个：`/chat/v2-staff`、`/chat/v2-customer`、`/chat/v2-group`、`/chat/trajectory`、`/chat/export`、`/chat/file-audio`、`/chat/resign-staff`、`/chat/refuse-archive`、`/customer/inheritance`；风险预警域 6 个：`/ai-insight/v2/risk`、`/ai-insight/v2/timeout`、`/ai-insight/v2/customer-loss`、`/ai-insight/v2/message-intercept`、`/ai-insight/v2/keyword-library`、`/ai-insight/v2/silent-customer`。

## 2. 方案比较与选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 先做视觉菜单和 demo | 交付快，但无法解决存档授权、权限、导出和处置闭环 | 不采用 |
| 会话存档底座 + 纵向闭环批次 | 依赖清晰，每批可测试和回滚，符合 Phase 3 约束 | 采用 |
| 按旧版页面逐页搬运 | 易带入旧 API、未定义边界和重复逻辑 | 仅用于复用审计 |

## 3. 业务批次与依赖

### 批次 0：前置能力与复用审计

确认会话存档授权、消息/媒体数据源、保留与脱敏策略、外部 provider、异步任务能力和现有旧接口。输出页面档案、旧能力映射、领域 API 契约和测试租户。若会话存档数据源或授权不可用，阶段只能停留在设计/基础设施状态，不得把页面标记为完成。

### 批次 1：会话检索基础

实现统一会话对象、消息查询、员工/客户/群三种视图及详情上下文：员工会话、客户会话、群聊会话。三页共享分页、筛选、时间范围、脱敏和数据权限合同，但页面 feature module 独立。

### 批次 2：轨迹、媒体与导出

实现会话轨迹、文件录音和会话导出。轨迹保留来源指针；媒体访问二次校验权限和下载审计；导出进入任务中心，具有范围确认、状态机、失败重试、过期下载链接和审计。

### 批次 3：离职与授权治理

实现离职员工、拒绝存档和客户继承。离职资产查看与客户继承分离权限；继承使用幂等键和并发控制；拒绝存档页面只展示授权范围允许的状态，不由客户端伪造授权结果。

### 批次 4：风险事件与处置

实现风险行为、超时预警、客户流失和沉默客户。统一风险事件、证据引用、处置状态、分派、通知和审计；规则命中必须能回到会话或客户事件原文/来源。

### 批次 5：规则配置与发送前门禁

实现关键词库和消息拦截。关键词库采用版本化发布，历史命中固定关联规则版本；消息拦截通过 provider 接入发送链路，测试环境禁止发送真实消息，生产放行/拦截结果必须具备解释和审计。

## 4. 领域与数据流

```text
会话存档/客户事件 provider
  -> ingestion / normalization
  -> tenant_id + corp_id 数据边界
  -> session query / timeline / media / export task
  -> 风险规则与 SLA 计算
  -> alert event + evidence + assignment + audit
  -> Dashboard API adapter
  -> 页面查询、处置、刷新后复核
```

所有请求从认证上下文解析 `tenant_id`、当前 `corp_id`、用户和数据范围；服务端不得信任客户端提交的企业、负责人、规则范围或导出范围。消息、媒体、风险事件和导出任务都必须包含租户边界，企业级数据还必须包含企业边界。

会话查询合同固定对象类型、对象 ID、员工/客户/群筛选、时间范围、关键词、分页游标、脱敏字段、数据来源和授权范围。详情响应不得绕过列表查询的权限合同。轨迹使用统一事件时间线，但每条事件必须带来源类型和来源 ID，不能用拼接文本替代可追溯证据。

## 5. 状态与错误语义

| 对象 | 状态/规则 |
| --- | --- |
| 导出任务 | `queued` → `running` → `succeeded` / `failed` / `expired` / `cancelled` |
| 风险事件 | `open` → `assigned` → `processing` → `resolved` / `ignored` |
| 关键词版本 | `draft` → `published` → `archived`；同一规则同时只有一个生效版本 |
| 客户继承 | `pending` → `assigned` → `accepted` / `failed`；重复幂等键返回原结果 |
| 消息拦截 | `blocked` / `allowed` / `review_required`，每次决定关联规则版本和解释 |

统一错误语义：无权访问 `403`，不存在或为避免泄漏而隐藏 `404`，并发/版本冲突 `409`，非法状态流转 `422`，参数无效 `400`。外部 provider 超时、限流和部分失败必须转换为可重试任务或明确降级状态，不能让页面显示伪成功。

## 6. 权限、审计与安全

- 会话读取、媒体读取、导出、风险查看、风险处置、规则维护、消息拦截策略和客户继承分别定义动作权限。
- 数据范围至少覆盖本人、协作人、本部门、下级部门、全企业和平台明确授权范围。
- 下载、导出、规则发布、风险处置、继承分配和拦截决定记录操作者、租户、企业、动作、目标、结果和时间。
- 消息和媒体默认脱敏；截图、日志、测试数据和文档禁止提交真实客户数据、访问令牌或可重放下载链接。
- 导出文件必须短期过期，下载前再次检查用户和企业上下文；任务完成后不得永久暴露对象存储地址。

## 7. 测试与阶段门禁

每个批次先写失败测试，再实现最小闭环。至少覆盖领域/application、repository、MariaDB、HTTP、React adapter、React 页面和 Playwright 主流程；会话导出、媒体访问、继承领取和风险处置补充幂等、并发、重试和审计测试。

浏览器主流程统一为：登录 → 进入菜单 → 查询或执行命令 → 验证反馈 → 刷新 → 再次查询验证持久化 → 更换企业/角色验证隔离。测试必须使用脱敏数据和隔离 provider，不发送真实消息、不下载真实客户资料、不触发不可逆第三方操作。

阶段完成前，15 个页面必须达到 `native` 或审查批准的 `legacy-adapter`，`backend=ready`，并具备对应证据；任何页面仍为 `demo`/`placeholder`，或仅有菜单/路由/fixture 证据，都不能宣告 Phase 3.3 完成。

## 8. 明确不纳入

- 会话存档授权尚未确认前，不实现伪造的生产会话数据；
- 不把普通聊天回调、旧版页面截图或静态 fixture 作为会话存档；
- 不在本阶段扩展营销工具、SCRM 扩展、报表、AI 知识库和企业设置；
- 不复用已占用的 `0099` migration 编号，新 migration 必须从仓库最新编号顺延；
- 不为了兼容旧界面维护双套产品逻辑，仅在有真实部署入口或历史链接需求时提供 adapter/重定向。
