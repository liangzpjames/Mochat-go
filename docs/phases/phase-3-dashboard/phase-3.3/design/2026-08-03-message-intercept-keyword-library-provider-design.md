# 消息拦截与关键词库 Provider 设计

## 目标

完成 `/ai-insight/v2/message-intercept` 与 `/ai-insight/v2/keyword-library` 的真实数据闭环，替换“数据提供方未接入”状态。关键词库负责分组、词条和发布版本；消息拦截负责引用已发布版本、评估消息、保存决定与审计记录。

## 设计选择

采用共享 Provider、分页面呈现的方案。词库和词条以草稿态维护，发布时生成不可变版本快照；拦截规则仅绑定已发布版本。每次评估保存规则、版本、命中词、决定和解释，历史记录不随词库后续修改而变化。

不接管生产消息发送链路。本阶段提供可由发送链路调用的同步评估接口，并在本地保存真实评估结果；测试和页面操作不会向企微发送消息。

## 数据模型

- `keyword_libraries`：词库基本信息、匹配方式、草稿版本、已发布版本和状态。
- `keyword_entries`：当前草稿词条，支持启停。
- `keyword_versions` 与 `keyword_version_entries`：发布后的不可变快照。
- `message_intercept_rules`：规则名称、词库及版本、会话范围、决定和状态。
- `message_intercept_records`：评估输入摘要、命中词、决定、解释和审计状态。
- `message_intercept_audits`：人工复核动作、操作者和备注。

全部表按 `tenant_id + corp_id` 隔离，写入和读取均校验企业范围。

## 状态和安全边界

- 词库：`enabled` / `disabled`；发布后版本号递增，旧版本只读。
- 拦截决定：`blocked` / `allowed` / `review_required`。
- 审计状态：`pending` / `confirmed` / `ignored`。
- 匹配方式首期支持 `contains` 和 `exact`，暂不开放正则，避免不受控表达式造成性能风险。
- 规则引用词库发布版本；无可用版本时不允许启用规则。

## 页面

关键词库页面提供词库列表、创建/编辑、启停、词条维护和发布。消息拦截页面提供命中记录与规则两个页签，支持记录筛选、详情、复核，以及规则创建、编辑和启停。空数据使用正常空状态，不再出现 Provider 未接入提示。

## 验收

覆盖领域校验、版本发布、消息匹配、企业隔离、HTTP 合同和 React 主交互；部署继续使用现有 Compose 项目并保留数据卷，最终以两个本地页面的截图和接口返回共同验收。
