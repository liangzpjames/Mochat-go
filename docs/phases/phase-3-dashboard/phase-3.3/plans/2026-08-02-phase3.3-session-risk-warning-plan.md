# Phase 3.3 会话与风险预警实施计划

> **执行说明：** 本计划只覆盖 `phase-3.3/session-risk-warning` 的 15 个页面；实施前必须完成设计文档中的批次 0 前置门禁。每个批次独立提交、测试和审查，不能把失败测试集中到阶段末尾。

**目标：** 将会话与风险预警的 15 个菜单从 `demo`/`placeholder` 升级为真实、可审计、可持久化和可验收的业务页面。

**架构：** 以会话存档标准化领域为查询底座，前端通过 feature API adapter 访问后端；轨迹、媒体、导出和离职治理复用会话权限合同，风险预警复用会话/客户证据并独立维护规则、事件和处置状态。外部企微/会话服务通过 provider 隔离，耗时导出、同步和计算进入任务中心。

**技术栈：** Go、MariaDB、React、TypeScript、React Query、Playwright、现有 Dashboard shell、现有认证/租户/企业/菜单权限基础设施。

## 全局约束

- 所有业务数据包含 `tenant_id`；企业级资源包含 `corp_id`。
- 服务端从认证上下文解析租户、企业和数据范围，不信任客户端提交的边界。
- 错误语义固定为 `400` 参数无效、`403` 无权、`404` 不存在/隐藏、`409` 冲突、`422` 非法状态。
- 写操作必须记录操作者、动作、目标、结果和时间。
- 不使用真实客户数据、访问令牌或可重放下载链接作为测试/证据。
- 会话存档、媒体、导出和消息拦截必须使用明确 provider；测试 provider 禁止真实外发。
- 所有页面必须覆盖加载、空数据、无结果、403、404、409/422、服务异常、重试、重复提交和刷新恢复。

## 批次清单

1. 批次 0：完成 15 页页面档案、旧能力复用审计、会话存档许可和 provider 门禁；输出 `reports/reuse-audit.md` 更新记录。
2. 批次 1：实现统一会话查询合同及员工会话、客户会话、群聊会话；输出列表/详情 API、权限和刷新后读取证据。
3. 批次 2：实现会话轨迹、文件录音和异步会话导出；输出媒体访问审计、导出任务状态和过期下载证据。
4. 批次 3：实现离职员工、拒绝存档和客户继承；输出继承幂等、并发冲突、授权状态和审计证据。
5. 批次 4：实现风险行为、超时预警、客户流失和沉默客户；输出规则命中、证据引用、分派、处置和 SLA 证据。
6. 批次 5：实现关键词库和消息拦截；输出版本发布、命中版本关联、拦截解释和防误发证据。
7. 阶段门禁：同步 manifest、页面矩阵、验收记录、任务报告和截图；运行全量合同/类型/单元/集成/构建/E2E/证据检查。

## 实施要求

每个业务批次都必须按“复用审计 → RED 测试 → GREEN 实现 → 集成验证 → 浏览器主流程 → 证据归档 → 独立提交”执行。具体文件路径和接口签名在批次 0 的审计与领域合同确定后才能冻结；不能在审计前凭旧页面名称猜测 API 或数据表。
