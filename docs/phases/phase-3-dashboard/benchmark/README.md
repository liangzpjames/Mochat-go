## 产品定位

圆弧 AI 将企业微信能力组织成四条相互连接的主链：

1. 会话存档与检索：员工、客户、群聊的消息归档、轨迹、导出和离职继承。
2. 风险与 AI 质检：风险行为、敏感词、超时、流失、情绪、员工评分和关键词洞察。
3. 获客与客户经营：活码、获客链接、群发、朋友圈、素材，衔接线索、联系人、商机、公海和订单。
4. 数据与治理：客户/会话/转化/行为报表，配套知识库、智能体、员工、角色和授权管理。

核心卖点不是单个工具数量，而是把“企微数据采集 → 客户经营 → AI 洞察 → 风险治理 → 报表复盘”放在同一个后台中。

## 已观察到的代表流程

### 渠道活码

分组管理 → 按名称、创建人或关联员工查询 → 添加活码 → 关联员工/部门与客户标签 → 投放 → 查看新增好友数与统计 → 导出、删除或批量分组。

圆弧特别提示将不再投放的活码作废，以改善投放中活码的刷新性能，说明活码存在明确生命周期，而不只是静态二维码。

### 精准群发

选择客户群发或群聊群发 → 按创建日期查询 → 新建群发 → 配置受众、内容和执行时间 → 查看执行结果与执行数据。

其产品价值在于把客户筛选、内容素材、企微群发任务和发送结果统一记录。

### SCRM 联系人

按范围、来源、标签、状态和关键词筛选 → 新增联系人 → 自定义列表字段 → 批量转移、协作、删除、放弃、加标签或删标签。

联系人不是单纯企微好友副本，而是具有负责人、协作人、来源、状态和标签的经营对象。

### 商机

按范围、阶段、创建时间和关键词筛选 → 添加商机 → 绑定客户和负责人 → 推进商机阶段 → 记录预计金额、预计成交时间与跟进记录 → 转移、协作、导出或删除。

可见字段包括商机名称、负责人、阶段、客户所属、来源、预计金额、预计成交时间、创建人、最后跟进和最新跟进记录。

### 数据报表

选择企业数据、客户联系、会话消息或风险质检报表 → 设置日期、员工/部门及业务筛选 → 查看汇总卡、趋势、分布和增长明细。

详细报表至少包含员工、部门、通话、客户、标签、单聊、群聊、超时未回、客户流失/负面情绪和风险行为数据。

### AI 知识库

创建知识库 → 填写名称和描述 → 导入或手动添加知识文档 → 关联智能体 → 在 AI 聊天或 AI 分析中引用 → 持续维护文档。

知识库列表提供描述、关联智能体、更新时间、文档数和创建人，说明其定位是可治理的企业知识资产。

### 员工权限

同步组织与员工 → 按部门、姓名、手机号、账号状态、账号类型和角色筛选 → 添加系统账号/许可 → 绑定角色 → 控制系统授权和许可账号。

圆弧区分企微员工、系统登录授权、许可账号和业务角色；Phase 3 不能只复用现有菜单 RBAC，需要明确这些概念的边界。

## 对 MoChat Go 的差距判断

### 已有较好基础

- 企业、员工、部门、客户、客户群和标签数据模型。
- 登录、租户隔离、菜单与角色权限。
- 渠道活码、群发、素材、欢迎语、拉群、裂变等既有后端能力。
- 异步任务、定时任务、企微回调、审计和 Docker 运行基础。
- React 路由、API Client、Query、Playwright 与发布链路。

### 主要业务缺口

- SCRM 中的线索、联系人协作、商机、公海和订单没有形成统一客户生命周期。
- 会话存档、全局检索、轨迹、文件录音、拒绝存档和离职继承需要独立领域设计。
- 风险规则、预警事件、处置状态和通知闭环尚未形成统一模型。
- AI 知识库、文档切分/索引、智能体、分析任务、引用证据和成本治理尚未形成。
- 报表目前偏单点统计，缺少统一指标口径、维度筛选、趋势与明细下钻。
- Sidebar 和 Operation 已完成 Phase 2.1 的移动端业务骨架、显式路由内容、主操作和 fake 外部平台链路；Phase 3 在此基础上深化业务规则和视觉对标。

## Phase 3 推荐顺序

1. **P0：客户经营主数据**
   先实现联系人、线索、负责人/协作人、标签与商机，建立其他模块共同依赖的客户域。
2. **P0：营销任务闭环**
   在现有渠道活码和群发后端上补真实 React 页面、任务状态、结果统计与失败恢复。
3. **P1：统一报表基础**
   固定指标字典和维度模型，先覆盖客户增长、员工触达、群聊和营销任务。
4. **P1：会话存档领域**
   在确认企业微信会话存档许可、SDK 和合规要求后实施，不与普通消息回调混为一谈。
5. **P1：风险质检闭环**
   基于会话存档构建规则、命中、处置、通知和复盘。
6. **P2：AI 知识库与智能体**
   在真实会话数据、权限和引用审计具备后接入，避免先做没有业务数据的 AI 外壳。

## 进入开发前的门禁

- 为第一批 P0 功能确定产品范围、角色和验收场景。
- 建立脱敏测试租户及真实企微联调环境。
- 固定联系人、线索、商机、营销任务的 API 契约和状态机。
- 明确数据权限：本人、协作人、部门、下级部门、全企业。
- 明确幂等键、企微限流、重试、补偿和死信处理。
- 建立业务事件和指标字典，禁止前后端各自解释同一指标。
- 修复全仓 Go 测试的 Windows 路径与文件权限基线。
- 完成预生产回滚演练并更换所有演示凭据。
